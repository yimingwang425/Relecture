# 出处核对评测 · 预登记补充：留出集（2026-10-10）

**本文件在留出集跑任何一次核对之前写下并提交。** 原预登记 `verify_eval_prereg.md` 不改；
它规定的主集评测照原样跑完、照原样报（结果文件里「主集 · Haiku · v1」那一节）。

## 为什么要补

主集上 Haiku · v1 跑到一半时已经看得出失败的样子：**页码错**抓得住，**换概念**几乎全漏、**改数字**漏一大半。
漏的方式是同一种——核对员给「平行于镜面的向量……特征值为 -1」配上课件原文
「Vectors perpendicular to it are sent to their opposites」，判 `supported`。
摘录确实在那一页（代码查过），但摘录说的是**垂直**。这正是 F122 写下的边界：
**摘录真实存在只证明摘录不是编的，不证明摘录支持这条说法。**

接下来要改 prompt 与代码校验（v2）。改法是**看着主集的失败设计的**，所以 v2 在主集上的数字不能算证据——
那等于拿训练集报成绩。v2 只在一个**改之前没人看过结果**的留出集上算数。

## v2 打算改什么（写在跑之前）

1. 判定多一种 `contradicted`：课件里有讲同一件事的原文，但**说法和它对不上**（数字、正负、方向、概念名不同）。
   要给摘录，摘录同样必须真的在读到过的那一页上。界面上它是一类问题（「和课件说法不一致」）。
2. 每条 fact 多一个必填字段：把说法里的数字、方向词、术语与摘录里对应的词**逐一对照**写出来，再下判定。
3. 代码校验多一条：判 `supported` / `wrong_page` 的说法里出现的数字（「第 N 页」除外），摘录里必须有对应的数
   （阿拉伯数字、英文数词、中文数词任一形式），否则退回——「数字对不上就不是 supported」从 prompt 里的一句话变成代码里的检查。

## 留出集

- 课件：同一份 `f1_samples/synthetic_deck.md`。
- 讲解：用生产讲解 agent 回答 `HOLDOUT_QUESTIONS` 的 16 个新问题（与主集、与 `pairs.json` 都不重），讲法档位在 P0 / P2 / P3 间轮换。
  生成后**不挑**。
- 注入：与主集**同一套确定性规则**（`perturb`），同样人工剔除「改了之后仍然为真」的，剔除清单与理由写进
  `verify_eval_holdout_items.json`。
- 某一类剔除后不足 15 条：追加问题生成讲解补足，追加的问题写进结果文件，不降标准。
- 未改样例：留出集的全部讲解原样。

## 决定规则（写在跑之前）

- 选**达标的组里单次成本最低的**；
- 都不达标：选三类检出率最小值最高、且逐条误报率 ≤ 10% 的那组，**界面文案降级**（不说「课件里没找到」）；
- 达标但只在一类上勉强（例如 70%–75%）：照样上线，结果文件里写明哪一类最弱。
