## 1. 背景与问题定义

### 1.1 现状

用 AI 辅助学习已成为学生默认行为，其中「上传课件让 AI 讲解」是最高频用法之一。该行为目前发生在通用对话框（ChatGPT / Claude / Gemini）中。

### 1.2 问题

通用对话框不是为「持续的、有个人偏好的学习」设计的。实际使用中反复出现同一循环：

```
调教风格 → 短暂好用 → 逐渐失效 → 烦躁地新开对话 → 重新调教
```

观察来源：项目发起人本人及同学群体的真实学习场景。在同学中该现象为普遍现象，且伴随明确的负面情绪与替代行为（新开对话）。

### 1.3 为什么现在做

- 该行为已高频发生
- 模型能力已足够，瓶颈在产品层而非模型层
- 通用对话框厂商短期内不会为单一垂直场景做深度个性化

## 2. 痛点拆解

2个独立问题，解法不同，需分别对待。

| 编号 | 痛点 | 本质 | 对应解法 |
| --- | --- | --- | --- |
| P1 | 找不到适合自己的讲解风格；能感知模型教学语言不适但**说不出为什么以及怎样改变** | 交互设计问题 | 从「描述」改为「选择 + 反馈」 |
| P2 | 风格约束不被执行：既有「对话变长后漂移」，也有**从第一轮起就未遵守** | 长上下文结构性问题 + 提示词执行力问题 | 独立风格审查 agent |

**P2 的表述已按实测修正（2026-08-20）**：原文写的是「对话变长后风格漂移」，预设了「一开始遵守、后来衰减」。漂移实验否定了这个预设——无审查组三条轨迹的第 1 轮术语标注率**全部为 0**，形态一致（只给中文译名，无英文括注），不是衰减而是**一次都没照做**。因此审查 agent 的价值不只在于阻止衰减，更在于**强制执行一条从未被遵守的约束**：前者意味着可以靠更好的提示词解决，后者意味着提示词根本没起作用，必须有独立的执行环节。详见 `实验脚本/漂移实验/实验报告.md`。

**P1 是最核心的洞察**：让用户「描述想要的风格」这个交互本身是失败的。大部分用户很难用语言描述自己的认知习惯，但**一定能在两个样例之间选出更舒服的那个**。

本产品构建三个闭环：

| 闭环 | 内容 | Project 为何做不到 |
| --- | --- | --- |
| 入口闭环（P1） | 样例选择替代文字描述 | 无此交互形态 |
| 输出闭环（P2） | 生成后检查，不合格则重生成 | 无法在生成与展示之间插入步骤 |
| 反馈闭环 | 用户点击反馈 → 配置自动更新 | 无反馈回写通道 |

## 3. 目标与成功指标

### 3.1 北极星指标

**周活跃用户的平均会话轮次。**

理由：该指标同时反映「用户愿意用」和「讲解质量足够好以至于用户愿意继续问下去」。若风格不合适，用户会提前放弃。

**为什么不选留存或 DAU 作北极星**：

| 候选 | 不选的理由 |
| --- | --- |
| 次周留存 | 它是**结果**指标，滞后一周才可观测，无法指导本周的产品决策。留在 §3.2 作过程指标 |
| DAU / 周活跃人数 | 只反映「有没有人来」，与本产品要解决的 P1/P2（风格不合适）**没有因果通路**——风格再差，好奇心也能撑起一次打开 |
| 溯源率 | 是质量约束不是价值度量。它达标只说明没编，说明不了讲得好 |

#### ⚠️ 北极星的失效模式 + 护栏指标

**「平均会话轮次」上升有两种原因，方向相反，而指标不分**：

| 原因 | 对产品的含义 |
| --- | --- |
| 好用，所以愿意继续问 | 指标上升 = 好事 |
| **没讲明白，所以反复追问** | 指标上升 = **坏事** |

**这是通则五的形态，与 D44 同源**：一个方向可能反了的指标，
它的输出看起来完全正常。D44 那次是审查在逼模型变啰嗦，这次是北极星
可能在奖励「讲不明白」。

**处置**：北极星保留，配一个**护栏指标**——

> **同一概念的重复提问率**。升高说明轮次是「没懂」堆出来的，
> 而不是「愿意深入」堆出来的。

锚点是现成的：F4 本来就要记录「用户标记为没看懂的概念」（§5.1），
概念识别可复用该通道。

**护栏指标的具体口径与阈值：占位待定。**
确定路径：埋点回流后，用「同一 `concept_id` 在同一会话内被追问的次数分布」
与人工标注的「这轮讲明白了吗」做对照，取能区分两类上升的切点。
在此之前不设数值——现在填一个数，与随手写的没有区别（§3.2 阈值来源规则）。

### 3.2 过程指标

| 指标 | 基线 | v1 目标 | 阈值来源 | 说明 |
| --- | --- | --- | --- | --- |
| 风格遵循度（20 轮后） | 待实测 | ≥ 85% | **占位待定** | **v1 的定义按维度枚举，见下方「风格遵循度的 v1 定义」**。数值与轮次均为占位值，确定路径见下 |
| 风格配置修改频率 | — | 首 3 次使用后趋近于 0 | 产品目标 | 反映风格习得是否准确 |
| 溯源率 | 待实测 | ≥ 90% | **占位待定** | 讲解内容可追溯到课件片段的比例。确定路径：溯源人工标注集建成后取可接受错误率反推 |
| 次周留存 | — | ≥ 30% | 产品目标 | 真实用户。这是「什么样的留存算产品成立」的判断，不由实测反推——写成占位等于说「测出来多少就是多少」，标准就没了 |
| 单会话成本 | **实测 $0.590**（15 轮，有审查） | 待重新推导 | **占位待定** | 原 `< $0.05` 从未从定价模型推导过。确定路径与参考推算见 §9.1 |

### 风格遵循度的 v1 定义（2026-08-21 收窄）

**按维度枚举，不用「A 类各激活维度」这种说法**——那个措辞会被读成包含术语处理。

v1 的「风格遵循度」= **以下三个维度中的激活项全部达标**：

| 维度 | 激活条件 | 实现 |
| --- | --- | --- |
| 详细程度 | 常驻 | `a_rules/metrics/paragraph_length.py` |
| 引用长度（合规约束） | 常驻 | `a_rules/metrics/quote_length.py` |
| 讲解语言一致性 | 讲解语言 ≠ 课件语言 | `a_rules/metrics/chinese_ratio.py` |

**明确排除的三项**：

| 排除项 | 原因 | 何时可能纳入 |
| --- | --- | --- |
| B 类全部（是否举例 / 结构 / 深度） | 依赖低成本模型判断，judge 未校准 | v1.1，§8.5 校准之后 |
| **术语处理** | 多课程下分母只能来自自动提取，实测召回率 **32%**，未达 §8.1 自己写的可用标准 | 正文通道达标 **且** 在第二门课复现，见 §8.1 |
| **冗余句式** | PRD §8.1 表中已定义，但**尚未实现**（`a_rules` 只有四个度量模块，本维度不在其中；`split_sentences` 为它预留但未接线） | 实现并验证之后 |

**冗余句式这一项要特别说清楚**：它在 §8.1 的表里，容易被数进「A 类维度」，
但它没有代码。**未实现的维度不能参与达标判定**——否则达标线里有一项永远无法计算。

### 阈值来源标注规则

**所有阈值必须标明来源**，三选一：

| 来源 | 含义 |
| --- | --- |
| 产品目标 | 由产品定位或商业约束决定，不因实测结果改变 |
| 实测依据 | 由实测数据校准得出，须注明数据来源与时间 |
| **占位待定** | 尚无依据的临时值，**必须同时写明确定路径** |

理由：**不能让测量结果反向定义标准**。目标值不能由模型现状反推（否则模型多好，目标就多高，指标失去约束力）；达标线也不能由某次实验的样本长度反推（否则实验跑几轮，标准就写几轮）。这是同一原则的两面。

未标来源的阈值，与随手写的数字无法区分——本文档此前的 `85%`、`20 轮`、`0.85±0.05` 都属此类，已逐项补标。

### 3.3 非目标（v1 不追求）

- 盈利与商业化验证
- 用户规模（目标 30–50 名真实用户即可）

### 3.4 指标口径字典（第一批，2026-08-27）

**为什么要有这一节**：`§3.2` 给的是指标名和目标值，而一个指标真正被算出来时，
分子分母、时间窗、去重规则、排除哪些账号，每一项都会改变结果。
这些不写下来，两个人算同一个指标会得到两个数，**而且两边都以为自己是对的**。

**分批的原则**：只写**已经能定死口径**的。
定不下来的标「占位待定」并写确定路径——
**一份没有数据流过的口径，和一个从没推导过的阈值，是同一类东西**（§3.2）。

#### 卡片格式（固定八项）

> 指标名 / 业务定义（一句话）/ 计算口径（分子 · 分母 · 时间窗 · 去重规则）/
> 数据来源（哪些事件 + 哪张表）/ 统计周期 / 排除规则 / 已知局限 / **阈值来源**

---

#### 3.4.1 风格遵循度

| 项 | 内容 |
| --- | --- |
| 业务定义 | 一轮讲解是否满足用户所配置的全部风格约束 |
| **分子** | 该轮中**全部激活维度均达标**的轮次数（布尔与，不是平均） |
| **分母** | 有效讲解轮次数。**排除**：无可计量内容的轮次（`raw=None`，口径 D03/D42） |
| 时间窗 | 按轮聚合，可按会话 / 用户 / 周汇总 |
| 去重规则 | **重生成不计入分母**——按用户可见的最终输出计（见 §13.0） |
| 数据来源 | `style_review_result` 事件；每维度分列存储 |
| 统计周期 | 日 / 周 |
| 排除规则 | 测试账号、内部账号、`schema_version` 不匹配的历史批次 |
| **已知局限** | **v1 只含三维**（详细程度 / 引用长度 / 讲解语言一致性）。B 类未启用（§8.5 未校准），术语处理已下线（§8.1），冗余句式未实现。「详细程度」只实现了两项计算方式中的前一项 |
| 阈值来源 | **占位待定**（§3.2 的 ≥85% / 20 轮均为占位）。确定路径：埋点回流后按真实会话轮次分布取 P90 |

**不做单一混合分**（§8.1 设计要点），埋点也必须按维度分列——
否则指标定义与数据结构不一致，事后无法拆开。

#### 3.4.2 重生成触发率

| 项 | 内容 |
| --- | --- |
| 业务定义 | 讲解首版未通过风格审查、需要重写的比例 |
| **分子** | `regeneration_triggered` 事件数去重到轮（一轮内重生成 2 次仍计 1） |
| **分母** | **有审查的**讲解轮次数 |
| 时间窗 | 按轮 |
| 去重规则 | 按 `explain_turn.event_id` 去重。**分母不含无审查轮次** |
| 数据来源 | `regeneration_triggered` + `explain_turn` |
| 统计周期 | 日 / 周；**须按风格配置分组**——实测它强依赖配置偏离程度 |
| 排除规则 | 同上 |
| **已知局限** | **不按配置分组的总体触发率没有意义**：实测默认档 0/15、最严档 8/15。混在一起报会得到一个不对应任何真实用户的中间值 |
| 阈值来源 | 原 `< 20%` 为**占位待定**；且 §9.1 已撤销「降低触发率是第一优先级」——触发率高不必然贵 |

**这条口径的分母曾经算错过**：47 次重生成 ÷ 90 次计划生成 = 52% 是错的，
正确分母是有审查组的轮次数 45，得 62%（见第 0 周实验报告 §三）。
**分母写清楚不是形式主义。**

#### 3.4.3 单轮成本

| 项 | 内容 |
| --- | --- |
| 业务定义 | 产生一轮用户可见讲解所花的模型费用 |
| **分子** | 该轮**全部尝试**的 token 成本之和（含被丢弃的重生成中间稿）+ 兜底判断成本 |
| **分母** | 1（按轮记录） |
| 时间窗 | 按轮 |
| 去重规则 | 三类输入 token **互不重叠**：未命中输入 / 缓存读 / 缓存写，不可相加重复计 |
| 数据来源 | `explain_turn.usage` 四字段 + 当时适用的价目 |
| 统计周期 | **报均值 + P50 + P90**，不只报均值 |
| 排除规则 | 失败重试（API 5xx）不计入质量指标，但**计入成本**——那笔钱真的花了 |
| **已知局限** | 价目带 introductory 到期日，**日志必须记录当时用的哪套价**，否则事后无法重算 |
| 阈值来源 | **实测依据**：$0.0151（均值）/ $0.0141（P50）/ $0.0225（P90），2026-08-26，180 轮 |

#### 3.4.4 单会话成本

| 项 | 内容 |
| --- | --- |
| 业务定义 | 一次完整学习会话的模型费用 |
| **分子** | 会话内全部轮次的单轮成本之和 |
| **分母** | 1（按会话记录） |
| 时间窗 | 会话 |
| 去重规则 | 依赖「会话」的切分规则——**见下方占位项** |
| 数据来源 | `explain_turn` 按 `session_id` 汇总 |
| 统计周期 | 报均值 + P50 + P90 |
| 排除规则 | 同上 |
| **已知局限** | **本指标的分母口径尚未定义**（见 3.4.5）。当前实测值来自**固定 15 轮**的实验会话，不是真实会话长度分布 |
| 阈值来源 | **实测依据**：默认档 $0.2971、最严档 $0.3245（15 轮，2026-08-26）。**上限仍为占位待定**，公式与确定路径见 §9.1 |

#### 3.4.5 四个定不下来的口径（占位待定 + 确定路径）

**不硬定。** 现在填一个数，与随手写的没有区别。

| 项 | 为什么定不下来 | 确定路径 |
| --- | --- | --- |
| **「会话」怎么切** | 交互间隔多久算新会话，取决于真实使用节奏，而前端还没有 | 埋点回流后，按真实交互间隔的分布找拐点（双峰之间的谷底）确定。**这是北极星指标的分母，PRD 此前从未定义过它** |
| 「周活跃」 | 打开算活跃，还是至少完成一轮讲解才算 | 同上。两种口径都算一遍，看哪个与留存的相关性更强 |
| 「次周留存」 | 自然周还是注册后 T+7；分母是全部注册用户还是首周有过讲解行为的用户 | 同上。§3.2 的 ≥30% 标的是「产品目标」，**但口径不定则该目标无法验证**——一个不能被验证的目标不构成约束 |
| 护栏指标「重复提问率」 | 需要概念级标注 | 见 §3.1 |

**「一轮」算不算重生成——这个能定**：
**按用户可见的输出计，重生成不计入轮次**，只计入成本与质量指标。
理由见 §13.0：否则同一份数据在成本表和北极星指标里含义不同。

## 4. 用户与场景

### 4.1 目标用户

核心画像：对学习质量有明确要求的大学生，尤其是跨语言学习者（如英文授课但中文思考的留学生）。

关键限定：对讲解质量无感知的用户不是目标用户——他们不会察觉风格问题，因而不会有使用动机。这一限定必须写明，否则会误判市场规模。

### 4.2 典型场景

| 场景 | 频次 | 说明 |
| --- | --- | --- |
| S1 · 课后当周消化 | 每周 1–2 次 | 刚上完课，理解本周课件 |
| S2 · 期中/期末复习 | 季节性高峰 | 集中过多周内容 |
| S3 · 卡在某个概念 | 不定期 | 针对性提问 |

## 5. 需求范围

### 5.1 v1 做

**F1 · 风格获取**
- 冷启动：用同一段课件内容生成两个风格差异明显的样例，用户二选一
- 迭代收敛：每次选择后更新对用户风格参数的后验估计；下一对样例针对当前不确定性最高的维度生成，而非随机
- 目标：5–8 次比较后收敛，之后不再打扰
- 持续校准：每次讲解后提供快捷反馈按钮（太啰嗦 / 例子没懂 / 讲太浅 / 讲太深），反馈直接更新配置
- 配置以结构化参数存储，非自然语言描述（可程序化检查的前提）

设计要点：二选一的认知负担显著低于"从多个中挑一个"，且符合 P1 的核心洞察——用户描述不出风格，但能在两个样例间做出选择。

降级方案：若主动选题的实现复杂度超出预期，退化为固定顺序的成对比较（每个维度问一次），仍优于 4 选 1。

**F2 · 课件上传与处理**
- 支持 PDF / PPT
- 切片、索引，供检索使用

**F3 · 讲解对话**
- 基于检索到的课件片段生成讲解
- 每次输出经风格审查后才呈现给用户

**F4 · 跨会话记忆**
- 风格配置跨课程、跨会话继承
- 记录用户标记为"没看懂"的概念

### 5.2 v1 明确不做（Non-goals）

| 不做的功能 | 理由 |
| --- | --- |
| 课堂实时划词解释 | 技术形态完全不同（前端渲染问题而非 AI 问题），与 P1、P2 无关 |
| Past paper / 刷题讲解 | 先把讲解做透，避免功能分散 |
| 笔记生成、脑图、总结 | 功能堆砌，与定位无关 |
| 多人协作 / 分享 | 无核心价值关联 |
| 移动端原生 App | Web 优先，降低开发成本 |

## 6. 能力边界定义

### 6.1 能做

- 基于文本课件的概念讲解、类比、举例
- 按结构化参数调整表达方式
- 判断内容是否符合给定风格约束

### 6.2 明确做不到 / 效果不可靠

| 边界 | 产品应对 |
| --- | --- |
| 扫描件、手写笔记等图片型课件 | 上传时检测并提示不支持（v1） |
| **正常 PDF 中内容主要在图里的页** | **上传后告知；检索无果时文案区分「内容在图里」与「课件未提及」** |
| **图内文字被转为矢量轮廓的页** | **无法检测，v1 不解决；见 §10 兜底** |
| 课件之外的知识 | 溯源约束 + 明确标注"以下内容超出课件范围" |
| 判断考试重点 | 不提供此功能，避免误导 |

原则：所有超出课件范围的内容必须显式标注。

**第二行为 2026-08-21 新增。** 原表只有「扫描件、手写笔记等图片型课件」一行，
覆盖的是**整份**不可用的情形；覆盖不到「文档整体判定 usable、但其中若干页的实质
内容压在图里」这种情形——**而它恰好落在课件最有内容的地方**。

实测依据：`MIT14_129S25_lec02.pdf`（14.129 *Blockchain and the Design of
Financial Systems*）的 p33–p36 是应对 CAP 三难的**四个完整模型**（共同账本 /
单一账本 / DLT 版单一账本 / 兼容账本），每页都有成段论述，**全部压在图里**，
可提取文本各 **2 个字符**（只有页码）。该文档 50 页中 46 页可用，整体
`verdict = usable`——**用户会以为整份都能讲**。

两类失败在用户侧的表现不同，故文案要分开（详见 `实验脚本/检索评测集/README.md` §3.1）：

| | 内容主要在图里、但页仍可用 | 页完全读不出文本 |
| --- | --- | --- |
| 检索结果 | 命中只有标题的片段，**答非所问** | **直接返回空** |
| 危险程度 | **更高——它看起来成功了** | 较低，失败是显式的 |

v1 不解决读图（多模态与图内 OCR 均不在范围内），但边界要写准：
**能力做不到不等于可以不告知。** 相关兜底文案见 §10。

**第三行为 2026-08-21 新增，它比第二行更隐蔽。** 实测：22.081J p20 的图内标签
`Furnace` / `Heat exchanger` / `Steam turbine` / `Makeup water` 渲染后肉眼清晰，
但**被转成了矢量轮廓，不在文本层**——该页 9 个文本块里没有任何一个是图内标签。

与第二行的关键差别：

| | 内容主要在图里（第二行） | 图内文字转为矢量轮廓（第三行） |
| --- | --- | --- |
| 页的判定 | `image_only`，可用页数会少 | **`digital_text`，正常可用** |
| 是否进切片 | 否 | **是，9 个块** |
| 检索能否命中 | 否 | **能，且命中的是正常文本** |
| 系统知不知道漏了 | **知道**（`skipped_pages` 里有记录） | **完全不知道** |

**第二行是系统知道自己读不了；第三行是系统以为自己读到了。**
后果是讲解 agent 基于不完整信息给出**看起来完全正常**的答案，
既不会触发任何兜底，也不会有任何标记。

v1 无法检测这种情况——判断「这张图里有没有文字」本身就需要读图。
本行写进 §6.2 是为了**把它记成已知边界而不是未知风险**；
一旦引入多模态或图内 OCR，这是首先要覆盖的场景。

## 7. 技术方案约束

### 7.1 架构

```
课件上传
   ├─→ 切片 & 向量索引
   └─→ 术语表提取（每门课一次性，模型辅助 + 用户可增删）
         ├─ 正文通道：加粗/标题/定义框/跨页高频名词短语
         └─ 图注通道：独立处理，正文通道抓不到（见 §8.1）
                ↓
用户提问 → 检索 agent（取 Top-K 相关片段）
                ↓
            讲解 agent（生成）
                ↓
            风格审查 agent
              ├─ A 类：规则计算（含术语表字符串匹配，零模型成本）
              └─ B 类：低成本模型判断
                ↓
          ──不合格──→ 重生成（上限 2 次）
                ↓ 合格
            输出 + 反馈收集 → 更新风格配置
```

术语表的三处复用：审查侧的分母来源 / 检索信号 / F4「没看懂」概念的锚点。一份数据三处用，避免为单一指标引入额外链路。

### 7.2 多智能体的必要性论证

本项目使用多 agent 不是为了技术展示，而是因为：

生成方与审查方的目标相反。 讲解 agent 的目标是把内容讲清楚，它没有动机去检查自己是否啰嗦；风格审查 agent 的唯一目标是执行约束。让同一个 agent 兼任两职，会出现自我合理化。

这与"防幻觉需要独立核查"是同一类设计原理。

### 7.3 模型选型约束

- 不硬编码模型，做抽象层，配置可切换
- 选型依据为实验结果而非主观印象：候选模型在固定风格约束下的指令遵循稳定性，通过 §8.2 的漂移实验测定
- 分层调用：
  - 讲解 agent → 中高端模型（质量敏感）
  - 风格审查 agent → **v1 完全不调模型**：只查 **A 类三维**（详细程度 / 引用长度 / 讲解语言一致性），纯规则计算，零模型成本。B 类（需低成本模型判断）移入 v1.1，届时再引入分层调用。**2026-08-22 修正**：原文写「四维」，那是含 `term_annotation` 的旧指标集；v1 的定义按维度枚举，见 §3.2
- 课件内容会话内不变 → 必须启用 prompt caching　⚠️ **本条的前提在接入检索后不再成立，见下**

> #### ⚠️ prompt caching 那条的前提待重新验证（2026-08-22）
>
> 「课件内容会话内不变」成立的前提是**课件全文在 system 里**——那是第 0 周的架构
> （漂移实验刻意不含检索，课件全量进 system 约 5K token）。
>
> **F3a 接入检索后，课件全文根本不在上下文里**：system 只剩风格约束与课件清单，
> 实测约 **406 token**，低于最小可缓存 prefix 长度（1024），
> **缓存断点不生效且不报错**；而每轮的检索片各不相同，天然不可缓存。
> 会话内真正还值得缓存的只剩**对话历史**。
>
> **实测已回来（2026-08-26），本条前提确实不成立**：
>
> | | 第 0 周 | 接检索后（实测） |
> | --- | --- | --- |
> | 课件全文 | 在 system 里（约 5K token） | **不在上下文里** |
> | system 段 | 约 5K token，断点生效 | **485 字符 / 约 406 token，断点不生效** |
> | 每轮检索片 | 无 | 约 400 token，**每轮不同，天然不可缓存** |
> | 实际被缓存的 | system + 对话历史 | **只剩对话历史** |
>
> **caching 仍然要开，但理由变了**：省的是**对话历史**，不是课件。
> 实测第 2 轮起 78/78 命中历史缓存，读取 1,188–27,228 token，缓存读占成本 10%。
>
> 本条的正确表述应为：**对话历史逐轮增长且前缀不变 → 必须启用 prompt caching**；
> 「课件内容会话内不变」在接检索后不再是启用 caching 的理由，
> 因为课件全文根本不进上下文。
>
> 这是**第 5 次「被数据推翻的判断」**（见 `F2开发.md` §八），
> 且与前四次形态不同：**前四次要跑完实验才知道，这次一次量纲检查就够了**——
> 406 与 1024 是两个确定量，不是统计结论。

### 7.4 上下文策略

- 单轮上下文 = 系统提示 + 风格配置 + 检索片段 + 最近 N 轮对话摘要
- 不累积全部历史，超过阈值后对早期对话做摘要压缩
- 目的：同时控制单次长对话内的幻觉与成本膨胀

### 7.5 · 技术选型论证

本节记录评估过但未采用的方案。选型的价值在于说明为何不采用，而非罗列采用了什么。

**检索方案**

| 方案 | 评估结论 |
| --- | --- |
| 全文塞入上下文 | ❌ 成本随课件规模线性增长，且长上下文是 P2 漂移的直接诱因 |
| 向量检索（采用） | ✅ 课件规模可控（单门课数十页），朴素向量检索召回已足够 |
| GraphRAG / 知识图谱 | ❌ 课件已有天然结构（章节、页码），构图的边际收益低于其构建成本与延迟代价 |
| Agentic RAG（模型自主决定检索策略） | ❌ 引入不确定性与额外调用；本场景的检索意图单一（"讲解这个概念"），不需要多跳推理 |

检索不是本项目的瓶颈，瓶颈在风格控制。技术投入应集中在后者。

**风格控制方案**

| 方案 | 评估结论 |
| --- | --- |
| 仅靠系统提示词 | ❌ 即 Claude Project 的做法，已知会随上下文增长而衰减（即 P2） |
| 生成 + 独立审查 + 重生成（采用） | ✅ 生成方与审查方目标相反，是结构性解法而非提示词调优 |
| 微调专用模型 | ❌ 每个用户的风格不同，无法为个体微调；且缺乏训练数据 |
| 约束解码 / 语法约束 | ❌ 可控制格式，无法控制"是否举例""深度是否够"这类语义属性 |

**偏好获取方案**

| 方案 | 评估结论 |
| --- | --- |
| 用户文字描述 | ❌ 即 P1 本身——用户说不出 |
| 4 选 1 单次选择 | ❌ 只能定位到 4 个预设点，覆盖不了多维连续的风格空间 |
| 成对比较 + 主动选题（采用） | ✅ 认知负担最低，且可用信息增益指导下一次比较，收敛更快 |

与 RLHF 的关系：成对比较是 RLHF 中偏好数据收集的标准形式。区别在于 RLHF 用群体偏好对齐模型，本产品用个体偏好配置生成约束——同一方法论，不同应用层。

## 8. 评测方案

### 8.1 风格维度的量化定义

风格维度分为常驻与条件激活两类，激活与否由用户的风格配置决定。未激活的维度不计入遵循度分母，否则单语用户的得分会被虚高拉起。

**A 类 · 规则可计算（零模型成本）**

| 维度 | 激活条件 | 计算方式 | 达标线 |
| --- | --- | --- | --- |
| 详细程度 | 常驻 | 平均段落字数、~~总输出长度~~ | 按配置区间 |
| 冗余句式 | 用户已标记 ≥1 条 | 被标记句式是否复现 | 0 次 |
| 引用长度（合规约束） | 常驻 | 单段原文引用字数 | ≤ 100 字，见 §12.1 |
| 讲解语言一致性 | 讲解语言 ≠ 课件语言 | 目标语言字符占比 | 按配置，**单侧下限**（v1.0 默认 ≥ 0.85） |
| ~~术语处理~~ | ~~同上~~ | ~~命中术语表的词中，符合所配策略的比例~~ | **⚠️ v1 不激活，见下** |

#### ⚠️ 术语处理维度 v1 不激活（2026-08-21）

**决策**：v1 走多课程，该维度下线，不计入风格遵循度。

**理由**：多课程场景下，术语表的分母只能来自**自动提取**——为每门课人工整理
不可行（A4 已验证每周有 3–4 门课件）。而自动提取的实测召回率是
**32%**（正文通道 17% / 图注通道 57%，见 `glossary/README.md`）。

这不满足 §8.1 自己写的可用标准：

> **召回率低意味着分母残缺，此时标注率再高也说明不了什么。**
> 同理于 §8.5 先校准 judge 再画曲线。

把一个分母残缺 68% 的维度计入达标判定，得到的数值无法解释——
它既不能证明模型遵守了策略，也不能证明没有。

**重启条件**（两条须同时满足）：

1. 自动提取的**正文通道**召回率达标（阈值待定，确定路径同本节其余占位项：
   人工标注集建成后按可接受误判率反推）
2. 在**第二门课的独立金标准**上复现——单门课上的数字受判据拟合影响，
   见 `glossary/README.md` §1.2 记录的 5 轮迭代

**已知影响**：§8.2 漂移实验中唯一呈现组间差异的正是本维度。该维度下线后，
漂移实验对 v1 现行指标集**不再提供直接证据**——详见 §8.2 的说明。

以下三值配置参数的定义保留，供重启时直接启用：

术语处理为三值配置参数，非布尔项：

| 取值 | 含义 |
| --- | --- |
| keep_original | 保留原文术语，不翻译 |
| translate_with_source | 译文 + 原文括注 |
| translate_only | 仅用译文 |

单语场景（讲解语言 = 课件语言）下该参数为 N/A，整项不激活。

**首现的作用域是整段对话（2026-08-20 修正）。** 初版实现按单轮重置，等于要求同一术语每轮重复标注。这不只是作用域写窄了——§2 的 P1 明确把「太啰嗦」列为痛点，**要求重复标注正是在奖励一个让用户体验变差的行为，指标方向与产品目标冲突**。实测证据：审查触顶失败的 8 个轮次中，6 个的残留术语在同轨迹更早轮次里已被正确标注过，模型是在做正确的事而被指标判为违规。修正后按整段对话计，且排除依据是「已被正确标注过」而非「已出现过」——否则一个始终未标注的术语几轮后会永远逃出检查。

讲解语言一致性只设下限、不设上界：要检测的是「开始说英文」，不存在「中文太多」这种失败模式；设上界还会与术语处理维度重复计量——`translate_with_source` 要求模型写「热机（heat engine）」，括注中的英文本就会压低该维度，两个维度将给出方向相反的信号。

术语识别方案：不在生成文本中现场识别，而在课件上传阶段一次性提取该课程术语表（加粗/标题/定义框词汇、跨页高频名词短语、Glossary 页），审查时退化为字符串匹配。

上述启发式全部依赖排版或词频信号，**抓不到图注文字**——图注既不加粗也非标题，且每条通常只出现一次。故需为图注单开独立提取通道（识别无句法结构的孤立名词短语簇），并配合用户手动增删入口；该通道误收风险较高，不宜全自动。

误差方向说明：术语表必然存在遗漏。遗漏项不计入分母，只会降低指标灵敏度，不会造成误判——误差方向是安全的。反之误收普通词会导致误判，故提取策略取保守，宁漏勿错，并提供用户手动增删入口。

**B 类 · 需模型判断（用低成本模型）—— ⚠️ v1 不做，移入 v1.1**

> **v1 的风格遵循度只计算 A 类维度。** B 类依赖低成本模型判断，而 judge 的可靠性需要人工标注的 ground truth 来验证（§8.5）。在完成校准之前使用 B 类，等于把**未经验证的测量工具的输出**当作指标。**宁可指标覆盖面窄，不可指标来源不可信。** 启用条件见 §8.5。

| 维度 | 激活条件 | 判断方式 |
| --- | --- | --- |
| 是否使用类比/举例 | 用户已配置偏好 | 二分类 |
| 结构（先结论 vs 先铺垫） | 常驻 | 二分类 |
| 讲解深度（只讲是什么 vs 讲原理） | 常驻 | 三档评分 |

#### ⚠️ 「总输出长度」从未实现（2026-08-26 实测发现）

「详细程度」这一行写的是**两项**计算方式，而 `a_rules` **只实现了平均段落字数**。
按「未实现的维度不参与达标判定」的纪律，v1 的详细程度只按平均段落字数判。

**后果不是少一个数**：平均段落字数可以**靠多敲回车平凡满足**。
按被测量自身的定义式分解（`字/段 = 总字数 ÷ 段数`，两边取对数后变化量可加，
**无阈值、无自由参数**），配置扫描实验实测：

| 配置点 | 字/段 | 真的讲短 | **分段** |
| --- | --- | --- | --- |
| P1（40–90 字） | 0.927× | 83% | 17% |
| P2（25–55 字） | 0.606× | 36% | 64% |
| **P3（15–40 字）** | 0.420× | 28% | **72%** |

**机制随偏离程度切换**：轻度收紧时模型是真的压缩，收得越紧越转向分段。
选了「很简洁」的用户想要的是前者，在最严档拿到的主要是后者，
而**审查看不见这个失败**——这是通则五的形态，与 D44 同源
（D44 错在太严、逼模型变啰嗦，这次错在漏、放过一个用户不想要的行为）。

补进 **v1.1** 待办（`A类规则计算脚本/TODO.md`）。v1 只加观察项
（`total_chars` / `paragraph_count`，见配置扫描实验口径 E10），不补判定。

**设计要点**

- 本节各维度的达标线同样适用 §3.2 的阈值来源规则。其中「引用长度 ≤ 100 字」来源明确（§12.1 的合规约束，非风格偏好）；「术语处理 ≥ 90%」为**占位待定**，确定路径为 §8.5 的人工标注集建成后按可接受误判率反推；「详细程度」区间已按六轮真实讲解实测校准（均值 41–75 字，故取 30–120），属**实测依据**。
- **术语表召回率为独立指标**（人工整理的术语表为金标准，召回率 = 自动提取命中的人工表条目数 / 人工表条目总数）。它衡量的是测量工具本身，不并入术语处理维度：召回率低意味着分母残缺，此时标注率再高也说明不了什么。同理于 §8.5 先校准 judge 再画曲线。
- 术语表条目须区分来源（正文 / 图注）。「术语表相对课件的覆盖缺口」与「讲解文本相对术语表的分母缺口」是两个数，不可混为一谈。**实测修正**：曾假设图注术语因正文未出现而进不了分母，六轮真实讲解否定了这一点——图注术语占全部术语出现的 42%，在图密集章节（火电厂流程、压水堆结构）达 83–87%，因为那些页的实质内容就在示意图里。图注术语必须收录。
- A 类优先，能用规则解决的绝不调模型。这是成本控制的关键，也是可讲的设计决策。
- 遵循度按维度分别报告，不做单一混合分。混合分会掩盖结构性问题——例如"长度控制良好但从不给类比"仍可能得到 88% 的表面达标分。§3.2 的 ≥85% 应理解为各激活维度均需达标，而非平均值达标。
- §8.2 的漂移实验不受激活机制影响：该实验固定单一配置，激活维度集合恒定，前后可比。

### 8.2 关键实验：漂移衰减曲线

**实验设计**

- 固定一份风格配置 + 一份课件
- 条件组：有审查 agent / 无审查 agent
- 每个条件跑 **3 条独立轨迹**，各 15 轮对话，每轮计算风格遵循度
- 15 轮取自一段真实复习序列，刻意不凑到 20：凑数需要编造提问，样本会偏离真实学习行为，测出来的适用范围随之收窄
- 重复必须是整条轨迹的重复：同轨迹内采样只是给单个点加误差棒，轨迹本身仍是单次实现，测不出漂移的离散度
- 结果按均值 + 全距作图，不画裸线；实验记录须写明重复次数与离散程度
- 遵循度按维度分别报告，**不合并**。本次提问序列中有若干轮为纯原理追问，术语密度低，`term_annotation` 在这些轮次信噪比低，而 `chinese_ratio` 与 `paragraph_length` 不受影响——合并成单一曲线会让低信噪比的维度污染其余三个
- ⚠️ **本节描述的是第 0 周那次实验（四维指标集）**。v1 是三维，`term_annotation` 已下线；该实验唯一测出组间差异的正是这个维度。**v1 指标集下的新对照实验见 `实验脚本/配置扫描实验/`**，其自变量是「配置偏离默认的程度」而非轮次——第 0 周已证明这三维在 15 轮内不随轮次衰减，再跑轮次拿不到新信息
- 实验可附带**观察项**（不进指标、不参与达标判定）。本次观察：某轮提问超出课件范围时，模型是否遵守 §6.2 显式标注。它不是 A 类维度，混进指标会让「风格遵循度」这个数悄悄变成别的东西
- 实验配置可覆盖生产口径，覆盖项须记入实验元数据。已知覆盖：术语维度的最小分母护栏实验用 2、生产用 5——若为满足护栏去挑术语密集的提问，测出来的将是「术语密集提问下会不会漂移」而非「真实使用中会不会漂移」，适用范围被悄悄收窄。代价是低分母点可信度较低，故逐轮记录首现术语数并在图上单独标注
- 绘制遵循度 vs 轮次曲线（均值 + 误差带）

**预期产出**：证明审查 agent 的必要性，并量化其收益。

同一框架用于模型选型：在多个候选模型上重复实验，选择衰减最平缓者。

这张图是本项目在面试中最有力的材料——它同时证明了指标定义能力、对照实验设计能力、以及用数据支撑设计决策的能力。

### 8.5 · 评判模型的可靠性校准 —— **v1.1 前置任务**

> **本节是启用 B 类维度的必要条件。** v1 不做 B 类，因此本节也移至 v1.1；但它必须在 B 类启用**之前**完成，不能与之并行。
>
前置问题：§8.1 的 B 类维度由低成本模型判断，§8.2 的漂移曲线与 §8.4 的上线达标线均建立在这些判断之上。若 judge 本身不可靠，全部指标失效。 本节先验证测量工具。

**已知的系统性偏差**

模型作为评判员存在若干已被广泛观察到的倾向，需逐项测试：

| 偏差 | 表现 | 测试方法 |
| --- | --- | --- |
| 长度偏好 | 倾向给更长的回答更高分 | 同一内容生成长短两版，比较评分差异 |
| 位置偏好 | 受选项呈现顺序影响 | 调换 A/B 顺序重测，看结论是否翻转 |
| 自我偏好 | 倾向同家族模型的输出 | 用不同厂商模型生成内容，交叉评测 |

**校准流程**

1. 构建标注集：100–200 条讲解样本，覆盖各风格维度的正例与反例
2. 双人独立标注：由 2 人独立标注，不得由一人完成（否则算不出一致性）
3. 计算一致率：使用 Cohen's kappa 而非简单准确率——类别不平衡时准确率会虚高
4. 人机对比：judge 与人工标注的 kappa
5. 不达标则校准：加入少样本示例、拆解评分标准、必要时升级模型，重测

**达标线**

| 项 | 要求 |
| --- | --- |
| 人工标注者之间 kappa | ≥ 0.7（低于此说明维度定义本身有歧义，需先修订 §8.1） |
| judge 与人工 kappa | ≥ 0.6 |
| 长度偏差 | 内容等价时评分差异 < 10% |
| 位置偏差 | 顺序调换后结论翻转率 < 5% |

注意第一行：如果两个人对同一条内容的判断都对不齐，问题不在 judge，在维度定义写得不够清楚。这种情况下应先回去改 §8.1，而不是调 judge。

**时序**

- 第 0 周（MVP 之前）：用离线样本完成首轮校准。§8.2 的漂移实验必须在校准之后进行，否则曲线不可信
- 第 6 周起（内测后）：用真实用户输出复测。离线样本的分布可能与线上不同，需验证 judge 在真实分布上是否仍可靠

#### 单会话成本上限：占位待定

原目标 `< $0.05` 与「20 轮」「85%」同属初版随手填的占位值，**从未从定价模型推导过**。按 §3.2 的阈值来源规则，它应归为**占位待定**，而不是保留或放宽。

确定路径：

```
单会话成本上限 = 月付价 × (1 - 目标毛利率) ÷ 月均会话数
```

三个输入项目前全部未定，需先确定定价模型（**待补章节**：订阅价 / 毛利目标 / 用量分布，以及订阅制下「用户已为模型付过一次费」的双重付费问题）。在此之前不设新的硬性数值。

**参考推算**（仅为标定量级，非目标值）：若月付 ¥19.9（约 $2.75）、月均 8 次会话、目标毛利 50%，则上限约 **$0.17**。

| 对比 | 倍数 | 判断 |
| --- | --- | --- |
| 实测 $0.590 vs 参考 $0.17 | 3.5× | 可通过工程优化接近的距离 |
| 实测 $0.590 vs 原占位 $0.05 | 11.8× | 不是工程问题，是目标值本身没有依据 |

#### 成本归因（按实测修正）

初版曾把检索列为压成本的主要手段，**实测不支持**：

- 输出 token 占成本 **68%**，检索只作用于输入侧。输入压到零也只省 32%（$0.59 → $0.40）。
- **成本主体是重生成**：62% 的触发率使有审查组的实际生成次数约为无审查组的 2 倍（92 次 vs 45 次）。
- 把触发率压到 20% 目标、再叠加检索，估算约 **$0.25**——仍是原占位值 $0.05 的 5 倍。

结论：**降低重生成触发率是成本优化的第一优先级**，检索是次要手段。

实测来源：`实验脚本/漂移实验/实验报告.md`（2026-08-20，claude-sonnet-5 / effort=medium，2 条件 × 3 轨迹 × 15 轮）。

#### ⚠️ 上面那条结论已撤销（2026-08-26）

| 单轮总成本 | $0.0187 → **$0.0196（+4.8%）** |
| 延迟 | 均值 **1,406 ms** · P50 1,427 · P90 1,595（n=12） |

比原估计（+12%、+1–2 s）**便宜也快**，因为检索片比预估短。

**它是严格串行的一跳**：输入是检索结果、输出进生成 prompt，
既不能与检索并行，也不能与生成并行——只能压小，不能藏掉。
但它**不是延迟超标的原因**：生成本身 P50 已 12.8 s（§9.2 要求 < 15 s）。

⚠️ **收益未测出**：有/无判断两组的「显式说明边界」计数为 **2/12 vs 1/12**，
n=12 上不可区分。代价有数、收益没有——见 `实验脚本/配置扫描实验/F3b报告.md` §三。

要求：从第一天起将每次调用的 token 数与成本写入日志。 面试必问单位经济，能报出具体数字与结构的候选人极少。

### 9.2 延迟

| 环节 | P95 要求 |
| --- | --- |
| 首字返回 | < 3s |
| 完整讲解 | < 15s |
| 审查不通过导致的重生成 | 用户不应感知到明显额外等待 → 采用流式输出 + 后置审查提示，或先审查再流式输出（需权衡，见下） |

待决策：审查 agent 会引入额外延迟。三种方案：

- A · 先审后出：质量有保证，但延迟翻倍
- B · 边出边审：延迟低，但可能出现"输出到一半被判定不合格"的尴尬
- C · 句子级并行审查：流式输出的同时，对已完成句子并行跑 A 类规则检查（正则、字符统计、术语表匹配，均为毫秒级），命中违规才中断并回滚；B 类维度异步执行，仅用于更新配置与统计，不阻塞输出

**采用 C，已验证可行。** A 类规则的实测耗时：单句 0.118 ms、整段（1800 字符）约 11 ms，相对首字 3s 的预算可忽略，句子级并行审查不构成延迟瓶颈。B 类的语义判断无法在流式过程中及时给出结论，强行等待即退化为方案 A，故仍走异步。

降级方案 A 保留为兜底，但目前无需启用。

补充（实测）：当前 Claude 模型已移除 `temperature` / `top_p` / `top_k`，传入返回 400。实验的可固定参数是 `effort` 与 `thinking`，「固定温度以控制随机性」在这一代模型上不可执行。

## 10. Bad Case 与兜底设计

| 场景 | 表现 | 兜底方案 | 用户可见文案（示例） |
| --- | --- | --- | --- |
| 课件为扫描件/图片 | 无法提取文本 | 上传时检测并拒绝 | 「这份课件是图片格式，暂时读不了。可以试试文字版的 PDF。」 |
| 提问超出课件范围 | 模型可能编造 | **每轮一次模型判断**（`covered`/`insufficient`/`partial`，低成本模型，成本与延迟见 §9.1）**＋ 跳过页限定语**（规则，零成本）。**检索分数判不了**——§10.1 实测四个 embedding 模型上两组分布完全重叠 | **不写模板文案**：判断结果作为输入进讲解 prompt，由讲解 agent 用自己的话说清边界（§10「兜底文案必须具体」）。实现见 `explain/gap.py`，口径 G01–G13 |
| 风格审查连续 2 次不通过 | 无法生成合规输出 | 降级输出 + 说明 | 「这次讲解可能不太符合你设定的风格，你可以点反馈告诉我哪里不对。」 |
| 模型 API 不可用 | 请求失败 | 切换备用模型 / 明确报错 | 「服务暂时不可用，稍后再试。你的课件和设置都还在。」 |
| 超时 | 长时间无响应 | 30s 超时中断 | 「这次响应超时了，要重试吗？」 |
| 用户上传非课件文件 | 讲解无意义 | 内容类型检测 | 「这份文件看起来不像课件，确认要继续吗？」 |
| 用户上传含个人信息的文件 | 隐私风险 | 提示用户 | 见 §12 |

原则：兜底文案必须具体，不写"请稍后重试"这类无信息量的提示。

### 10.1 「课件里没有提到」判不出来（2026-08-21 实测）

**实测结论：纯向量相似度无法区分「课件里有答案」与「课件里没有」。**

检索评测集的 30 题中，5 题为 `no_answer`（课件讲了该主题但没讲该子问题）。
比较两组的 top-1 相似度：

| 模型 | 有答案组 | `no_answer` 组 | 间隔 |
| --- | --- | --- | --- |
| text-embedding-3-small@1536 | [0.322, 0.539] | [0.415, 0.445] | **−0.123** |
| text-embedding-3-large@3072 | [0.251, 0.534] | [0.340, 0.448] | **−0.197** |
| text-embedding-3-large@1024 | [0.296, 0.571] | [0.346, 0.471] | **−0.175** |
| text-embedding-3-small@512 | [0.367, 0.558] | [0.436, 0.475] | **−0.108** |

**四个模型全部重叠，无一可分。** 这不是「阈值没调好」——不同模型、不同维度上
方向一致，是方法本身的界限。典型反例：问「各方案造价多少」的相似度 0.4706，
**高于** 5 道有答案的题，因为课件确实**提了**成本效益分析这个角度、只是没给数字。
向量检索抓的是主题相关性，它本来就只能到这一步。

**产品含义：§10 的兜底必须区分三种情况，而检索分数一种都判不了。**

| 情况 | 正确文案 | 判据 |
| --- | --- | --- |
| 课件确实没提 | 「课件里没有提到，我可以基于通用知识讲…」 | 需模型判断 |
| **内容在图里读不了** | 「这部分在第 N 页的图里，我读不了图」 | `skipped_pages` + 模型判断 |
| **检索到了但不够回答** | 「课件里只提到 X，没有展开 Y」 | 需模型判断 |

**一次模型判断可以同时覆盖这三者**：把候选片与问题一起交给模型，问
「这些片够不够回答这个问题；如果不够，是完全没提、还是提了没展开」。
否则要为三种情况各造一套机制，而其中两种根本没有可用的规则信号。

§6.2 新增的「内容主要在图里的页」正是第二种情况——它此前被归入第一种，
文案是错的（课件提到了，只是我们读不了）。

**成本影响见 §9.1**：这使 §10 的兜底从零模型成本变为**每轮都发生**的模型调用。

## 11. 假设清单

0→1 项目与成熟产品的关键差异：大量需求尚未被验证。必须显式区分「已验证」与「仍是猜测」，否则会把猜测当事实做进产品。

| 编号 | 假设 | 状态 | 验证方式 |
| --- | --- | --- | --- |
| A1 | 风格漂移是普遍现象且令用户烦躁 | **已验证** | 同学群体中普遍存在，有明确替代行为 |
| A2 | 大部分用户无法用语言描述自己想要的风格 | 部分验证 | 同学群体中普遍存在 |
| A3 | 用户愿意为解决此问题付费 | **未验证** | 目前仅有 1 个自述数据点（项目发起人本人）。自述意愿是弱证据 |
| A4 | 平时（非考试季）有足够使用动机 | **已验证** | 每个教学周都有至少 3–4 个不同课程的课件需要学习。**该假设同时是 v1 走多课程的依据之一**——见下 |
| A5 | 「样例选择」比「文字描述」更有效 | 未验证 | A/B 对比：两种配置方式下的风格满意度 |
| A6 | 目标用户规模足够 | 未验证 | 需竞品调研 + 小红书等渠道试水 |

---

### 11.1 A4 与多课程决策的关联（2026-08-21）

A4 已验证：每个教学周有 3–4 门不同课程的课件需要学习。

**「只支持单门课」与这条已验证的假设直接冲突。** 若 v1 只支持单门课，
用户每周要面对 3–4 门课件却只能用产品处理其中一门，产品在真实使用节奏里
覆盖不到 3/4 的场景——而 A4 正是「平时有足够使用动机」的依据。
用一个已验证假设去论证使用动机，同时又做一个与该假设冲突的范围决策，
两者不能并存。

**这是 v1 走多课程的依据之一**，其直接后果是术语表的分母只能来自自动提取
（人工整理 3–4 门课不可行），进而导致术语处理维度在 v1 下线——见 §8.1。

记此关联是为了让这条决策链可回溯：**多课程不是功能偏好，是 A4 的推论**；
术语维度下线也不是能力不足的托词，是这条推论撞上自动提取实测水位的结果。

## 12. 合规与伦理

前置声明：以下为产品视角的风险梳理，非法律意见。撰写者不是律师。正式对外开放前将由专业人士复核。对当前的封闭内测形态，本清单作为设计约束使用。

适用法域：目标用户主要在新加坡，但未来可能面向境内，故两套框架并列考虑。部署地与用户所在地共同决定适用规则。

### 12.1 著作权（核心风险）

问题：大学课件的著作权通常归授课教师或学校，学生并非权利人。本产品涉及四个动作：存储、切片、API 传输、生成输出。前三者涉及复制，输出还可能涉及改编与信息网络传播。

**已纳入设计的约束**

| 措施 | 作用 |
| --- | --- |
| 课件仅存于用户个人空间，不跨用户共享、不建公共库、不做跨用户检索 | 将使用场景限定在个人学习 |
| 不用于模型训练 | 避免内容以任何形式沉淀进模型 |
| 一键删除；注销即清空 | 用户可随时终止 |

表述注意：上述措施的作用是显著降低风险，而非使行为自动落入"合理使用 / fair dealing"的安全区。中国著作权法的合理使用与新加坡 Copyright Act 2021 的 fair dealing 框架不完全等同，且判断需综合使用目的、商业性、对原作品市场的影响等因素。PRD 与对外文档中不宣称"属于合理使用"。

**需补充的措施**

1. 上传确认文案
   「我确认这是我本人所修课程的材料，仅用于个人学习，且未被标注为保密或禁止外传。」
2. 输出侧引用限制
   - 溯源引用单段上限 100 字
   - 系统提示词中明确禁止大段复述原文
   - 产品必须是"讲解"，一旦滑向"课件重述"即越界
   - 该限制应写入风格审查 agent 的检查维度（见 §8.1）
3. 评测材料的使用范围
   公开课程材料（如 MIT OCW）仅限内部开发与评测使用。**对外展示——demo 截图、简历、面试材料、博客、演示视频——一律使用自写的合成课件**，不得出现第三方课件原文或基于其生成的讲解内容。
   理由：CC BY-NC-SA 的 SA 条款约束改编作品，模型基于课件生成的讲解是否构成改编没有确定答案；内部评测不触发分发，对外展示则进入灰区。合成课件的成本远低于一次授权争议，且可按需构造极端样本用于测试审查 agent。
   另需注意：OCW 课件不必然整份都是 CC 授权的，部分页面会标注第三方保留权利，此类内容不适用上述内部使用空间。
4. 异议处理流程（半页纸即可）
   ```
   接收异议（公开邮箱）→ 定位相关内容 → 删除并回复 → 记录留档
   ```
5. 对外宣传禁止事项
   绝不出现「覆盖 XX 大学 XX 课程资料」类表述。这是最直接的不利证据，且与产品定位（个人学习工具，非资料库）相矛盾。

### 12.2 个人信息保护

适用：新加坡 PDPA；若面向境内用户，另适用《个人信息保护法》。

**风险点**：
- 课件本身可能含教师姓名工号、学生名单、成绩表
- 产品收集学习记录、风格配置、提问内容

**措施**：

| 措施 | 说明 |
| --- | --- |
| 隐私政策明示 | 收集什么、用途、存储在哪个国家、传给哪些第三方 API |
| 跨境传输披露 | 调用境外模型 API 即构成数据出境，必须明示 |
| 敏感信息检测 | 上传时扫描常见模式（证件号、学号成绩表），命中则提示用户并删去敏感信息。 |
| 导出与删除 | 两套法律的共同要求 |
| 未成年人 | 少数情况存在。不做个性化推荐，不收集非必要信息 |

### 12.3 第三方 API 的数据条款

核心问题：产品向用户承诺「不用于训练」，但上游服务商是否承诺尚待查证。

若上游条款与产品隐私政策冲突，则产品承诺构成虚假陈述。

**接入前必须查证的三项：**

1. 该服务商的开发者条款是否明确不将 API 输入用于训练（企业版通常承诺）
2. 数据保留期限
3. 数据存储地

结论需写入 §13.3 数据流向图，并与隐私政策逐条对齐。

#### ✅ 查证结果（2026-09-11）

**两个服务商，不是一个。** Anthropic 已在用（讲解生成 + F1 对照臂分类）；
OpenAI 是 F2 摄入接线要引入的第二个（embedding），**查证是它接入前的 gate**。

| | **Anthropic**（已接入） | **OpenAI**（待接入，embedding） |
| --- | --- | --- |
| **① 用于训练？** | **默认不用**。原文：「By default, we will not use your inputs or outputs from our commercial products (e.g. Claude for Work, Anthropic API, Claude Gov, etc.) to train our models.」 | **默认不用**。原文：「data sent to the OpenAI API is not used to train or improve OpenAI models (unless you explicitly opt in to share data with us).」 |
| **例外** | 用户**显式提交反馈**（👍/👎）时可用于训练，该反馈数据留存**至多 5 年** | 显式 opt-in 才用 |
| **② 保留期限** | ⚠️ **该页面未给出通用 API 的保留期限**，只写了反馈数据的 5 年。**如实登记为未查清**，不编一个数 | 滥用监控日志**至多 30 天**（除非法律要求更长）。`/v1/embeddings` **支持 Zero Data Retention**（需申请批准），开启后请求完成即不留存 |
| **③ 存储地** | ⚠️ 未在上述页面查到。**未查清** | 提供多区域数据驻留（含美国、欧盟、新加坡等）。⚠️ **关键差异：美国与欧盟支持「存储 + 处理」，其余多数区域（含新加坡）只支持存储**——所以即使选新加坡驻留，**处理仍在境外** |

**对本产品的三条推论：**

1. **Anthropic 的训练例外对我们不适用。** 产品里的四个反馈按钮（F05–F07）
   是**内部**的——它们改的是 `style_config` 那一行，**从不回传给模型服务商**。
   我们没有任何通路把用户内容作为「反馈」提交给 Anthropic。
2. **OpenAI 的 ZDR：决定不申请**（2026-09-11 拍板）。两条理由：

   - **ZDR 面向企业级客户与高合规场景**（HIPAA、金融），个人开发者申请通常不受理。
     把它列为待办，等于挂一个**永远不会完成的项**——而挂着的待办会让人以为
     「迟早会补上」，那比明写「不做」更糟（同 F25 对「待核 vs 通过但过期」的处置）。
   - **默认条款已经够**：API 输入默认不用于训练，30 天保留**仅用于滥用监测且到期自动清理**。
     课件讲解是普通教育场景，这段留存不构成实质风险。

   ⚠️ **重新评估的触发条件**（写具体，不写「以后」）：
   ① **数据类型改变**——例如用户上传的材料开始含个人信息（成绩单、名单）；
   ② **面向机构客户**——学校/企业采购通常自带合规要求。
   两者任一成立即重新评估，而不是等「想起来」。
3. **「应用服务器在新加坡」不等于「数据不出境」。** §13.3 原本只列了模型 API 一次出境；
   加上 embedding 是第二次，且新加坡区只存不算。**隐私政策要按两次出境改写。**

#### 🔴 两项未查清，且它**阻塞对外开放**

**Anthropic 的通用 API 保留期限**与**数据存储地**在上述页面查不到。

**存储在哪个国家**、传给哪些第三方」，而 Anthropic 是我们的主模型服务商——

- 服务条款写明：不对学习结果、考试成绩作任何保证

### 12.6 学术诚信

本产品定位为理解辅助，不代写作业、不代答考题，产品内不提供此类入口。

补充：产品内提示用户遵守所在学校的 AI 使用政策。各校规定差异极大，明确责任边界。

## 13. 埋点与数据回流

### 13.0 事件模型（第一批，2026-08-27）

**分批的原则与 §3.4 相同**：本批只定义**已经有数据流过**的四个事件——
它们的 schema 直接从配置扫描实验已落盘的 `rounds.jsonl` 反推，**不凭空写**。
一份从没有事件流过的 schema，和一个从没推导过的阈值，是同一类东西。

#### 通用字段（所有事件必带）

| 字段 | 说明 |
| --- | --- |
| `event_name` | 事件名 |
| `event_id` | uuid，幂等去重的键 |
| `event_ts` | **必须写明是客户端时间还是服务端时间**。混用会让「同一会话内的轮次顺序」在时钟偏移下静默错乱——它不会报错，只会让漏斗和留存偏移 |
| `user_id` | **对外导出时 hash；库内以真 uuid 存储**，受 RLS 保护并随账号注销级联删除（2026-09-10 改，理由见本节末） |
| `session_id` | 会话标识。⚠️ **切分规则尚未定义**，见 §3.4.5 |
| `course_id` / `deck_id` | 多课程是 v1 范围（§11.1），从第一天起就要能按课分组 |
| `app_version` / **`schema_version`** | 见下 |
| `client_type` | web / 其他 |

**`schema_version` 必须埋。** 口径一变，历史数据就不可与新数据合并，
而**没有版本字段就无法区分它们**——合并会得到一个看起来正常的错数。

> 这与本轮刚建的 `metric_set_id` 是同一个道理：配置扫描实验里，
> 五个配置点的指纹按设计各不相同，靠指纹挡不住跨指标集的误合并，
> 必须另有一个「指标集是不是同一个」的标识。埋点侧的对应物就是 `schema_version`。
> 见 `A类规则计算脚本/README.md` D47。

#### ⚠️ `user_id` 的口径改了：**hash 移到导出层**（2026-09-10）

本节原文要求事件表里存 hashed `user_id`。**F1 阶段 4 建 `style_events` 时改掉**，
现口径：

> **事件数据对外导出时 hash；库内以真 uuid 存储，受 RLS 保护并随账号注销级联删除。**

理由：本条原本的目的是**防止事件数据被关联到个人**，而 §12.1 的「注销即清空」是
一个**更强**的保障——数据都没了，hash 与否无所谓。而存 hash 会让事件表挂不上
`auth.users` 的外键，`on delete cascade` 随之失效：

| | 存 hash（原文） | 存真 uuid（现行） |
| --- | --- | --- |
| 事件能否关联到个人 | 要拿到 hash 函数与盐才行 | RLS 拦住（客户端**读不到任何事件**，只能写自己的） |
| 注销后事件还在不在 | **还在**（外键挂不上，cascade 失效） | **随账号一起删掉** |
| 对外导出时 | 已是 hash | **导出层 hash** |

**用一个弱保障换掉一个强保障，是净亏。** F1 的 F14 刚把「注销即清空」从一条
从未被测量过的承诺变成有断言的（删 `auth.users` 的行 → 配置行必须消失，
反向验证把外键改成 `no action` 让它变红），不能在事件表上把它丢掉。
事件表现在有同形的断言，见 `supabase/verify_rls_local.mjs` 的
「注销 · style_events 的 on delete cascade」与反向控制 R9。

配套的三件事都已落地，不是承诺：

1. **RLS**：`authenticated` 对 `style_events` **只有 insert**，且只能插 `user_id = auth.uid()`
   的行；没有 select / update / delete 的授权，也没有对应策略。读事件是分析行为，走 `service_role`。
2. **cascade**：外键 `on delete cascade`，本地反向验证两面都跑过。
3. **导出层 hash**：**对外导出数据时才 hash**。⚠️ 导出工具尚未实现——
   这一条目前是**待落地项**，不是已实现的保障。落地时按 F14 的形态配一条会红的断言
   （导出产物里出现真 uuid 即判红），否则它会是又一条只写在文档里的承诺。

记录：F1 口径 **F35**（`f1_samples/README.md` §一）· `docs/F1/F1进度.md` 未决项 #4 ·
迁移 `supabase/migrations/20260910140000_f1_style_events.sql` 文件头。

### 13.2 数据回流

用户反馈（"太啰嗦""例子没懂"）→ 更新个人风格配置 → 同时汇总为风格维度的整体分布，用于优化默认样例的设计。

这是产品的飞轮：用的人越多，初始样例越贴近真实需求分布，新用户找到合适风格的速度越快。

#### ⚠️ 冷启动：样本少时飞轮不能转（2026-08-27）

飞轮的前提是「风格维度的整体分布」可估。**用户数少时这个分布估不准**，
而基于它更新默认样例，会把前几个用户的偏好固化成全体新用户的起点——
**这是一个自我强化的偏差，且它不会报错**：默认样例看起来一直在「优化」。

处置：**回流更新默认样例前设一个最小样本量门槛，低于它不启用回流**，
只收集不生效。

**门槛数值：占位待定。**
确定路径：内测数据回流后，用 bootstrap 重采样看维度分布的估计方差随样本量的收敛点。
在此之前不填数——§3.2 的阈值来源规则同样适用于这里。

**个人配置的回流不受此限**：那是每个用户自己的数据更新自己的配置，
不存在分布估计问题。受限的只有「汇总为整体分布 → 改默认样例」这一条通路。

#### 三个数据侧的时间点（2026-08-27）

**埋点不能排在功能之后。** 埋点晚于功能上线，等于**第一批用户的数据全丢**——
而第一批用户恰好是最需要理解的那批（他们决定了 A3/A5/A6 能不能验证）。

| 里程碑 | 时间点 | 交付 | 为什么是这个位置 |
| --- | --- | --- | --- |
| **埋点上线** | **早于 v1 内测开放，与 F3 接线同批** | §13.0 的四个事件 + 通用字段落库 | 四个事件的 schema 已从 F3a 的 `rounds.jsonl` 反推出来，**不需要等前端**；等前端再做就会丢掉内测第一周 |
| **口径评审** | **内测第 1 周结束时** | §3.4.5 的四个占位口径定死：会话切分 / 周活跃 / 次周留存 / 护栏指标 | 它们的确定路径全部写的是「按真实分布定」，第 1 周正好是第一批分布可用的时刻。**再晚就会有人先用一个临时口径出了报表** |
| **AB 实验** | **F1 交付之后** | §8.6 的 A5 验证（样例选择 vs 文字描述） | A5 至今未验证，而它是 P1 的核心假设。**必须等 F1**——没有样例选择功能就没有实验组 |

三者的顺序不可换：没有埋点就没有分布，没有口径就没有可信的指标，
没有可信的指标就无法判读 AB 实验。

**v1 走多课程（2026-08-22 修正）**。原表写「单课程」，与 §11.1 直接冲突：
A4（每周有 3–4 门课件）**已验证**，而它正是「平时有足够使用动机」的依据；
若 v1 只支持一门课，产品在真实使用节奏里覆盖不到 3/4 的场景。
**用一个已验证假设去论证使用动机，同时又做一个与该假设冲突的范围决策，两者不能并存。**

多课程不是功能偏好，是 A4 的推论——其直接后果是术语表的分母只能来自自动提取，
进而导致术语处理维度在 v1 下线（§8.1）。这条决策链见 §11.1。

v1.1 那行相应改为「多课程**管理体验**」：多课程本身 v1 就有，
v1.1 补的是批量与归档这类体验，不是能力。

提升手段：v1 后的质量提升主要依靠 §13.2 的数据回流，而非更换模型。
