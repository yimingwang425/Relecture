## 〇、开工前必须先说的一件事

**判断二里那条规则通道（`skipped_pages` 与检索命中页的交集）恒为空集，永远不会触发。**

`image_only` 页**不产生切片**（slicer S01：切片单位是页，跳过的页不进索引），
所以它们**不可能出现在检索命中页里**。这一条 `retrieval/README.md` §四早就写过：

> `unreadable_page` 一行会带「← 上限 0（gold 页不产生切片）」的标注。
> 这不是修辞：其 gold 页是 `image_only`，不在索引里，`page-recall` 在结构上恒为 0。

实测确认（14.129，4 个 `image_only` 页恰好是 33–36，与两道 `unreadable_page` 题的
gold 完全重合）：

| 题 | gold 页 | 检索命中页（top-5） | 与 33–36 的交集 |
| --- | --- | --- | --- |
| Q029 | 33, 34, 36 | 21, 20, 24, **37**, 41 | **空** |
| Q030 | 35 | 21, 20, 16, 1, 3 | **空** |

**这是通则七第 5 例与第 6 例的合体**：一个看起来在做兜底的规则，
实际不防任何东西（#5）；而它依赖的信号在**需要它的那些页上根本不存在**（#6）——
因为那些页没有文本，这正是它们被跳过的原因。

我按纪律把它提出来，不是要推翻判断二的**意图**（第三类走规则、零模型成本，这是对的），
是它的**机制**要换。

### 替代机制：从「逐题判定」降为「『没提』分支的限定语」

**先说为什么逐题判定在 v1 做不到。** 要判断「用户问的是不是压在图里的内容」，
需要某种描述那些页内容的信号——而我们**恰恰没有**，那就是它们被跳过的原因。

试过的两条替代信号都不成立：

| 候选 | 结果 |
| --- | --- |
| 命中页与跳过页**邻接**（±1） | Q029 命中 p37（邻接 36）→ 会触发；**Q030 完全不邻接**（命中 21/20/16/1/3）→ 漏。2 题里对 1 题 |
| 命中跳过块前的**标题页** | 14.129 p32 正是「The Evolution of Ecosystems: The CAP Trilemma Extended」（57 字符，标题页），但**两题都没命中它**——中文提问与一个纯英文标题没有语义重合 |

**建议的机制**（口径 G03）：不做逐题判定，改为

> 当两分类判断结果为「**取到的片段不足以回答**」，
> **且该课件存在 `image_only` 页**时，把跳过页清单作为**限定语**一并注入讲解 prompt。

讲解 agent 于是能说出 §10.1 要的那句话：
「**课件正文里没有讲到，不过第 33–36 页的内容在图里，我读不了，可能在那部分**」。

- **仍然零模型成本**：只是一个「清单非空」的布尔判断，比交集更弱但**它真的会触发**
- **误差方向单向且可解释**：会在「课件真的没提、且恰好该课件有图页」时多说一句限定语。
  代价是用户多看一行；反方向（内容在图里却说课件没提）才是 §6.2 的核心风险
- **它与判断一一致**：标注形态、不做门。第三类本来就不该是一个独立分支——
  它是「没提」这句话的**精度修饰**

**规模上的已知限制**：14.129 的 4 个跳过页是**一个连续块**，
所以「清单非空」与「指出具体是哪一块」等价。若某课件有多处分散的跳过块，
这条限定语会把全部块都列出来，精度下降。当前语料无此形态，**登记不修**（口径 G04）。

## 一、三个问题

### Q1 · 两分类的 prompt，以及「没展开」与「检索没取到」怎么分

#### 结论：**不靠 prompt 区分——模型没有信息去区分它。靠事后归因分解。**

模型只看得到检索片。若检索漏了那一页，模型看到的就是「片段里没有」，
它**无法知道**那是课件没讲还是检索没取到。要求它区分，等于要求它报告
一个它观测不到的量——那是造假断言的配方（通则七 #1）。

处置分两层：

**第一层 · 把类别定义在「模型看得到的东西」上。**
两个类别都**不对课件整体下判断**：

| 类别 | 语义 | 刻意不写成 |
| --- | --- | --- |
| `insufficient` | **取到的片段不足以回答这个问题** | ~~课件没有讲~~ |
| `partial` | 片段提到了这个主题，但**没有回答所问的那一层** | ~~课件提了没展开~~ |

这不是文字游戏。`multipage` 最好只到 6/9（F2 §十二第 3 条），
让模型说「课件没讲」就是让它替检索背书。**说到自己看得见的范围为止。**

**第二层 · 错误归因在评测侧做，不在 prompt 里做。**
评测集有 gold 页，所以每一条判断错误都能分解：

```
判断错了
 ├─ gold 页在检索结果里 → 判断本身错（模型的责任，进校准指标）
 └─ gold 页不在检索结果里 → 检索漏了（retrieval 的责任，full-hit@5 已在测）
```

**这一步是本轮校准结果能不能读的关键**：不分解的话，一个检索问题会被记成
judge 不准，然后有人去调 prompt——**修一个不在那里的东西**。

#### prompt 形状（口径 G01）

- **系统提示固定**，不含课件与提问 → 会话内不变；但它很短，
  **预期低于最小可缓存长度**（同 F3a 的实测：406 < 1024），
  日志里如实报「未生效」而不是「未命中」
- **输入**：检索片原文（与讲解 agent 拿到的**同一份 ContextPack**）+ 提问
- **输出**：严格两选一 + **一句**理由（≤ 40 字）。
  用结构化输出约束取值域，取值不合法即判为无效样本，不做「就近解释」
- **不给它 `skipped_pages`**：那是规则通道的事（G03）。
  给了它就会开始猜「是不是在图里」，而它没有依据——**又一个假断言的入口**

#### 一个刻意不做的设计

**不让模型输出置信度。** 它会输出一个看起来可用的数，而那个数没有校准，
用它设阈值等于凭空造一个占位阈值（§3.2）。要分档就得先校准分档，
本轮不做（口径 G05）。

### Q3 · 总成本与工期

#### 延迟：这一跳加多少，能不能并行

**不能与检索并行**——它的输入就是检索结果。
**不能与生成并行**——它的输出要进生成的 prompt。**它是严格串行的一跳。**

能与它重叠的只有 prompt 组装这类本地动作（微秒级），**收益可忽略，不做**。

所以诚实的说法是：**这一跳只能压小，不能藏掉。**

| 手段 | 效果 |
| --- | --- |
| 用 `claude-haiku-4-5`（$1/$5） | 分层调用，PRD §7.3 本来就这么写的 |
| 输出极短（二选一 + ≤40 字理由） | 输出 token 是延迟主项 |
| 关 thinking | 事实判断，不需要 |

**预估 +1–2 s / 轮，须实测**。放进已经超标的预算里：

| | F3a 实测 | 加这一跳（预估） |
| --- | --- | --- |
| 完整讲解 P50 | 13.7 s | ~15 s |
| 完整讲解 P90 | **22.4 s** | **~24 s** |
| §9.2 要求 | < 15 s | 更超 |

**这一跳不是延迟超标的原因，也不是解法。** 超标的主项是生成本身，
真正的解法是流式（§9.2 方案 C，已记 TODO，等接前端）。
本轮把这一跳的实测值写进 §9.1 与 §9.2，**不假装它不存在，也不为它改架构**。

有一个能真正藏掉这一跳的做法——**投机并行**（生成与判断同时发，
判断说「够」就直接用，说「不够」才带着判断重生成）。
期望延迟从 `gap + gen` 降到 `max(gap, gen)`，代价是约 1/6 的轮次多一次生成。
**本轮不做**（口径 G07）：它把「每轮一跳」变成一个有分支的流程，
而本轮的验收标准（观察项「是否显式标注」）在两条分支上的语义不同。
记 TODO，触发条件：延迟成为上线阻塞项时。

#### 成本

单次判断：输入约 1,500 token（5 片 + 提问）、输出约 60 token。
按 haiku `$1/$5`：**≈ $0.0018 / 轮**。

| 对比 | 值 |
| --- | --- |
| F3a 实测单轮成本 | $0.0151 |
| 加这一跳 | **+12%** → 约 $0.0169 |
| 15 轮单会话 | $0.2971 → **约 $0.324** |

**它是每轮固定开销，不是异常路径**（§9.1 已写明这一点）。

#### 本轮总预算

| 项 | 量 | 成本 |
| --- | --- | --- |
| 校准：30 题 × **2 次**重复 | 60 次 haiku 调用 | ~$0.11 |
| 14.129 端点复现：P0/P3 × 2 组 × 1 轨 × 6 轮 | 24 次生成 + 24 次判断 | ~$0.47 |
| 22.081J 回归：P0 × 2 组 × 1 轨 × 6 轮（带判断，测延迟增量） | 12 次生成 + 12 次判断 | ~$0.20 |
| 嵌入 | 缓存全命中 | **$0** |
| 假跑 / sanity / 测试 | — | $0 |
| **合计** | | **≈ $0.80** |

**为什么重复 2 次而不是 1 次或 3 次**：1 次分不清「判错」与「这次抽到了另一个答案」；
3 次买不到「稳定 vs 摇摆」的区分（n=3 时 2/1 与 3/0 的差别不构成证据，R17）。
2 次给出的是**一个计数**——不一致的题数——而计数不需要 n=3 才可信。

## 三、验收：用现成的观察项，不建新机制

「超出课件范围是否显式标注」第 0 周就在记，F3a 也一直有
（`observation_out_of_scope_disclaimer` / `out_of_scope_disclaimer`）。
本轮把它从**观察项**升为**验收标准**（口径沿用，正则不动）。

**升级要写明一件事**：它此前的身份是「观察项，不进指标」，
现在进了验收——**同一个量换了身份，就不能再引用它此前的读数当基线**
（第 0 周 2/2、F3a 若干轮），因为那些读数是在「没有兜底判断」的条件下取的。
本轮的基线要在同一批次里由无判断组给出。

**而这个基线同时就是收益读数**（口径 G13）：

| | 无判断组 | 有判断组 |
| --- | --- | --- |
| 「超出课件范围显式标注」计数（n=12） | 基线 | 收益 |

方案原本只算了代价，没有对应的收益量。**校准准确率是自指的**——
它说明判断本身准，说明不了接进链路之后讲解变好了。
两组接近就说明这一跳换了个寂寞，**那个结论要敢写**。
