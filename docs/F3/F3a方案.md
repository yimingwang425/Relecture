## 一、先回答你的四个问题

### Q1 · `quote_length` 口径要不要升级

**建议：本轮不升级，改为先加一个 30 行的观察探针取证，下一轮再定。**

先把你问题里的两件事拆开，因为它们的答案相反：

| 问题 | 答案 |
| --- | --- |
| 弱口径（按引号猜）下的零触发能不能说明「引用没问题」？ | **不能** |
| 原因是不是「口径弱」？ | **不是。主要原因是没有触发机会** |

第 0 周那 15 轮里没有任何一轮要求模型引用原文。**一个从未获得触发机会的判据，
零触发说明不了任何事**——这正是通则七第 5 例的形态（「它在什么情况下会触发？
如果答案是几乎不会，它就不是约束」）。所以先造机会，再谈口径。

另外一个被低估的事实：第 0 周实验报告 §一 记的引用长度是 **0–86 字**，
上限是 100。**「几乎不触发」不等于「离得远」，只差 14 字。**
README 里那个「离 100 字上限很远」是单轨记录（4–74），全批次数据不支持它。

弱口径真正的盲区只有一个，但它很致命：**模型不加引号地整段照抄英文原文，
按引号猜的口径完全看不见**。而 v1 是英文课件 + 中文讲解，
一旦模型偷懒直接贴原文，形态恰好就是「不带引号的英文段落」。

所以本轮的做法是**用观察项换决策**：

> **句级 verbatim 探针**（实验侧观察量，不进达标判定）：
> 把讲解按 `text.split_sentences` 切句（这个函数 D14 里已实现、至今无使用者），
> 每句归一化后用 `str.find` 在**本轮 + 本轨迹历史轮的全部检索片原文**里查子串，
> 记录 `max_verbatim_sentence_chars` 与命中来源轮次。约 40 行，零新依赖。
>
> **比对范围含历史轮**（2026-08-22 评审修正）：历史检索片仍留在上下文里，
> 模型照抄的来源不限于本轮。只比本轮会**系统性低估，且低估方向不可见**——
> 一个漏掉照抄的探针，与「没有照抄」的输出长得一模一样。

读法预先登记：

- 探针显示存在长的**未加引号**照抄 → 弱口径确实漏了，升级有实测依据
- 探针恒小 → 弱口径下的零触发就有了解释力，升级可以不做

**这符合「不能让测量结果反向定义标准」的反面要求：先取证，再改口径，
而不是因为口径看起来弱就改。**

#### 真要升级，改动量估计

| 项 | 量 | 说明 |
| --- | --- | --- |
| 输入通道 | ~20 行 | 四个维度函数签名一致是 `a_rules` 的设计约束。加课件原文要么扩 `evaluate()` 的分发（已有 `term_annotation` 的特例分支作先例），要么走 config。**这是结构性改动，不是加个参数** |
| 算法 | ~120–150 行 | 朴素 DP 在方案 C 的句子级并行审查下不可接受。正确做法是对课件建后缀自动机（O(m) 一次），输出侧流式匹配 O(n)。零依赖可写 |
| 测试 | ~25–30 条 | 归一化失配、跨块引用、中英混排 |
| **新口径（比代码贵）** | **3 条** | ① 比对对象是**整份课件**还是**本轮检索片**（比检索片会漏掉模型引用未检索页；比全文需要把全文带到审查层——审查在服务端本地跑，全文本来就在库里，代价是 CPU 不是 token，**建议比全文**）② 匹配出的字符区间如何折算成 D04 的字数口径 ③ **多长的公共子串才算「引用」**——这是一个新的**占位待定**阈值，必须写确定路径 |
| 合计 | **~1–1.5 天** | 其中口径讨论占一半 |

第三条口径是我不建议现在做的主要原因：它会**新引入一个占位待定阈值**，
而本轮实验的产出正要用来消掉现有的占位项，不宜同时再加一个。

### Q2 · 配置扫描的点位

**结论：5 个点。3 点在详细程度轴 + 1 点在语言轴 + 1 个共享默认基点（基点即详细程度轴的一端）。
引用长度不作为自变量。**

#### 为什么引用长度不扫

`max_quote_chars = 100` 来自 PRD §12.1 的**版权约束，不是风格偏好**
（口径 D16 写得很清楚）。真实用户不会把它调到 40——把它当自变量扫，
测的是一个产品里不存在的配置。

它在本实验里的角色是**因变量**：靠提问诱发（见 §五 提问序列第 3 轮），
上限恒为 100。

#### 为什么详细程度占 3 个点

它是三维里**唯一在 F1 中被用户连续调节**的维度，「拐点在哪」这个问题
主要长在它身上。而语言一致性的可调空间只有阈值高低一维，且第 0 周实测
两组都在 0.91–1.00，取一个点问「提到接近满分会不会开始触发」就够了。

#### 点位

模型的自然行为（第 0 周实测，无审查组）：**平均段落 29–78 字**，中枢约 55。
偏离度就是按「自然值离区间边界还有多远」定义的：

| 点 | `paragraph_length` | `chinese_ratio.min` | 自然值(≈55)的位置 | 偏离度 |
| --- | --- | --- | --- | --- |
| **P0** | 30–120 | 0.85 | 区间中部，余量充足 | 0（默认，**与第 0 周同配置，可交叉引用**） |
| **P1** | 40–90 | 0.85 | 区间内，余量收窄 | 轻 |
| **P2** | 25–55 | 0.85 | **贴上界** | 中 |
| **P3** | 15–40 | 0.85 | **在区间外** | 强 |
| **P4** | 30–120 | **0.95** | — | 语言轴单点 |

P0–P3 是一条单调收紧的轴，P4 与 P0 只差一个字段。**不做全交叉**：
5 点 vs 全交叉 4×2=8 点，而全交叉多出来的格子回答的是「两个维度的交互」——
在 F1 还没给出真实配置分布之前，那个问题没有人问。

#### 只扫「偏短」不扫「偏长」

偏长（如 100–200 字）对 LLM 是**容易的方向**——让模型多写从来不难；
偏短与模型的天然啰嗦相反，也正是 PRD §2 的 P1 痛点方向。
**先扫会咬人的一侧。**（记入「先不做」，触发条件见 §七）

#### ⚠️ P3 的达标可以靠分段实现，而指标看不见（【评审指定】2026-08-22 补）

`paragraph_length` 量的是**平均**段落字数。P3 是 15–40 字/段，
模型满足它有两条路：真的讲简洁（800 → 300 字），
或者**多敲回车**——同样 800 字切成 25 段、每段 32 字，**稳过判定**。
选了「很简洁」的用户想要的是前者，拿到的是后者。

它同时污染本轮的两个读数：

| 读数 | 会被污染成什么 |
| --- | --- |
| 触发率近零 | 读成「模型能遵守偏离常态的指令」，实际是「指令可被平凡地绕过」 |
| 审查有没有用 | 读成「审查在 P3 也不触发，没用」，实际是**审查也看不见这个失败** |

**这是通则五的形态，与 D44 同源**——D44 错在太严（逼模型变啰嗦），
这次错在漏（放过一个用户不想要的行为）。共同点：**输出看起来完全正常。**

**本轮处理**：两个观察项，不进达标判定——`total_chars` · `paragraph_count`。
判读规则见口径 **E10**，跑之前定死。

**顺带定位到的 PRD/代码缺口（记 TODO，本轮不修）**：
PRD §8.1「详细程度」的计算方式写的是「平均段落字数、**总输出长度**」两项，
而 `a_rules` 只实现了前一项——**总输出长度从来没有代码**。
按「未实现的维度不参与达标判定」的纪律，本轮不补判定；
但缺口从哪来必须写清楚，否则下次又会有人把它数进「已实现」。

### Q3 · 总运行次数、成本、以及噪声压得住到什么程度

#### 运行量（分阶段，停止规则预先登记）

| 阶段 | 内容 | 计划生成数 | 预估 |
| --- | --- | --- | --- |
| 0 | `--fake` 全链路 + sanity | 0 | $0 |
| 1 | 5 点 × 2 组 × **1 轨** × 6 轮 ＋ 成本臂（P0 × 2 组 × 1 轨 × **15 轮**） | 60 + 30 = **90** | **≈ $1.65** |
| 2 | 补第 **2 轨**（扫描臂） | +60 | ≈ $1.10 |
| 3 | **仅对落进「不可分辨带」的点**补第 3 轨 | +0…36 | $0…0.65 |
| 3b | **条件触发**：若阶段 2 显示 P3 触发率明显高于 P0 → 补 P3 成本臂（P3 × 2 组 × 1 轨 × 15 轮） | +0 或 30 | $0 或 0.55 |
| 4 | **可选**：跨学科端点复现（14.129，P0/P3 各 1 轨 6 轮） | +0 或 24 | $0 或 0.43 |
| | **合计（典型：阶段 1+2）** | **150** | **≈ $2.75** |
| | 合计（含 3b + 4） | ~204 | ≈ $3.73 |
| | 合计（最坏：全部补第 3 轨 + 高触发率） | ~230 | ≈ $4.2 |

对照第 0 周：**137 次生成 / $2.4614**。典型路径 150 次 / ~$2.75，持平。

单次生成成本估算 ≈ **$0.018**（用第 0 周实测反推：$2.4614/137 = $0.01797，
输出占 68% → 输出约 1220 token）。新链路两个方向相反的变化大致抵消：
system 从 5K token 的全量课件降到 ~350 token（缓存写入成本大降），
但每轮新增 ~400 token 的检索片且**它天然无法缓存**（每轮不同）。

**上限不确定的部分是重生成**，而它正是被测量。所以预算写成区间，
并且**阶段 1 结束就能知道触发率量级**——如果它接近零（§9.1 补记预测的方向），
阶段 2 之后就可以停，总花费落在 $2.5 附近。

#### 噪声压得住到什么程度（诚实版）

| 想回答的问题 | 本量级能不能答 | 依据 |
| --- | --- | --- |
| 「触发率是不是**近零**」（全局） | **能** | 阶段 2 后全部点合计 60 个有审查轮次；若事件总数 ≤2，95% 上界 ≈ 6%，足以推翻 §9.1 的 62% 画像 |
| 「某个配置点的触发率**是高还是低**」 | **勉强能，靠跨轨同向重复** | 单点 n=12，观测 1 次事件与观测 6 次事件的 95% CI 分别约 [0.2%, 34%] 与 [21%, 79%]——**两者是重叠的**。单点数字不构成证据，构成证据的是 R17 的纪律：同一方向在 2–3 条独立轨迹上重复出现 |
| 「触发率**是多少**」（数值） | **不能** | n=12 时 ±25pp。要压到 ±10pp 需每点 n≈100，5 个点约 1000 次生成 ≈ $18 |
| 「拐点**在哪一档**」 | 能定位到档，不能定位到阈值 | 只能说「P2 与 P3 之间开始出现」，不能说「区间宽度小于 X 时开始」 |
| 「成本是多少」 | **能，且比触发率可信得多** | token 是确定量，方差只来自输出长度。成本臂是 15 轮实测，不外推 |

**预先登记的判读带**（n=12/点，写在 README 里，跑之前定死）：

- 触发事件 **≤ 1/12** → 判「近零」
- 触发事件 **≥ 6/12** → 判「高」
- **中间一律判「本实验不可分辨」**，不做解读，只决定要不要补第 3 轨

登记它的原因和 R17 一样：**事后挑一个看起来合适的判据，等于没有判据。**

### Q4 · `evaluator` 三维化的最小改动 + 指纹隔离

我把代码读了一遍确认过，**改动比预想的小，因为激活机制早就是集中的**（D22）。

#### 需要改的（约 15 行生产代码）

| 文件 | 改动 |
| --- | --- |
| `a_rules/config.py` | ① 新增字段 `term_annotation_enabled: bool = False`（**默认关**）② 登记进 `_FIELDS` / `from_dict` / `to_dict` / `__post_init__` 类型校验 ③ `activates_term_policy` 改为 `self.is_bilingual and self.term_annotation_enabled` ④ `CONFIG_VERSION` → **`"2.0"`** |

#### 零改动（已逐个核对）

| 文件 | 为什么不用改 |
| --- | --- |
| `a_rules/evaluator.py` | `scored` 已过滤 `counts_toward_score`，`all_activated_passed` 只看 `scored`。术语维度返回 `not_activated` 后自动出局，且 `details` 仍写入日志（可作观察项） |
| `drift/reviewer.py` | `failed` 只遍历 `ev.scored`，反馈不会再提术语 |
| `drift/aggregate.py` | `aggregate()` 里已有 `if d is None or not d.get("activated"): continue` |
| `metrics/*.py` | 术语模块自己在 `term_annotation.py:222` 查激活，直接返回 `not_activated` |

#### 需要改的测试（约 8 行）

`tests/test_term_annotation.py` 有 60 处引用，但它们共用一个 `cfg()` helper
（第 29 行），加一行 `kw.setdefault("term_annotation_enabled", True)` 即可；
另有 4 处直接构造 `StyleConfig(`，`test_config.py:93`、`test_evaluator.py`、
`test_glossary.py` 各 1 处。**447 条测试的其余部分不动。**

#### 指纹隔离——这里有一个坑

新指纹会自动变（新字段 + 版本号都进 `to_dict()`）。但**「指纹不同」不是守卫，
只是一个不同的字符串**。而且本实验里有个新情况：

> **配置指纹按设计逐点不同**（5 个点 5 个指纹）。
> 所以 `drift/verify.py` 那条「本批次指纹 == 当前配置指纹」的检查**在本实验里失效了**——
> 它会被 5 个合法的不同指纹撑破。

所以守卫要分三层：

| 层 | 检查 | 失败时 |
| --- | --- | --- |
| **点内** | 同一配置点的所有轮次，指纹必须唯一 | 退出 1（说明这批数据不是用你以为的配置跑的） |
| **点间** | 全部点的 `metric_set_id` 必须一致 | 退出 1，**不得画进同一张图** |
| **批次间** | `metric_set_id` 与历史批次不同即拒绝合并；`CONFIG_VERSION != "2.0"` 的批次直接拒读 | 退出 1 |

`metric_set_id` = `sha256(CONFIG_VERSION + 排序后的计分维度名列表)[:12]`。
它与指纹的分工：**指纹管「阈值有没有被改」，`metric_set_id` 管「指标集是不是同一个」**。
配置扫描要求前者按点变化、后者全程恒定——一个数管不了两件事。

**反向验证**（通则七 #4 的硬要求）：加一条测试，把 `term_annotation_enabled`
改回 `True` 后 `metric_set_id` 必须变化、合并检查必须变红。不会红的守卫是空转的守卫。

#### ⚠️ 一处连带影响，需要你拍板（【提出·待确认】）

术语维度下线**不只是「不计分」**，它还悄悄改了 `chinese_ratio` 的分母。

`chinese_ratio` 的 D15 排除（把「热机（heat engine）」括注里的英文从分母里剔掉）
是靠 `annotated_english_spans(doc, glossary)` 实现的，而该函数
**`glossary is None` 时直接返回空**（`term_annotation.py:92`）。
v1 走多课程、没有可用术语表 → **括注英文会重新计入分母，`chinese_ratio` 变严**。

量级：一段讲解多 10 个未排除的英文词，占比从 ~0.97 掉到 ~0.94。
在 0.85 阈值下无所谓——**但 P4 点的阈值是 0.95，它正好落在会翻转的位置上。**

三个选项：

| 选项 | 改动 | 代价 |
| --- | --- | --- |
| A | 实验里传入 22.081J v1.1 术语表，仅用于识别括注 | 零代码，与第 0 周口径一致 |
| **B（已定）** | 新增**不依赖术语表**的形态规则：识别「汉字＋（ASCII 英文）」括注并排除 | ~30 行 + 测试。忠于 D15 的立意，且生产迟早要做 |
| C | 什么都不做，接受 `chinese_ratio` 变严 | 零成本，但 P4 的结论混入一个与配置无关的系统性偏移 |

#### 决定：做 B，A 降为一次性交叉校验（【评审指定】2026-08-22）

**我原先建议的 A 是通则七第 6 例的形态——观测范围与应用范围错配。**
A 能成立是因为 22.081J 恰好有一份人工整理的术语表；
而 **v1 生产走多课程，没有术语表**。用一个生产不具备的条件，
去测生产会遇到的阈值：A 测出的 P4 触发率是**生产的下界，差多少不知道**。

处置：

| | 做法 |
| --- | --- |
| 实验路径 | **走 B**（形态规则） |
| A 的用途 | **只做一次离线比对，不进路径**：在 22.081J 上把「术语表识别」与「形态规则识别」的结果求差集，差集即形态规则的误差。零 API 成本，且参照物**没有参与 B 的设计**——这是真正的外部验证，不是自洽检查（通则七 #3） |
| 比对结果 | 写进 `explain/README.md` |
| 退路 | 若比对显示 B 的误差大到会翻转 P4 的判定 → 退回 A，并把错配作为限制写进报告 |

**B 的已知误收面**（口径 X12，登记不修）：`（见 p12）`、`（Figure 3）`
这类非术语括注也会被排除，方向是**抬高** `chinese_ratio`（更宽松）。
误差方向已知且单向，可解释。

### 3.1 prompt caching——有一个会静默失效的坑

第 0 周能缓存是因为 system 里塞了 5K token 的课件全文。
**接了检索之后 system 只剩风格片段 + 课件清单，约 350 token，
低于 Sonnet 的最小可缓存长度（1024 token）——缓存断点会静默不生效，不报错。**

这是「会静默改变数字的问题」（通则六），处理如下：

| 断点 | 位置 | 说明 |
| --- | --- | --- |
| ① | system 段末尾 | **实测其 token 数并写进 metadata**；若低于最小可缓存长度，报告里写「**未生效**」而不是「未命中」——这两句话的含义完全不同 |
| ② | 最近一轮消息末尾 | 沿用 `cache_conversation`。**对话历史才是本链路真正值得缓存的东西**——它逐轮增长，且包含前几轮的检索片 |

**本轮检索片天然无法缓存**（每轮不同）。这不是缺陷，是检索的固有形态，
如实记入成本归因即可——它也印证 §9.1「输出占 68%，检索只作用于输入侧」。

#### 再往上一层：§7.3 的论断在新架构下可能不成立（【评审指定】2026-08-22）

PRD §7.3 写「**课件内容会话内不变 → 必须启用 prompt caching**」。
**这句话的前提是课件全文在 system 里——那是第 0 周的架构。**
接检索之后课件全文根本不在上下文里，检索片每轮不同天然不可缓存，
唯一值得缓存的只剩对话历史。**前提没了，论断也就悬空了。**

本轮**不改 PRD**（等实测），但报告里必须单独回答一句：
**接检索后 caching 还剩多少收益。**

若答案是「扫描臂 6 轮里基本没生效」，则 §7.3 要改，
且这大概率是**第 5 次「被数据推翻的判断」**——前四次推翻的是对课件 / 模型 /
成本 / 自己判据的假设，**这次推翻的是架构假设**，形态与前四次都不同。
成立则按 `F2开发.md` §八 的既有体例记进那张表。

### 3.2 风格配置参数化注入（F1 的接口形状）

`style_prompt.render(config) -> str`，**只渲染激活的维度**：

| 配置字段 | 渲染 |
| --- | --- |
| `paragraph_length` | 「每段控制在 {min}–{max} 字」 |
| `max_quote_chars` | 「引用课件原文时单段不超过 {n} 字」 |
| `chinese_ratio`（激活时） | 按阈值分档渲染强度，阈值本身不直接暴露给模型 |
| `term_*` | **v1 不渲染**（维度已下线，prompt 里也不该再要求它——否则模型花 token 做一件不计分的事） |

**配置同时驱动 prompt 与判定，两侧同步**（口径 X05）。
这一条必须写清楚，否则实验会被误读：如果只收紧判定而不改 prompt，
触发率上升是**平凡结论**（判据变严了当然更容易违规）。同步变化测的才是
真问题——**模型能不能遵守一个偏离常态的指令**。

### 3.3 检索片不完整——prompt 怎么写

F2 §12 第 3 条：`multipage` 最好只到 6/9，**缺的部分不带任何标记**。
所以讲解 prompt 里必须有一句立场明确的话：

> 你看到的是课件的**若干片段**，不是全文。片段可能不含回答该问题所需的全部内容。
> 若片段不足以回答，**说出缺什么**，不要用通用知识补全后当作课件内容讲。

**本轮不写兜底文案**（那是 F3b），但这句约束现在就得有——
否则实验测到的「达标」里会混进一批「编得很流畅所以规则查不出问题」的输出。

### 3.4 `skipped_pages` / `unusable_pages` 一路传到检索层

`SliceManifest.skipped_pages` 已有完整结构（`index` / `kind` / `reason` /
`image_count` / `image_coverage_union`）。通道：

```
SliceSet.manifest.skipped_pages ──► ContextPack.skipped_pages
                                     ├─► system 的「已知读不了的页」清单（仅事实，不含文案）
                                     ├─► RoundLog.context.skipped_pages_in_scope
                                     └─► GapChecker 入参（F3b 用）
```

本轮的验收标准只有一条：**通道通、日志里有、F3b 拿得到**。不写文案。

### 4.1 为什么这次可以含检索，而第 0 周不行

第 0 周排除检索的理由是「两组可能取到不同片段，连输入都不一样，对照就废了」。

本轮的检索 query = **本轮提问原文**，不含对话历史改写（口径 X01，
依据 PRD §7.5「检索意图单一，不需要多跳推理」）。因此：

> **检索结果只取决于提问，与配置点、与条件、与对话历史全部无关。**
> 每轮只检索一次，两组共用同一份 `ContextPack`。

这从结构上消掉了当年那个风险，而不是靠约定。sanity check 加一条：
**同一 (点, 轮) 下两组的 `retrieval_signature` 必须逐字节相同**。

### 4.3 成本臂

P0（默认配置）× 2 组 × 1 轨 × **15 轮**，提问用**第 0 周的原序列**
（`漂移实验/config/questions.json`）。

这样单会话成本是**实测**而非外推，且可与 $0.590 / $0.231 直接并列。
差额由两个原因共同造成（四维→三维、全量课件→检索），
**日志里可以分开归因**：检索的影响看 input token，维度的影响看重生成次数。

它与扫描臂在**同一次运行、同一份 JSONL** 里——【评审指定】判断二的要求。

### 4.4 停止规则（预先登记）

- 阶段 1（1 轨）跑完 → `verify_scan` 通过 → 看触发率量级
- 阶段 2（2 轨）跑完 → 按 **E05 主判据（单调性）** 判读，判读带只用来定位拐点
- **只有落进「不可分辨带」的点才补第 3 轨**
- 若阶段 2 后全部点都在「近零」带且无单调上升 → **停，结论就是「v1 三维下审查几乎不触发」**
- **条件项（不必再确认）**：若阶段 2 显示 **P3 触发率明显高于 P0**
  → **补一条 P3 成本臂**（P3 × 2 组 × 1 轨 × 15 轮，≈ $0.55）。
  理由：最严配置下的会话成本，才是「F1 该不该把这一档开放给用户」的依据

### 4.5 阶段 4（可选）· 跨学科端点复现

整个扫描跑在 22.081J 一份课件上，而**通则三**说判据的脆弱性是学科相关的，
v1 又走多课程。最便宜的兜法：

> **只在 P0 与 P3 两个端点**，用 **14.129**（区块链金融，已有 gold 页）
> 各跑 1 轨 6 轮 = **24 次生成 ≈ $0.43**，看端点对比是否跨学科复现。

不补完整的第二条轴，**只验端点**。主要成本是给 14.129 编一套 6 题序列。
