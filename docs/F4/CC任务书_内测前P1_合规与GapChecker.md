## 第一件 · `restricted_pages_excluded` 改为 `null`

### 背景（决定已拍板，不要重新论证）

用户上传的课件**不做受限页排除**，v1 立场已定：我们无从判断用户 PDF 里哪几页是第三方保留权利内容，责任写进使用条款。`RESTRICTED_PAGES` 是按测试集文件名硬编码的，与用户上传无关。

所以这个字段**没有数据源可补**，补护栏无从补起。处置是让它停止产生假证据。

### 做什么

1. **写入侧**：`/upload` 成功时该字段写 **`null`**，不写 0。`null` 的语义正是「没有检查过」。
2. **必需清单**：把它从 `f1_event_required_keys('deck_uploaded')` 里**移除**——这正是 F50 那条口径的适用情形（null 有含义的字段不进必需清单，否则 `f1_event_payload_ok` 会把一条完全正确的事件判成缺字段，而被拒的事件是静默消失的）。
3. **schema_version** 抬到 `f1-events-5`。payload 口径变了，版本号跟着走。
4. **存量不回填**：现有 `deck_uploaded` 行里的 0 全是验收数据，随清理一起删。在迁移注释里写明这一点，并写明**清理之前这些 0 不可读作「没有受限页」**。
5. 迁移注释里写死这个字段的含义：**`null` = 未检查（v1 的既定状态）**；将来若真做了排除机制，才可能出现整数。

### 守卫

| 守卫 | 反向验证 |
| --- | --- |
| `/upload` 成功后该字段是 `null` | 改回写 0 → 必须红 |
| 该字段不在必需清单里 | 加回清单 → 一条 `null` 的正常事件被拒 → 必须红 |
| `deck_uploaded` 其余必需字段照旧 | 去掉任一 → 必须红 |

⚠️ **既有的那几条测试要跟着改**：`test_upload_events.py` 断言「传 0 得 0」、`verify_rls_local.mjs` 断言「0 可以写入」。它们现在钉的是要被推翻的行为。改完要说明改了哪几条、为什么。

⚠️ `test_ingest.py` 那条（给 `ingest_document` 传 `restricted_pages` 则真的排除）**保留不动**——它测的是函数本身，函数没坏，坏的是没人给它传参。

## 第二件 · GapChecker 接进生产

### 先查三件事，查完再动手

1. **`ModelGapChecker` 现在住在 `实验脚本/配置扫描实验/scan/live.py`，生产不 import 它。** 它该搬到哪里？约束：**不许在 `api/` 下重抄一份实现**，实验侧和生产侧必须用同一份。给出你的方案再动手。
2. **G03a 的规则通道要 `skipped_pages`。** 生产链路上，某门课的跳过页清单**存在数据库里吗**？`deck_uploaded` 事件里有，但事件表是埋点不是状态——`/explain` 读不读得到？读不到的话这条通道在生产上做不了，**如实说，不要现编一个来源**。
3. **`explain_turn` 的 payload 里有没有 `gap_verdict` / `gap_cost_usd` / `gap_latency_ms`？** G08 要求判断的成本与延迟单独记账但计入单轮。缺哪个补哪个。

### 做什么

在 `/explain` 里把真实的 GapChecker 传进 `run_round`，替换默认的 `NullGapChecker`。

**不加开关**（口径见下）。理由：F3b 的实测数之所以会被误读成「生产已验证」，正是因为实验和生产两条路径分叉，而没有任何东西在核对「线上到底接没接」。再加一个开关就是再造一个这样的问题。要停用就 revert。

**模型用 `claude-haiku-4-5`**，输出严格两选一 + ≤40 字理由，关 thinking（G01）。**不给它 `skipped_pages`**（G01 末条）——给了它会开始猜「是不是在图里」，而它没有依据。

**G03a 限定语**（若第 2 条查得通）：判断为**非 `covered`** 且该课件跳过页非空 → 把跳过页清单作为限定语注入讲解 prompt。注意门槛是「非 `covered`」不是 `insufficient`——F3b §2.2 的校准显示建在 `insufficient` 上会 2 题漏 1 题。

### 守卫

| 守卫 | 反向验证 |
| --- | --- |
| 生产链路真的调了模型判断 | 换回 `NullGapChecker` → `gap_verdict` 恒 null → 必须红 |
| **限定语不是恒触发** | 造一条 `covered` 或跳过页为空的数据 → **必须不注入**；把条件换成恒真 → 必须红 |
| 成本与延迟真的被记账 | `gap_cost_usd` 置 0 → 必须红 |
| 判断失败不打断主链路 | 让判断抛异常 → 讲解仍然返回，`gap_verdict` 为 null 并带失败原因 |

**第二条最关键**，形态与 F4 的注入守卫完全一样：一个恒触发的限定语，输出看起来完全正常，只是每轮都多说一行——最难发现的那种。

### 明确不做

- **不测这一跳的收益**（G13 延续）。F3b 那次 2/12 vs 1/12 是在一个**零事故样本**上测的——该防的错误一次都没发生。内测才是产生实例的地方。
- 不做投机并行（G07）、不做置信度分档（G05）。
- 不为它调延迟架构。P90 22.4 s 的主项是生成本身，1.4 s 不是原因也不是解法。
