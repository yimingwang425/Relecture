## 一、结论

### 第 0 周「两组曲线基本重合」的结论被局部推翻了

第 0 周在 v1 的三个维度上「两组曲线基本重合、全程达标」，据此无法判断审查 agent
有没有价值。本实验给出的答案是：

> **审查 agent 的价值随配置偏离默认的程度出现，不是全有全无。
> 第 0 周测不出来，是因为它只测了一个点。**

| | 有审查达标率 | 无审查达标率 |
| --- | --- | --- |
| **P0（默认 30–120 字）** | 1.000 | **1.000** ← 第 0 周的结论在这里复现 |
| P1（40–90） | 1.000 | 0.667 |
| P2（25–55） | 1.000 | 0.667 |
| **P3（15–40，最严）** | 1.000 | **0.417** ← 两组分开 |
| P4（语言 ≥0.95） | 0.917 | 0.750 |

**P0 复现了第 0 周，P3 分开了。** 同一个实验里两件事同时成立——这正是「只测一个点」
会漏掉的形态：那个点恰好是两组重合的点。

### 主判据成立

预先登记的主判据（E05）：**触发率沿 P0→P1→P2→P3 单调不减，且 ≥2 条轨迹同向。**

```
轨 1: [0.000, 0.333, 0.333, 0.500]
轨 2: [0.000, 0.333, 0.333, 0.500]
```

两条独立轨迹**逐点完全重合**。按 R17（差异须在多个独立条件下同向重复）构成证据。

### 三个配套数字

| 项 | 值 |
| --- | --- |
| **拐点** | **P0 与 P1 之间**。默认档触发率 0.000（近零带），稍一收紧即跳到 0.333 |
| **P3 上的收益** | 达标率 **0.417 → 1.000** |
| **触顶失败** | **1 / 180**（第 0 周：13/45） |

触发归因：`paragraph_length` 29 次、`chinese_ratio` 4 次。

### 事后观察（不作证据）

`触发率` 与 `1 − 无审查达标率` 测的是同一个量的两侧，两者在 5 个点上同向：

| | P0 | P1 | P2 | P3 | P4 |
| --- | --- | --- | --- | --- | --- |
| 有审查触发率 | 0.000 | 0.333 | 0.333 | 0.500 | 0.333 |
| 1 − 无审查达标率 | 0.000 | 0.333 | 0.333 | 0.583 | 0.250 |

聚合层面很接近，**但逐轨并不相等**（如 P1 轨 1 为 0.333 vs 0.167，轨 2 为 0.333 vs 0.500）——
两组是独立采样，n=6/格时逐格偏差本就该有。

**这条没有预先登记，不进主判据。** 记它是因为它是本实验设计的附带交叉验证：
两个由不同代码路径算出的量指向同一件事。**登记在后的观察不能反过来当证据**——
否则任何一次实验都能事后找出若干「互相印证」的量。

## 二、成本

### 两条成本臂（15 轮真实序列，实测不外推）

| | P0（默认） | P3（最严） |
| --- | --- | --- |
| 有审查 · 单会话 | **$0.2971** | **$0.3245** |
| 无审查 · 单会话 | $0.2616 | $0.2201 |
| 触发 / 15 轮 | **0 / 15** | **8 / 15** |
| 重生成次数 | 0 | 9 |
| 最终达标 | 15/15 | 15/15（无审查 14/15） |
| 平均输出字数 | 783 | 502 |

**对 F1 的答案：P3 这一档可以开放给用户。**
最严配置下的单会话成本 $0.3245，比默认档只贵 **1.09×**。
即使触发率 53%，成本几乎没涨——因为 P3 的输出本来就短（502 vs 783 字），
重生成重写的是短文本。

**P3 内部有/无审查是 1.47×，这个数有 9 次重生成撑着，可以报。**
**P0 的 1.14× 不可区分于零**：0 次触发、n=1 轨，倍数全部来自两组输出长度的随机差异。

### 与第 0 周并列（不覆盖）

| | 本轮（v1 三维 + 检索） | 第 0 周（四维 + 全量课件） |
| --- | --- | --- |

## 三、prompt caching：PRD §7.3 的论断前提不成立

**system 段实测 485 字符 / 约 406 token，最小可缓存 prefix 是 1024 token。
断点不生效，且不报错。**

| | 第 0 周 | 本轮 |
| --- | --- | --- |
| 课件全文 | 在 system 里（约 5K token） | **不在上下文里** |
| system 段 | 约 5K token，断点生效 | **406 token，断点不生效** |
| 每轮检索片 | 无 | 约 400 token，**每轮不同，天然不可缓存** |
| 实际被缓存的 | system + 对话历史 | **只剩对话历史** |

对话历史的缓存工作良好：**第 2 轮起 78/78 命中**，读取 1,188–27,228 token。
所以 caching 仍然在省钱，但**省的是历史，不是课件**——
§7.3 写的「课件内容会话内不变 → 必须启用 prompt caching」，
其前提（课件全文在 system 里）在接检索后已经不成立。

**这一条是本实验唯一一个「不需要跑实验就能知道」的结论**：406 与 1024 是两个确定量，
sanity check 就够了。详见 `F2开发.md` §八「被数据推翻的判断」第 5 次。

## 四、E10 · 分段规避：判为「确实简洁」，但主要机制是分段

`paragraph_length` 量的是**平均**段落字数，模型满足偏短配置有两条路：
真的讲简洁，或者**多敲回车**。E10 的三分类判为「确实讲得更简洁」
（总字数比 0.78，超出 ±15% 的「基本不变」区间）。

**但那是阈值技术性的结果。** 按被测量自身的定义式分解
（`字/段 = 总字数 ÷ 段数`，两边取对数后变化量恰好可加，**无阈值、无自由参数**）：

```
P0: 字/段 1.000× = 总字数 1.000× ÷ 段数 1.000×（基点）
P1: 字/段 0.927× = 总字数 0.939× ÷ 段数 1.013×  → 真的讲短 83% / 分段 17%
P2: 字/段 0.606× = 总字数 0.834× ÷ 段数 1.377×  → 真的讲短 36% / 分段 64%
P3: 字/段 0.420× = 总字数 0.785× ÷ 段数 1.870×  → 真的讲短 28% / 分段 72%
```

**机制随偏离程度切换**：轻度收紧时模型是真的压缩（83%），
收得越紧越转向分段（P3 上 72% 来自分段）。

成本臂（15 轮真实序列，P3 相对 P0）的同一算式是 **真的讲短 51% / 分段 49%**——
构造过的扫描臂把分段比例推高了。**两个数要分开报**，同口径 E07a。

**产品含义**：选了「很简洁」的用户想要的是前者，在最严档拿到的主要是后者，
而**审查看不见这个失败**。根因是 PRD §8.1 的「详细程度 = 平均段落字数、**总输出长度**」
只实现了前一半——`a_rules` 里没有总输出长度的代码。按「未实现的维度不参与达标判定」
本轮不补判定，缺口补进 **v1.1** 待办。

（阶段 1 单轨时这张表是三点恒定 75/25，且 P1 出现「总字数反而上升」。
补轨后两者都消失——**那是 n=1 的假象**，也说明单轨读数有多不可靠。）

## 五、必须写明的限制

### 1 · 单课程，跨学科未验证

全部结论测自 **22.081J lec01b 一份课件**。通则三：判据的脆弱性是学科相关的，
只用一个样本验证必然过拟合。而 v1 走多课程。

方案里的阶段 4（14.129 端点复现，P0/P3 各 1 轨 6 轮 ≈ $0.43）**未做**，
记 TODO，触发条件「有第二门课的完整跑批预算时」。
注意它与 G2 那次跨学科验证的差别：**那次验的是判据，这次要验的是结论。**

### 2 · P4 口径敏感，三口径并列

括注排除有三种口径。在 0.95 阈值上（n=180，用本批次 transcripts 重算）：

| 口径 | 均值 | 最低 | 不达标 |
| --- | --- | --- | --- |
| 无排除 | 0.9423 | 0.8193 | **85** |
| 仅术语表（选项 A） | 0.9454 | 0.8193 | **76** |
| **形态规则（选项 B，采用）** | 0.9525 | 0.8193 | **59** |

括注密度：每轮平均 2.73 处，180 轮里 114 轮有括注——
**v1 的 prompt 并不要求写括注，模型仍然自发在写**。

采用的 B 是三者中最宽松的，**所以 P4 的触发率 0.333 里有一部分是口径给的**。
这不是退回 A 的理由（A 靠这门课恰好有人工术语表，v1 多课程没有，是观测/应用范围错配），
而是三个数必须并列报的理由。

**第 0 周那六份样本上的同类对比不作为本结论的依据**——那批测自
`term_annotation` 激活、prompt 明确要求写括注的配置。

### 3 · 扫描臂是构造序列，触发率是压力上界

扫描臂第 3 轮刻意诱发引用、第 5/6 轮刻意压长度。
**真实使用率只能从成本臂出：P0 = 0/15，P3 = 8/15。**

### 4 · 两个倍数的强度不同

- **P0 的 1.14× 不可区分于零**：0 次触发、n=1 轨，全部来自输出长度的随机差异
- **P3 的 1.47× 可以报**：有 9 次重生成撑着

### 5 · 首字延迟无数据

不流式，`latency_ms` 是完整响应时间。PRD §9.2 的「首字 < 3s」**本轮测不了**，
日志字段 `first_token_latency_ms` 恒为 `null`——不塞一个没测过的数。

### 6 · 样本量：能答什么、不能答什么

| 问题 | 能不能答 | 依据 |
| --- | --- | --- |
| 触发率是不是近零（默认档） | **能** | 成本臂 15 轮 + 扫描臂 12 轮，事件数 0 |
| 收益是否随偏离程度上升 | **能**（主判据） | 两轨逐点同向重复（R17） |
| 某点触发率**是多少** | **不能** | n=12 时 95% CI 宽达 ±25pp |
| 拐点的精确位置 | **只能到档** | 「P0 与 P1 之间」，不能说「区间宽度小于 X 时」 |

**第 3 轨未补**：它只买拐点精度，而主判据已成立、F1 的问题已有答案。

### 7 · 其他

- `image_only` 兜底通道**未被真实数据演练**：22.081J 39 页全部可读，`skipped_pages` 为空。
  通道本身有测试覆盖，但本批次没有数据流过它
- **verbatim 探针 180 轮全部为 0**：未发现未加引号的整段照抄。
  据此，`quote_length` 弱口径的零触发**在本课件上**有了解释力——
  但这是英文课件 + 中文讲解的组合，同语言课件上结论未必成立
- 无 B 类维度（judge 未校准）、无 F3b（`gap_verdict` 恒 `null`）、未接 Supabase
