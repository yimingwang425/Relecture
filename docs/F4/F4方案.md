## 〇、一句话

F4 的第一件事 F1 已经做完（只欠一条会红的断言）；第二件事**不需要重做术语提取**——
「没看懂」的唯一消费方是讲解 prompt，它的触发时机是检索命中，
而检索的输出单位就是**切片**。术语表在这里是一个不必要的中间层。

## 一、探查结论：概念抽取不在关键路径上

交接文档 §九把「锚点怎么解」列为 F4 唯一的未知风险，三个候选方向里有一条是
「重做术语提取（要评估 32% 是方法问题还是任务本身难）」。**这条不用评估，因为问题问反了。**

锚点的粒度不该由「概念是什么」决定，该由**消费方读它的时候手里有什么**决定。
把消费方逐个列出来，它们手里都没有概念：

| 消费方 | 读取时机 | 手里有的东西 | 需要概念粒度吗 |
| --- | --- | --- | --- |
| 讲解 prompt 注入（产品功能） | 每轮检索之后、生成之前 | `slice_ids`（检索的输出） | **不需要** |
| 护栏指标「重复提问率」（§3.1） | 离线分析 | 事件里的 `slice_ids` | **不需要** |

两个消费方都在检索的下游，而**检索按切片进出**。要用概念做锚点，就得在写入侧
把点击映射成概念、在读取侧把检索片映射成概念——**多出两次映射，每一次都会漏**，
而漏掉的那部分与「用户没标记过」长得一模一样。

所以：**锚到切片**（口径 F54）。这是交接文档列的第三个方向，它不是「粒度粗但现成」的
将就选项，**它是唯一不引入新失败模式的选项**。

### 顺带结清术语表的账

PRD §7.1 用「一份数据三处复用」论证术语提取值得做：审查分母 / 检索信号 / F4 锚点。
现在三处的实际状态是：

| 复用点 | 状态 |
| --- | --- |
| 审查侧分母 | **已下线**（§8.1，召回 32%） |
| 检索信号 | **从未接入**（retrieval 选型走 T0，术语表不在路径上） |
| F4 锚点 | **本方案决定不用** |

**`glossary/` 模块当前没有任何消费方。** 这句话必须写进 PRD，否则「三处复用」会继续
被引用成术语提取的立项依据。**不删代码**（33 条测试 + 一份人工金标准是真资产），
但重启条件收敛为一条：§8.1 原有的两条重启条件满足 **且** 届时确有消费方。

## 二、两个消费方用同一个锚点，但**不共用同一个信号**

这是本方案里唯一一处主动扩了范围的地方，理由写在下面。

PRD §3.1 写护栏指标时说「锚点是现成的：F4 本来就要记录用户标记为没看懂的概念，
概念识别可复用该通道」。**照字面做会让护栏在最需要它的情形下不触发**：

> 护栏指标要测的是「轮次上升是不是『没懂』堆出来的」。
> 而**真正没懂的用户的典型行为是反复追问，不是点按钮**。
> 分子挂在用户点击上，等于要求用户先承认没懂，才能测出他没懂。

这是通则七第 5 例的形态（一个看起来在做护栏的规则，在需要它时不触发）。

处置：两个消费方共用锚点，分用信号（口径 F62）：

| | 信号 | 依赖用户行为 |
| --- | --- | --- |
| 讲解 prompt 注入 | **用户点击**（显式标记） | 是，且这是对的——注入必须有授权 |
| 护栏指标 | **同一会话内同一 `slice_id` 被重复命中的次数** | **否** |

护栏那一侧**零新增代码**：`slice_ids` 本来就在检索日志里。F4 要做的只有一件事——
**确认讲解轮事件里真的落了 `slice_ids`**；若没落，补上（检索结果本来就在手里，零成本）。
这是护栏指标唯一的数据来源。

**两处误差方向都要登记**：

- 切片不等于概念，一页讲了三个概念时，「问了同一页的两个不同概念」会被计成重复
  → **高估**重复率 → 护栏偏保守 → 方向单向、安全（口径 F61）
- `session_id` 当前是「一次页面加载」，刷新即新会话 → 会话内重复被**低估**
  → 两个偏差方向相反，**不得相互抵消着读**，各自单独写进口径

## 三、交付物

### 3.1 表（Supabase）

```sql
-- 一次「没看懂」点击 = 一行
confusion_marks
  id          uuid  PK  default gen_random_uuid()
  user_id     uuid      REFERENCES auth.users ON DELETE CASCADE
  round_id    uuid      -- 讲解轮标识，幂等键
  slice_ids   uuid[]    -- 本轮检索命中的全部切片
  question    text      -- 本轮提问原文，存但 v1 不注入（F59）
  created_at  timestamptz
  UNIQUE (user_id, round_id)
```

**表名刻意不叫 `concept_marks`**（口径 F55）：它锚的不是概念。
名字会变成一条没人核对的断言，半年后有人按名字去写「按概念聚合」的查询，
而那个聚合永远算不对。

**不存 `course_id`**（口径 F63）：切片经 `documents` 可 join 出课程，
而检索本就按课隔离，交集判定天然不跨课。理由同接线阶段的
「`course_id` 只放 `documents`，`match_slices` 走 join」——冗余一列的唯一强理由不存在。

**RLS**：`user_id = auth.uid()`，select + insert 各一条策略。**不授 delete**（见 F60）。

### 3.2 写入：沿用现有反馈按钮区，加第五个

讲解页每轮下方已有四个反馈按钮，新增「**这部分没看懂**」，零新组件。

⚠️ **必须与「讲太深」辨析清楚，否则两个按钮会互相吃流量**（口径 F56）：

| 按钮 | 作用域 | 持久性 | 改配置 |
| --- | --- | --- | --- |
| 讲太深 | **全局**（深度轴下移一格） | 永久，影响所有后续讲解 | ✅ |
| **这部分没看懂** | **局部**（本轮命中的那几片） | 下次命中这些片时生效 | ❌ |

按 F06（「例子没懂」）的既有形态处置：`config_changed: false`，
**不进「配置修改频率」的分子**（F41）。UI 文案要把「这次这里」与「以后都」说开，
否则用户想表达前者却点了后者，配置被一路改深，而**没有任何指标会红**。

### 3.3 读取与注入

```
提问 → 检索(slice_ids)
      → 与本人历史 marks 的 slice_ids 求交集      ← 一次 array overlap 查询，零模型成本
      → 非空则在【本轮消息】前缀注入一句限定语      ← 不进 system（F57）
      → 生成
```

**注入位置在本轮消息不在 system**（口径 F57）：marks 逐轮变化，放 system 会让 system 段
每轮不同。当前 system 约 406 token、缓存断点本来就未生效，所以这不是性能考量，
是**别把一个会变的东西放进一个按「不变」设计的位置**。

**措辞与详细程度轴正交**（口径 F58）。不写「讲得更详细」——那与 `paragraph_length` 判定
方向相反，在 P2/P3 用户上会推高重生成触发率，而配置扫描实验已实测 P3 触发 8/15。
写成：

> 用户此前看过这部分内容并标记为没看懂。**换一个切入点重讲，不要照搬上次的表述。**

约 35 字。**这不是文案偏好，是约束冲突决定的**——它决定了这一跳会不会顺带涨成本。

**不注入上次的提问原文**（口径 F59，字段存下来但不用）：上次问题与本次未必相关，
而模型无法判断二者是否相关。要它区分等于要它报告一个它观测不到的量——
F3b 的 G02 是同一条。存着是为了内测后可以再决定，改主意时不用重跑数据。

### 3.4 埋点

新增一个事件，进现有那张 `event_type` + `payload jsonb` 的表，不建新表：

| event_type | 必需 payload 字段 |
| --- | --- |
| `confusion_mark_created` | `round_id` · `slice_ids` · `mark_count_after` |

同时**核对一件既有事项**：讲解轮事件的 payload 里必须有 `slice_ids`。
它是护栏指标的唯一来源（§二），漏了就再也补不回来——PRD §14「埋点不能排在功能之后」
说的正是这种情形。

## 四、①「风格配置跨课程、跨会话继承」的处置

**不写功能代码。** 接线时已拍板「配置按人不按课」，`style_config` 主键就是 `user_id`，
这件事在结构上已经成立。

但按 F53（「验收要确认的东西，系统必须能自己答出来」），
「已经成立」不能是一句话，得有一条会红的断言：

> 同一用户在两门不同课下各跑一轮讲解，`build_system()` 产出的风格片段必须逐字节相同。
> **反向验证**：让配置读取带上 `course_id` 分行 → 断言必须红。

外加一件收尾：F1 方案 §九「配置按课程差异化」那条 TODO 的触发条件写的是「F4 / v1.1」。
本轮已判定不做，**触发条件改写为具体证据**——「内测出现同一用户在不同课上给出方向相反的
详细程度反馈」——而不是继续挂一个到期就会被默认执行的版本号。

## 六、守卫清单（每条须能被反向验证变红）

| 守卫 | 反向验证方式 |
| --- | --- |
| 跨课继承（§四） | 让配置读取按 `course_id` 分行 → 断言必须红 |
| **注入真的会触发** | 造一条有交集的数据 → 本轮 messages 必须含限定语；去掉注入逻辑 → 必须红 |
| **注入不是恒触发** | 造一条**无交集**的数据 → 必须**不**注入；把交集判定换成恒真 → 必须红 |
| RLS 跨用户隔离 | 用 A 的 token 读 B 的 marks → 403/空 |
| cascade | 删 `auth.users` 的行 → marks 必须消失；把外键改 `no action` → 反向必须红 |
| 幂等 | 同一 `round_id` 点两次 → 表里仍为一行 |
| 埋点真的写进去了 | 断言**表行数增加**，不是断言函数被调用 |
| `slice_ids` 真的落了库 | 断言讲解轮事件的 payload 里有非空 `slice_ids`；置空 → 必须红 |

第三条是本轮最关键的一条：**一个恒触发的限定语，和一个永远不触发的规则一样糟**，
而前者更难发现——它的输出看起来完全正常，只是每一轮都在多讲一句。
这是 F3b 那条「跳过页 ∩ 命中页恒为空集」的镜像形态。

## 十、需要你拍板的三项

1. **F54 · 锚到切片，不做概念抽取**。这是本方案的全部分量所在，也是唯一一处
   推翻交接文档判断的地方（它把「重做术语提取」列为待评估选项，本方案认为不必评估）。
2. **F62 · 护栏指标的分子改为检索重复**，不依赖用户点击。这是本方案唯一主动扩范围处，
   代价是一次字段核对，收益是护栏在最需要它的情形下会触发。
3. **F60 · v1 不做取消标记**。误标方向单向可解释，但它确实是一个用户无法撤销的动作。

拍完即可进第 1 步。F4 完成后，v1 的四个功能模块齐了，
剩下的是交接文档 §七那组内测前的清理（验收数据、自助注册、受限页排除）。
