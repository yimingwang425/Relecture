3. **Sonnet 明显好一些，仍未达标**：X 65.6%（< 70%）、Y 25.0%（> 10%）、Z 80.0%（达标）；单次 $0.0255（单轮 +94%），
   延迟中位 6.8 s、P90 14.0 s——都在学生等待的路径上。

### detail_level（标签可信）上的模式

- **审查员拿参考数字当硬指标**：P3 的参考是「整篇约 120 字」，而讲解助手的 P3 实际写到 136–214 字。
  审查员（尤其 Haiku）因此把明显比 P0 版短一半的讲解判成「不够精简」。
- **「符合」里有一部分其实不符合别的轴**：非目标轴取默认值（多举例、先结论），讲解助手常常没照做；
  审查员按那些轴打回，在本评测里被记成「误打回」。**Y 因此偏高**，它混进了讲解助手在其他轴上的不服从。
- Haiku 在「P0 讲解 × 精简偏好」上 5/8 交不出合格结论（提交被退回两次后步数用完）。

### Haiku 的判错条目

约 80 条，**没有逐条读**（偏离预登记，见下）：上面那张不依赖标签的表已经说明它在掷硬币，逐条归因改变不了这个结论。

## 发现的缺陷

1. **时限与实测延迟不匹配**：提交那一步 Haiku 要写数百 token 的问题与修改意见（单条实测 912 token、10.4 s），
   单步 8 s 的时限几乎必然超时。
2. **引文校验太松**：一个字母的引文几乎能在任何一段里找到。应当要求引文至少若干个字（例如 ≥ 6 个非空白字符）。
3. **生成侧**：讲解助手对 B 类讲法的服从度不高，尤其是 structure 与 depth。这是讲解 prompt 的问题，不是审查员的问题，
   但它决定了「风格审查」上线后会打回多少次。

## 偏离预登记

1. **加了「放开时限」的诊断跑**（Haiku 全集、Sonnet 部分）：预登记没有预料到生产时限下 83% 超时。诊断跑只改时限，
   prompt、工具、校验不变；标题数字仍以生产配置那一列为准。
2. **Sonnet 只跑了 104 条**：前 4 个问题的 64 条（符合 + 偏离）+ 冲突集与对照全部 40 条。全集按估算会超预算上限 $8；
   选这 104 条是为了让四个集都有数。
3. **Haiku 判错条目没有逐条读**，理由见上。Sonnet 三条 B 类轴上的判错条目全部读了。
4. **补充了不依赖标签的分辨力表**（未预登记）。
5. **两条对照问题设计有误**（问题本身就在要推导），照实报，没有剔除。
6. 预登记的达标线都按全集口径报；去掉可疑对的参考数字不适用（detail_level 自动检查 0 对可疑）。

## 能说的与不能说的

- **能说**：在自写合成课件上、按预登记的方法评测，上线的风格审查配置因超时基本不起作用；Haiku 放开时限也判不出讲法；
  Sonnet 检出 66%、误打回 25%、冲突时放行 80%，单次成本 +94%、延迟中位 6.8 s。
- **不能说**：「风格审查 agent 检出率 X%」作为已达标的成绩；任何一个数都不是在真实学生会话上测的；
  B 类轴的标签有噪声（讲解助手本身不服从），且只由 Claude 复核过、没有人工标注。
