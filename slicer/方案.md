## 1. 切片单位与边界策略

### 1.1 结论：**页（幻灯片）为切片单位**

一个可用页 = 一个切片。块不作为检索单位，但**完整保留在切片内部**，充当结构与溯源锚点。

四条理由，前两条是这次测量给的：

1. **页天然有界，不需要长度阈值。** 100 个可用页里**没有一页超过 2000 字符**（max 1911，
   p95 仅 1125）。幻灯片的版面本身就限制了单页信息量——这不是巧合，是媒介属性。
   于是「切片多长」从**输入参数**变成了**测量结果**。
2. **这条差异直接影响 2b。** 固定 token 窗口要求**现在**就定一个数，而那个数取决于
   2b 还没选的 embedding 供应商的上下文窗口。用页做边界可以把这个决定**推迟到 2b**，
   而不是现在凭感觉填一个占位值、再让它一路影响召回质量。
3. **页边界是作者亲手划的语义边界。** 一页 = 一个论点，这是免费拿到的、比任何自动
   切分都准的语义切割。实测 `size_rank` 最高块正是幻灯片标题
   （`WELL KNOWN ISSUES` rank 0.94、`OUTLINE` rank 0.97、`STRATEGY ASSESSMENT` rank 0.96），
   说明页内结构清晰、页间界限干净。
4. **页号是用户可验证的溯源锚点。** 用户能翻到第 N 页对照讲解。
   token 窗口的边界对用户毫无意义，无法呈现、无法核对。

### 1.2 为什么不用固定 token 窗口 + 重叠

标准 RAG 做法，但它的前提在这里不成立。

| 问题 | 说明 |
| --- | --- |
| **幻灯片文本不是线性的** | 标题、项目符号、图注、页脚在**版面上并列**，不是连续散文。拼成一个字符串再按 token 切，切点会落在任意位置——可能把一个 bullet 的后半与下一个 bullet 的前半装进同一切片。§0 实测 37.9% 的块 ≤ 20 字符，切碎的概率很高 |
| **重叠窗口在这里是纯浪费** | 重叠的价值是「避免切断连续论述」。幻灯片本来就是断的，重叠只是复制文本，抬高向量库规模与 2b 的写入成本，换不来召回收益 |
| **强迫现在定一个无依据的数** | 窗口大小与重叠比例都得填，两个数都只能标「占位待定」，且会一路影响召回质量。§1.1 第 2 条 |
| **丢掉页边界** | 一个窗口可能横跨两页，溯源文案「第 N 页」就没法写了 |

**保留场景**：讲义型 PDF（连续散文、单页数千字）会让页单位失效。
故 §1.4 的超长页拆分路径仍要实现，只是当前语料 0 触发。

### 1.3 为什么不用块（block）

| 问题 | 实测 |
| --- | --- |
| **单块语义不完整** | 块中位数 **30 字符**，37.9% ≤ 20 字符。一个 bullet 脱离它的标题后检索出来毫无意义——`≥ 85%` 这种块召回了也没法讲 |
| **向量库规模膨胀 7.4×** | 741 块 vs 100 页。2b 的 embedding 调用与存储成本直接翻 7 倍，换来的是更差的语义完整性 |
| **召回后仍要拼回页** | 命中一个 bullet 之后，讲解 agent 需要同页的标题与兄弟 bullet 才能讲。等于绕一圈回到页 |

**但块不是没用**——它是 §2 的溯源锚点与切片内部结构，只是不作为**检索单位**。

### 1.4 边界策略的三个细节

| 情形 | 策略 | 理由 |
| --- | --- | --- |
| 正常页 | 1 页 = 1 切片 | §1.1 |
| **超长页** | 按**块边界**拆，绝不在块中间拆；阈值由 2b 注入，**默认不拆** | 块是作者给的最小语义单位，拆穿它就回到了 token 窗口的老问题。当前语料 max 1911，**0 触发** |
| **过短页**（18/100 页 < 120 字符） | **v1 不合并**，改为给出 `prev_slice_id` / `next_slice_id` 邻接链 | 合并阈值无依据（凭感觉给数）；且合并会切断「切片 ↔ 页」的一一对应，而这个对应正是溯源文案「第 N 页」的基础。检索层需要上下文时沿邻接链自行扩展。**「是否需要合并」应当由数据回答**——2b 之后按页字符量分组统计检索命中率，再决定 |

`page_indices` 定成**列表**而非单个整数，就是给日后可能的合并留形状，现在恒为单元素。

## 2. 溯源粒度：溯到**块**

### 2.1 三个粒度的代价

| 粒度 | 条目数 | 支撑 §12.1「单段引用 ≤ 100 字」 | UI 可高亮 | 用户可核对 | 人工标注可行性（§8.1 溯源率） |
| --- | --- | --- | --- | --- | --- |
| 页 | 100 | ✗ 只能定位到页，不知引用来自哪段 | 只能整页 | ✓ 页码 | ✗ 一页 7 个块，标不准 |
| **块** | **741** | **✓ 块文本可直接做最长公共子串比对** | **✓ 有 bbox** | **✓ 页码 + 版面位置** | **✓ 粒度合适** |
| span | 1951 | ✓ 但过细 | ✓ | ✗ 39.7% ≤ 3 字符，对用户无意义 | ✗ 标不了 |

### 2.2 这一步顺带解掉一条挂着的 TODO

`实验脚本/A类规则计算脚本/TODO.md` 里有一条：

> **引用长度与课件原文比对** —— 当前只按引号/引用块识别引用；更准的做法是与课件文本
> 求最长公共子串，但需课件文本作为额外输入，超出本脚本的输入范围。
> **触发条件：接入 F2 之后**

切片携带块级原文，**这个输入现在有了**。A 类的 `quote_length` 维度可以从
「按引号猜」升级为「与课件原文求最长公共子串」，§12.1 的合规约束才算真正可执行。
本次不改 A 类脚本（不在 2a 范围），但方案里点明这条路已通。

### 2.3 span 不进切片

块级已含 `font.size_pt` / `size_rank` / `bold` / `bbox` / `image_adjacency`——
第三步图注通道要的全在这一层。span 级 1951 条、39.7% ≤ 3 字符，装进切片是纯体积成本。

**前提**：parse 结果必须**持久化**（按 `doc_id` 存档），切片只是它的**派生视图**。
需要 span 时按 `doc_id` + `block_id` 回取。
这是一条架构约束，不是实现细节——若 parse 结果用完即弃，span 就真丢了。

## 3. 输出 schema（草案）

```jsonc
{
  "schema_version": "1.0",
  "manifest": {
    "doc_id": "sha256:…",                 // 与 parse 结果同一个 id
    "source_schema_version": "1.0",       // 消费的 parse schema 版本，对不上要拒绝
    "slicer_version": "0.1.0",
    "slice_ruleset_version": "slice-1.0", // 口径版本，改边界策略必须递增
    "page_count": 19,                     // 原始总页数，**含不可用页**
    "sliced_page_count": 17,
    "slice_count": 17,
    "skipped_pages": [                    // 【要求 4】页号连续性的依据
      { "index": 8, "kind": "image_only", "image_count": 2,
        "reason": "内容全在图里，解析服务读不了图" }
    ]
  },
  "slices": [
    {
      "slice_id": "sha256:…#s003",
      "doc_id": "sha256:…",
      "ordinal": 3,                       // 切片序号，连续无缺号
      "page_indices": [4],                // **原始页号**，缺号即被跳过的页
      "prev_slice_id": "…#s002",
      "next_slice_id": "…#s004",
      "title": "MORE PROPOSED SOLUTIONS", // 便利字段，见 §3.1
      "title_block_id": "p4-b1",
      "text": "…",                        // 供 2b 嵌入与讲解 agent 使用的拼接文本
      "char_count": 246,
      "units": [                          // 【要求 2/3】块级溯源锚点 + 版面信息
        {
          "block_id": "p4-b1",
          "page_index": 4,
          "order": 1,
          "text": "MORE PROPOSED SOLUTIONS",
          "text_span": [0, 23],           // 在 slice.text 中的偏移；引用比对靠它回指原块
          "bbox_pt": [19.1, 50.9, 405.2, 82.2],
          "bbox_norm": [0.03, 0.08, 0.56, 0.13],
          "font": { "size_pt": 25.1, "size_rank": 0.95, "bold": true, "name": "…" },
          "image_adjacency": { /* 原样透传，含 gap_lines / overlap_ratio */ }
        }
      ],
      "images": [
        { "image_id": "p4-i0", "bbox_norm": [...], "coverage": 0.31 }
      ]
    }
  ]
}
```

### 3.1 `title` 是便利字段，且**不做 role 分类**

`title_block_id` 用**纯结构规则**选出：`size_rank` 最高，并列时取最靠上的块。
**不设阈值**——不需要判断「够不够大才算标题」，只需要「哪个最大」。
实测在 22.081J 上给出的正是幻灯片标题（rank 0.94–0.97）。

**刻意不输出 `role`（title / body / caption / footer）分类。**
图注与正文的判定是**第三步**的事。切片层给出去等于用无依据的阈值抢做第三步的决定，
而第三步真做时会发现切片里已经躺着一个错标签，还得先把它清掉。
切片只负责把**信号**（`size_rank`、`image_adjacency`、`bbox`）原样送到第三步手上。

实测佐证这些信号确实够用：22.081J 上 `is_adjacent` 命中 18/334 块（5.4%），
内容是 `Photo by André Cotte on Flickr.`、`Image by MIT OpenCourseWare…`、
`[data from doe.eia.gov]` 等真图注；同时也命中了 `REAL HEAT ENGINES`（rank 0.96）
这类**图上方的标题**——单靠邻接会误收，需要与 `size_rank` 联合判断。
**这正是第三步该做的事，不是切片该做的事。**

## 4. 不可用页的处理【要求 4】

三条硬约束：

1. **不进切片。** `scanned_ocr` / `image_only` / `empty` 的页不产生切片。
2. **页号序列保持连续。** 切片的 `page_indices` 一律用**原始页号**。
   15.316 那种整份不可用的情况会得到 0 个切片；14.129 的 p33–p36 被跳过后，
   相邻切片的页号就是 32 → 37，**缺号本身即信号**。
   绝不重新编号——重编会让「第 N 页」对不上用户手里的课件，用户按页码翻会翻错页。
3. **`manifest.skipped_pages` 可查到每一页被跳过的页号与原因**，含 `image_count`。

### 4.1 这条要传到检索层（已记入 parse-service/TODO.md）

`image_only` 的页**不是空页**，是「内容全在图里」的页。
用户问到这类内容时，检索会一无所获，而 PRD §10 现有的兜底文案是
「这个内容课件里没有提到」——**这句话是错的**。课件提到了，只是我们读不了图。

正确文案：**「这部分在第 N 页的图里，我读不了图。」**

`skipped_pages` 就是让检索层能写出这句话的数据。本方案负责把它产出来并传下去；
文案本身归 F3。

## 5. 阈值与来源

| 阈值 / 决策 | 值 | 来源 | 依据 / 确定路径 |
| --- | --- | --- | --- |
| 切片单位 | **页** | **实测依据** | 2026-08-20，100 个可用页：p50 = 260、p95 = 1125、max = 1911 字符，无一页超 2000。页天然有界 |
| 溯源粒度 | **块** | **实测依据** | 块 741 条 / p50 = 30 字符；span 1951 条 / 39.7% ≤ 3 字符。见 §2.1 的三列代价对比 |
| 超长页拆分阈值 | **未设（默认不拆）** | **占位待定** | 当前语料 **0 触发**。确定路径：2b 选定 embedding 供应商后，按其上下文窗口与实测召回确定；作为必填配置项注入，不在 2a 内写死 |
| 过短页合并阈值 | **不合并** | — | 见 §1.4。合并阈值无依据，且会切断切片与页的一一对应。「是否需要合并」由 2b 之后按页字符量分组统计检索命中率来回答 |
| `title_block_id` 的选取 | `size_rank` 最高、并列取最靠上 | **无阈值** | 只需相对比较，不需要「够不够大」的绝对判断 |
| 切片重叠 | **无** | — | §1.2：幻灯片本来就是断的，重叠是纯成本 |

## 6. 已知局限

| 项 | 说明 |
| --- | --- |
| **多栏版面的拼接顺序** | `slice.text` 按块的 `order` 拼接，而 `order` 是几何序（先 y 后 x），parse schema P16 已声明**不是阅读顺序**。多栏幻灯片会拼错顺序。当前语料未见多栏，无从验证，故不预先处理——记 TODO |
| 讲义型 PDF | 单页数千字的连续散文会让页单位失效，依赖 §1.4 的超长页拆分路径，而该路径的阈值待 2b |
| PPTX | parse 尚未支持，切片层无需改动即可承接（`origin` 已分装） |

## 7. 待你拍板

1. **切片单位用页**（§1.1），以及不用 token 窗口 / 不用块的理由是否成立。
2. **溯源到块**（§2），span 不进切片、改为按 `doc_id` + `block_id` 回取——

   建议做成**库**（Python 包）而非服务，由 2b 或上层服务调用。
   目录暂用 `slicer/`，名字与形态都可改。
