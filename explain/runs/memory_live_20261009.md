## m1 → m2 改了什么（为什么有两份记录）

m1 两次整理都把**之后保留原文的那几轮里的提问**（「压扁和行列式为零有什么关系」「迹是什么」……）写进了
「还没解决的问题」。那几轮会原样留在对话里，问题在那里已经答过了——讲解助手拿到笔记会以为它们还悬着。
目录里列出保留轮次的提问，本意只是让模型判断「最后一两轮要不要留」，m1 的措辞没有说清。

m2 在 system 与目录标题里写明「只供判断留不留最后一两轮，不要写进笔记」，open_questions 限定在已整理范围内。
m2 两次整理都没有再出现。**这条只能靠 prompt，代码判断不了**（自由文本，模型会改写措辞）——如实登记。

## 能说的与不能说的

- **能说**：链路在真模型上跑通；校验退回在真模型上真的发生过一次并被改对；模型做出了「留下没讲完的推导」这个判断。
- **不能说**：「有了笔记讲解更连贯了」。n = 2 个场景、每个一次（R17）。要在真会话上比较「笔记 + 原文」与「只有原文」。
- **代价**：每次整理 $0.017–0.031、12–39 s。**不在关键路径上**（在讲解返回之后跑）；按触发规则约每 6 轮一次。

## 观察到、本轮不修的

1. **状态判断偏乐观**：第 2 轮学生说「没懂」，m2 的笔记仍把「特征向量」标成 understood（理由是学生之后继续往下问）。
   按 system 的定义说得通，但「卡住过」这个信号丢了。**触发条件**：内测里抽查笔记，struggling 明显少于「点过没看懂」的轮次。
2. **concepts 偏碎**：m2 第一次整理把五个例子各列成一个概念（镜面反射 / 投影 / 剪切 / 旋转）。字数在上限内，不退回；
   多了只是笔记长。**触发条件**：笔记常年贴着 1200 字上限。
