# 漂移实验（A 类维度版本）

PRD §8.2「漂移衰减曲线」的实现。**只含 A 类四维**——B 类维度与 judge 校准
等人工标注就绪后再做，因此本实验的结论只覆盖 A 类维度的漂移。

## 实验设计与其边界

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 对照 | 有审查 / 无审查，各 **15 轮** | 15 轮取自真实复习序列；凑到 20 需编造提问，样本会偏离真实学习行为 |
| 重复 | **每条件 3 条独立轨迹** | 当前模型无 temperature，采样随机性无法消除；每条件每轮 n=1 时无法区分漂移与噪音 |
| 审查 agent v0 | 只查 A 类四维，零模型成本 | §7.2「生成方与审查方目标相反」，v0 做到最直白：审查方完全不调模型，没有自我合理化的空间 |
| 重生成上限 | 2 次 | §7.1 |
| 无审查组的指标 | **照常计算，只记录不干预** | 不算就没有对照 |
| **检索** | **不含。课件全量进 system prompt** | §8.2 要隔离的变量是「审查 agent 有无」。引入检索后两组可能取到不同片段，连输入都不一样，对照就废了。**结论仅适用于「课件全量在上下文中」这一条件** |
| 重生成方式 | 反馈驱动，不是重试 | 当前模型已移除 temperature，纯重试大概率复现同样的问题；把审查反馈作为一轮追加指令，模型才有依据修改 |
| 修正往返 | **不进对话历史** | 只留提问与最终输出，两组历史结构保持一致；否则第 k 轮的输入长度差异会变成审查之外的第二个变量 |

## 重复必须是整条轨迹的重复

漂移是一条对话轨迹随轮次演化出来的性质。在同一条对话里对某轮采样 3 次再挑
一条继续，轨迹仍然只有一条——重复没有统计意义。所以每个 replicate 是**一次
独立的 20 轮完整对话**，各自维护自己的历史。

`3 × 2 × 15 = 90` 次生成是**下限**，重生成会在此之上追加（上限 ×3）。

**误差带取全距（min–max），不取 ±1SD。** n=3 时样本标准差本身极不稳定，
用 ±1SD 作图会暗示一个并不存在的分布假设。标准差仍输出，但只作参考量。

聚合结果写入 `summary.json`，每行 `(条件, 轮次, 维度)` 带均值、全距、
**有效观测数**、达标数。有效数必须看——某些 replicate 可能因分母护栏
（`term_min_occurrences`）算不出数，只看「达标数/重复数」会把 1 个观测
误读成 3 个。

## 分母护栏：实验用 2，生产保持 5

`term_min_occurrences` 在实验配置里被覆盖为 **2**（`config/style.json`），
生产默认仍是 5。这是刻意的口径覆盖，配置指纹随之变化，属正常。

**为什么不反过来——改提问去迁就护栏？** 因为那会偷换测量对象。若为满足
护栏去挑术语密集的提问，这 20 个问题就不再是真实学习行为的样本，测出来的
是「术语密集提问下会不会漂移」而非「真实使用中会不会漂移」，实验结论的
适用范围被悄悄收窄。这是有效性问题，不是精度问题。

护栏本身是为**单次生产判定**设计的（一次不出数就等下一次）。实验有 3 条
轨迹可合并，低分母噪音会被部分平均掉，所以实验侧承受得起更低的门槛。

**代价与应对**：低分母轮次的点可信度确实较低。因此

- 每轮记录首现术语数（`rounds.jsonl` 的 `term_occurrences_first`）
- `summary.json` 每个点带 `denominators` / `denominator_min` / `low_denominator`
- 表格与图上，任一 replicate 分母低于生产护栏 5 的点标 **⚠**

读图的人据此知道哪些点该少信几分，而不是把它们和高分母的点等同看待。

## 两条已登记的预期（不改设计）

**一 · 第 9、11、12、13 轮是纯物理原理追问，术语密度低，大概率触发低分母 ⚠。**
这是真实分布，不作调整。**报告时四个维度必须分开看，不要合并**——
`term_annotation` 在这些轮次信噪比低，而 `chinese_ratio` 与 `paragraph_length`
不受影响；合并成单一曲线会让低信噪比的维度污染其余三个。

**二 · 第 12 轮（DC/AC）超出课件范围**，顺带观察模型是否遵守 PRD §6.2
「超出课件范围须显式标注」。**仅记录，不进指标**——它不是 A 类维度，也不
参与达标判定；混进指标会让「风格遵循度」这个数悄悄变成别的东西。

记在 `rounds.jsonl` 的 `observation_out_of_scope_disclaimer`（其余轮次为
`null`），跑完在终端单列一行汇总。

## 教训：处理组多做的动作会在无关维度上引入偏差

假跑第一版的输出显示 `with_review` 明显差于 `without_review`——看起来像
「审查让结果更差」这个结论。实际原因是假模型的质量衰减挂在**调用次数**上，
而重生成也是一次调用：有审查组每轮最多调 3 次，衰减速度是对照组的 3 倍。
偏差挂错了计数。

**通则：对照实验中，处理组比对照组多做的任何动作，都可能在与处理无关的维度
上引入偏差。** 设计和排查时都要问一句——偏差是不是挂在了错误的计数上？

在本实验里，处理组（有审查）比对照组多做的动作是**重生成**，它至少沿三条
路径可能污染测量：

| 路径 | 后果 | 现有处置 |
| --- | --- | --- |
| 任何按调用次数累积的量 | 假模型衰减即此例 | 改为按对话轮次计 |
| 修正往返进入对话历史 | 有审查组上下文更长，输入长度成为第二个变量 | 修正往返不入历史，只留提问与最终输出 |
| token 与成本 | 有审查组必然更贵 | 这是**真实代价**，不是偏差——照实记录，用于 §9.1 的成本预算 |

第三行值得单独说：并非所有组间差异都是偏差。重生成带来的成本差异是审查
agent 的真实代价，本来就该被测出来；要消除的是**与被测属性无关**的差异。

## ⚠️ temperature 在当前模型上不可用

Claude Opus 5 / Sonnet 5 **已移除 `temperature`、`top_p`、`top_k`，传入返回 400**。
「固定温度以控制随机性」在这一代模型上无法执行。

可固定并记录进实验元数据的是 **`effort`** 与 **`thinking`**（样本头写的
「Sonnet 5 Medium」对应 `effort: "medium"`，不是温度）。剩余随机性来自模型
采样本身，只能靠 sanity check 的重复采样观察，不能靠参数消除。

## Sanity check

两层，`python -m drift sanity` 一并跑：

1. **输入同一性（硬检查）**——两组第 1 轮的 system / messages / 模型参数逐字节
   相同，比对 sha256 指纹。确定性检查，抓实现 bug，不过就中止。
2. **输出同分布（观察）**——重复采样第 1 轮各 N 次，报告四维的均值与极差。
   n 通常只有 3–5，**这不是统计检验**，只能看量级异常；报告里据此写
   「未见系统性差异」而非「已验证同分布」。

## 用法

### 运行前：凭据注入

**不要全局 `export ANTHROPIC_API_KEY`。** 全局设置会让在同一环境下运行的
Claude Code 从**订阅计费切换到 API 按量计费**——实验没跑，账单先涨。

凭据放在本目录的 `.env`（已 gitignore，根与本目录两层都有规则）：

```
ANTHROPIC_API_KEY=sk-ant-...
```

两种局部注入方式，任选其一：

```bash
# A · 只在当前 shell 生效，用完 unset
set -a; source .env; set +a
$PY -m drift run --repeats 1
unset ANTHROPIC_API_KEY          # 用完就撤，别留在 shell 里

# B · 单行内联，只对这一条命令生效（更稳妥，不污染 shell）
env $(grep -v '^#' .env | xargs) $PY -m drift run --repeats 1
```

方式 B 更安全：变量只存在于那一个子进程，Claude Code 所在的 shell 完全不受
影响。方式 A 图省事，但要记得 `unset`——忘了就等于全局设置。

凭据只在进程内存里传给 SDK：`drift` **只**读 `ANTHROPIC_API_KEY`，不回退到
`ANTHROPIC_AUTH_TOKEN` 或 `ant auth login` 的 profile（否则实验跑起来了却说
不清这笔钱从哪个凭据出）。凭据不写入任何文件、不进日志、不进 `metadata.json`
或 JSONL——输出里只有模型名与用量。

```bash
PY=../A类规则计算脚本/.venv/bin/python   # 复用 a_rules 的 venv

# 1. 抽课件全文（需要 pypdf，仅此一步）
$PY -c "from pypdf import PdfReader; import pathlib; \
  print('\n\n'.join((p.extract_text() or '') for p in \
  PdfReader('../测试集/MIT22_081JF10_lec01b.pdf').pages))" > config/courseware.txt

# 2. 写你的 20 个提问
cp config/questions.example.json config/questions.json && $EDITOR config/questions.json

# 3. 先用假模型跑通全链路（不调 API，确认 JSONL 结构、排序、成本日志）
$PY -m drift sanity --fake
$PY -m drift run --fake --out runs/smoke

# 4. 真实调用
export ANTHROPIC_API_KEY=...
pip install anthropic          # a_rules 本身仍是零依赖，这只是实验侧
$PY -m drift sanity            # 先单独跑 sanity
$PY -m drift run --repeats 1   # 先跑真实单轨
$PY -m drift verify --run runs/<批次>   # 核验，通过再跑完整
$PY -m drift run               # 正式实验（3 replicate × 2 组 × 15 轮）
```

`verify` 只查两件容易出错、代价又高的事：**配置指纹**是否与当前配置一致
（对不上说明这批数据不是用你以为的配置跑的），以及**第 2 轮起缓存是否命中**
（没命中成本接近翻倍，通常到账单才发现）。不做更细的校验——核验脚本本身
出错或过于繁琐，比它能挡住的问题更麻烦。

**成本估算**（claude-sonnet-5 正价，课件约 5K token，单轮输出约 1300 token）：

| 缓存策略 | 6 条轨迹 × 15 轮 |
| --- | --- |
| 只缓存 system | ~$4.4 |
| **再缓存对话历史（默认）** | **~$2.2** |
| 含重生成（×1.4 估） | ~$3.1 |

对话历史逐轮增长，20 轮下来它远比课件本身贵——只缓存 system 会让历史每轮
按全价重算一遍。`cache_conversation` 默认开，断点打在最近一轮消息末尾。

`--fake` 用确定性假模型，输出质量随轮次线性衰减。**它不是模拟真实漂移**——
曲线形状是写死的，只用来验证链路，不能当结论看。

## 首次单轨实测记录（2026-08-20，n=1）

`claude-sonnet-5` / `effort=medium`，配置指纹 `b50218965f4c`，术语表 v1.1。
**单轨，n=1，以下均为待验证的观察，不是结论。**

### 一 · 只有 term_annotation 出现组间差异

| 维度 | 有审查 | 无审查 | 判断 |
| --- | --- | --- | --- |
| chinese_ratio | 0.93–0.99 | 0.91–1.00 | 两组均无可观察漂移，全程达标 |
| paragraph_length | 36–105 字 | 29–78 字 | 同上 |
| quote_length | 4–74 字 | 4–22 字 | 同上，离 100 字上限很远 |
| **term_annotation** | 波动，第 15 轮降至 **0.444** | **第 9 轮起基本归零** | **唯一出现组间差异的维度** |

**这个区分度本身是有意义的**：若四个维度一起动，更可能是测量工具或实验设置
的系统性偏向；只有一个维度动、其余三个纹丝不动，说明指标没有整体偏向某一组。

**但审查并未完全阻止漂移**——有审查组第 15 轮也降到 0.444。审查能压住，压不死。

### 二 · 术语维度有 5 轮完全无数据

第 4、5、6、7、13 轮两组皆为「—」，即便护栏已降到 2。这几轮是单位换算、
读图、原理追问，本就几乎不含术语表内的词。**这比事先预计的（9/11/12/13 轮
低分母）更严重**：不是分母低，是压根没有观测。

后果：term_annotation 曲线在 15 个点里只有 10 个有值，分辨率有限。这是真实
提问分布的性质，不是缺陷——但读图时必须知道空点在哪。

### 三 · 重生成率 53%，远超 §9.1 的 20% 目标

15 轮触发 8 轮；第 8、10、15 轮重生成 2 次后**仍不达标**（降级输出）。

**待归因，不改设计。** 至少三种可能，需完整实验数据才能分辨：

1. 讲解 agent 的提示词不足以稳定满足术语标注要求
2. 90% 阈值对该模型过严（该阈值本身是**占位待定**，见 PRD §3.2）
3. 反馈驱动的重生成本身效力有限——三次触顶说明反馈没能让模型收敛

### 四 · 观察项：模型遵守了 §6.2

第 12 轮（DC/AC，超出课件范围）两组**都**给出了「超出课件范围」声明，2/2。
仅记录，不进指标。

### 五 · 成本模型曾报高 50%

脚本原按正价 $3/$15 报 $1.0971；`claude-sonnet-5` 在 2026-08-31 前是
introductory 价 $2/$10，重算为 **$0.7314**。定价表已改为带到期日，8/31 后
自动回落。

原先用正价的理由写的是「宁可高估也不要在达标判定上乐观」——**那个理由是错的**。
§9.1 承诺的是报准单位经济，高估不是安全，是错。

核对过无重复计算：`input_tokens` 是未命中缓存的余量（42 次调用合计仅 84），
与 `cache_read` / `cache_creation` 不重叠。成本构成：**输出 token 占 68%**，
缓存读取 14%，缓存写入 18%。缓存工作良好——522,574 读 vs 84 未命中。

## 输出

```
runs/<时间戳>/
├── metadata.json   模型参数、配置指纹、术语表版本与冻结状态、sanity 结果、
│                   以及「不含检索」「不含 B 类」「temperature 不可用」三条边界声明
├── rounds.jsonl    每轮每 replicate 一条完整记录
├── summary.json    按 (条件, 轮次, 维度) 聚合的均值与全距 —— 作图数据源
└── transcripts/    每轮最终讲解文本，轮次零填充命名（排序 = 轮次序）
```

`rounds.jsonl` 每条含：条件、轮次、提问、请求指纹、重生成次数、是否达标、
每次尝试的 completion（token / 成本 / 延迟 / stop_reason）与审查结果、
本轮 usage 汇总与成本、最终四维评估的完整 details。

成本按 claude-api 的公开价目折算，含 prompt caching 的 1.25×写 / 0.1×读。
Sonnet 5 按正价（$3/$15）而非 8 月底前的introductory价计——宁可高估，
也不要在 §8.4 的 <$0.05 判定上乐观。

## 不入库的文件

`config/courseware.txt`（课件全文，避免仓库里出现同一份材料的第二个副本）、
`config/questions.json`（你自己写的提问）、`runs/`。
