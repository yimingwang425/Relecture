## 一、口径决策表

> 口径变了数字就变了。**任何调整都必须先改这张表并记新日期，再改代码。**
> 未记在此表的口径变更视为 bug。体例照 `explain/README.md` 的 X01–X12。
> 归属：**【评审指定】**＝任务书给定或评审拍板；**【提出】**＝本模块提出并已确认。

| 编号 | 口径 | 决策 | 理由 | 归属 | 日期 |
| --- | --- | --- | --- | --- | --- |
| F01 | 每对样例的差异面 | **只在目标维度上不同**，非目标维度一律取默认值（`P0` / `more` / `conclusion_first` / `why`） | 通则二的直接应用。若两个样例同时在两维上不同，用户选了 A **你不知道他选的是哪一维**——而 F1 的全部产出就是这个归因 | 【评审指定】 | 2026-09-07 |
| F02 | 样例的生成时机 | **预生成为静态 JSON**，不现场调模型 | 四条理由，任一条单独成立：**合规**——§12.1 要求对外展示一律用自写合成课件，F1 样例给所有用户看即对外展示，这是硬约束不是偏好；**对照纪律**——只有预生成才能在发布前人工核过 F01；**成本**——现场生成每新用户 ≈ $0.18，发生在用户产生任何价值之前；**延迟**——冷启动首屏不能等两次生成。代价（样例不是用户自己的课件）**登记，不修**，触发条件见 §二 | 【评审指定】 | 2026-09-07 |
| F03 | `chinese_ratio.min` | **恒 0.85，v1 不开放给用户** | P4 的三口径分歧（85/76/59）尚未收敛。**开放一个测量本身不稳的档，等于把口径误差记到用户偏好头上**。同理 `max_quote_chars` 恒 100（§12.1 合规常量，不是风格偏好） | 【评审指定】 | 2026-09-07 |
| F04 | 配置的三个标识 | `metric_set_id` / `config_fingerprint` **不含** B 类字段；新增 `prompt_profile_id` **含** B 类字段 | B 类进指纹会出事：两个 A 类判定完全相同的用户会有不同指纹，`verify` 里「点内指纹唯一」这类守卫在真实用户数据上直接噪声化。分开的第二个收益：归因「讲解质量变了，是阈值变了还是 prompt 变了」，**一个标识答不出，两个能**。承接 a_rules D47 / explain X10 | 【评审指定】 | 2026-09-07 |
| F05 | 反馈按钮映射 | 太啰嗦 → 详细程度轴下移一格；讲太深 / 讲太浅 → 深度轴下/上移一格 | 用离散实测点位做轴的收益不只是「测过」：若档位是连续区间，「太啰嗦」必须回答「往哪个方向移多少」，**那是一个新的占位阈值**。离散轴上就是移动一格，**零新阈值** | 【评审指定】 | 2026-09-07 |
| F06 | 「例子没懂」的语义 | **不改配置**，只触发本轮重生成；事件里 `config_changed: false`，且**不进「配置修改频率」的分子** | 该按钮此前从未定义语义。§13.2 的飞轮假定每次反馈都回写配置，一个不产生配置变更的按钮混在里面，会让 §3.2 的「配置修改频率首 3 次后趋近于 0」**因为按钮没接通而达标** | 【评审指定】 | 2026-09-07 |
| F07 | 轴端点 | 已在端点再点同方向（如 P3 上点「太啰嗦」）→ 配置不变，返回 `config_changed: false`，**前端给一句说明** | **不静默吞掉**——静默吞掉会让用户以为生效了，也会在埋点里多一次假的配置变更 | 【评审指定】 | 2026-09-07 |
| **F08** | `f1_arm` 在哪里算、怎么算 | **数据库的 `auth.users` after-insert 触发器**里算，`md5(uid)` 首位十六进制二分（`0–7`→`pairwise`，`8–f`→`text`）。不用 `hashtext()` | 两条都不能由前端做：①前端算 hash 是「TS 一份 Python 一份必然漂」的复发（约束 3）；②用户对自己那行有 update 权限，**能改自己的臂**，AB 分组当场污染。不用 `hashtext()` 是因为它是内部函数，PostgreSQL **不承诺跨大版本稳定**——分组函数一旦漂，历史用户的臂归属不可复现，而 A5 的三个读数全部按臂分组。实测 400 个随机 uuid → 187/213 | 【提出】 | 2026-09-07 |
| **F09** | 建行失败时的行为 | **让注册整体失败**，触发器里不 try/except | 没有 `style_config` 行的用户是坏状态：他进不了 onboarding、拿不到臂。吞掉之后这个坏状态会在第一次讲解时以别的形态暴露，那时归因成本高得多 | 【评审指定】 | 2026-09-07 |
| **F10** | 改 `f1_arm` 时的行为 | **抛异常**（SQLSTATE `23514`），不静默改写回 `old` 值 | 静默改写会掩盖前端的真 bug，且与 F07「不静默吞掉」是同一条原则。合法客户端本来就不发这个字段——PostgREST 的 PATCH 只带 body 里的列，未出现的列 `new = old`，不触发本检查 | 【评审指定】 | 2026-09-07 |
| **F11** | RLS 验收的构成 | 每条「拒绝」断言必须配一条**「允许」反向控制**；涉及 insert 的断言**断错误码不断「有没有报错」** | 任务书原文「A 读 B 的行 → 返回空」**在 B 的行不存在时也绿**，在整表被收权时同样绿——单独拿出来是空转的（通则七 #5），已在 `supabase/verify_rls_local.mjs` 的 R3 演示。错误码那条来自一次实测发现：`user_id` 是主键且 F09 保证每个合法用户都已有行，冒名 insert 必然也撞唯一约束，**只断言「报了错」测的是主键不是 with check**——RLS 关掉后错误码从 `42501` 变 `23505`，断言照样绿 | 【提出】 | 2026-09-07 |
| **F12** | 反向验证的执行位置 | 正向验收在**生产**；「拆掉防护看它红」这类破坏性动作只在**本地**一次性实例上做，生产不 `disable row level security` | 生产上关 RLS 的窗口期内任何请求都能跨用户读写，代价与收益不对称。本地跑的是 `migrations/` 下的**原文**而非复制品——复制品漂掉之后，反向验证证明的就是另一个对象（通则七 #6） | 【提出】 | 2026-09-07 |
| **F13** | 档位 → 区间映射的唯一出处 | 只读 import `实验脚本/配置扫描实验/scan/points.py` 的 `AXIS_POINTS`；F1 侧不重写这四组数字，**TS 侧一个数字都不写** | 与约束 3（指纹不在 TS 侧算）同一个坑的另一个入口。注意 P0 的 30–120 不是 `points.py` 里的字面量而是 `StyleConfig` 的默认值（P0 的 `overrides={}`），走 `point.config().paragraph_length` 取值才自动正确。**本轮只读引用，不提升到生产模块**——当前只有一个消费方，触发条件见 §二 | 【评审指定】 | 2026-09-07 |
| **F14** | 合规承诺的可测量性 | PRD §12.1 的**「注销即清空」必须有一条对应断言**，且该断言要能被反向验证变红。本轮实现为：删 `auth.users` 的行 → `style_config` 的行必须随之消失（本地 `verify_rls_local.mjs`，反向验证 R6 把外键改成 `no action`）；生产侧由删除两个验收账号后 `count(*) = 0` 确认 | **合规承诺若无对应断言，它和一句没实现的话在生产上表现一样。** 本表刻意不给 delete 策略，「注销即清空」完全依赖外键的 `on delete cascade`——这句话写进了隐私政策，却从没有任何测量指向它。与 F11 同类：**承诺存在 ≠ 承诺被测量**（通则七 #1：凡是写成「已验证」的句子，必须能指出是哪次测量得出的）。推论：§12.1「需补充的措施」里其余各条（一键删除、异议处理留档）落地时同样要各配一条会红的断言，而不是只写进文档 | 【提出】 | 2026-09-07 |
| **F15** | 部署的前置条件要有断言 | **提交作者邮箱必须是 GitHub 上已验证的邮箱**，且这一条要有一条会红的检查（`web/scripts/verify_git_identity.mjs`），查的是 `gh api` 的 `author.login`——**Vercel 反查的同一个信号**，不是比对写死的常量 | Vercel 查不到账号就静默拦部署：代码没问题、构建没跑、没有一条错误指向这里，你以为在看新版本其实是上一次部署（通则六）。**比对常量的检查在 2026-09-08 那次事故里会是绿的**——邮箱没变，变的是「GitHub 还认不认它」；一个在事故发生时照样绿的检查就是没有检查。反向控制取一个已知反查不到账号的历史提交，要求它恒为 `null`。离线时默认判失败、放行须显式加 `--allow-offline`：跳过了却退出 0 的检查与它防的失败是同一类东西。**副作用要知道**：归属按账号当前已验证邮箱实时算，换邮箱后历史提交会一起变成不可归属，回滚/重新部署它们会撞同一堵墙 | 【提出】 | 2026-09-08 |
