# 检索评测集

F2 第二步的**前置**：一组问题 + 已知正确答案，用来比较不同检索策略。

**不做索引、不选模型、不写检索代码**——那是 2b。本目录只有数据与校验脚本。

| 项 | 值 |
| --- | --- |
| 规模 | **30 条** |
| 语料 | `实验脚本/测试集/` 的 3 份 OCW 课件（15.316 不出题，见 §4.3） |
| 金标准粒度 | **页** |
| 标注者 | **1 人**（无一致性数据） |
| 建立日期 | 2026-08-21 |

```bash
../../slicer/.venv/bin/python 校验.py   # 校验 gold 页、合规排除、标签一致性
```

---

## 1. 这个评测集能用来做什么

**比较同一标注者下的不同检索策略。**

具体地说，2b 之后要回答的第一个问题是 slicer TODO 记的那条：
**命中过短切片时，扩展相邻切片 vs 不扩展，哪个召回更好？**
没有这组数据，2b 做完只能肉眼看几条说「感觉还行」。

它能支撑的判断形如：

- 策略 A 与策略 B 在**同一批问题**上，谁召回的 gold 页更多
- 换 embedding 供应商后，`synonym` 类的表现是变好还是变差
- 扩展邻接链之后，`multipage` 类的完整命中率有没有提升

这些都是**相对比较**。相对比较不要求标注绝对正确，只要求标注**前后一致**——
同一个人、同一套标准、同一批问题，这个条件满足。

## 2. 这个评测集**不能**用来做什么

### 2.1 不能用来校准 judge

**没有一致性数据。** PRD §8.5 要求 judge 校准必须有 2 人独立标注算 Cohen's kappa，
本集是单人标注，**算不出一致率**。用它去校准 judge，等于用未经验证的标注去验证
另一个未经验证的工具。

（PRD §8.5 是 v1.1 的前置任务，与本集无关；此处写明是为了防止日后被误用。）

### 2.2 不能作为绝对召回率的依据

三条理由，各自独立成立：

| 理由 | 说明 |
| --- | --- |
| **n = 30** | 单个 tag 分组只有 2–18 条。任何「召回率 87%」的说法在这个样本量上都没有置信区间可言 |
| **单人标注** | 「答案在哪几页」由一个人判断，没有第二人复核。系统性偏差无从发现 |
| **语料单一** | 只有 3 份 OCW 课件、3 个学科，且 20/39 的 gold 页集中在 22.081J 一门。测出来的是「在这三份课件上的表现」 |

所以：**本集产出的数字只能用于横向比较，不能写进 PRD §3.2 的溯源率指标，
也不能作为 §8.4 上线达标线的依据。** 那两处要的是绝对值，本集给不了。

### 2.3 不能用来测讲解质量

金标准只标到「答案在哪一页」，不含参考答案文本。它测的是**检索**，不是生成。

## 3. 四类 tag

一条可以有多个 tag，故各类之和大于 30。

| tag | 条数 | 含义 | 预期 |
| --- | --- | --- | --- |
| `synonym` | **18** | 同义 / 跨语言表述。问题用学生的说法，课件用术语 | 应当命中。**这是选 embedding 的核心理由** |
| `multipage` | **9** | 答案跨多页，`gold_pages` 多于一个 | 应当全部命中，只中一页算不完整 |
| `figure_heavy` | **3** | 答案在图密集页（`char_count < 120` 且 `image_coverage_union ≥ 0.5`） | **预期失败**，见 §3.1 |
| `unreadable_page` | **2** | 答案在 `image_only` 页，解析后**不产生切片** | **预期失败**，见 §3.1 |
| `no_answer` | **5** | 课件里没有答案，`gold_pages` 为空 | 应当返回空或低分 |

`figure_heavy` + `unreadable_page` = **5**，即原定的「答案在图密集页」一类。

### 3.1 为什么把预期失败的样本放进评测集

**失败本身就是数据。** 这两类验证的是 PRD §10 兜底文案的必要性——
如果它们全部失败，就证明「这部分在第 N 页的图里，我读不了图」这句文案必须存在；
如果某些意外成功了，那说明图注文本比预想的更有用，第三步的图注通道优先级要提高。

**两类分开标，因为在用户侧的表现不同**，兜底文案可能要写两套：

| | `figure_heavy` | `unreadable_page` |
| --- | --- | --- |
| 页的 `kind` | `digital_text`（可用） | `image_only`（不可用） |
| 是否产生切片 | **产生** | **不产生** |
| 检索会发生什么 | 命中一个只有标题的切片，**答不了问题** | **直接返回空** |
| 用户看到什么 | 一段答非所问的讲解 | 什么都没有 |

前者更危险：它看起来成功了。

举例（均已人工核对页面图像）：

- `figure_heavy` Q027 → 14.129 p45，可提取文本 37 字符（标题 + 页码），
  而图里是一张连接损益表与资产负债表的完整流程图。
- `unreadable_page` Q029 → 14.129 p33/p34/p36，可提取文本各 **2 字符**（页码），
  而图里是应对 CAP 三难的三个模型（共同账本 / 单一账本 / 兼容账本），
  每页都有完整的论述文字——只是全被压进了图。

### 3.2 `no_answer` 的设计原则（不是偏好，是标准）

> **课件讲了这个主题，但没讲这个子问题。**
> 不收完全不着边的问题。

理由：完全跑题的问题（如在能源课上问「量子计算怎么做」）检索返回空是**白捡的**，
它测不出任何东西——任何检索器都能做对。有区分度的是**贴着覆盖范围边缘**的问题：
主题在课件里，答案不在。

本集的 5 条都按此标准出：

| id | 问的是 | 课件讲了什么 | 差在哪 |
| --- | --- | --- | --- |
| Q005 | 太阳能怎么储存 | p34/p35 讲了太阳能发电 | 全篇无储能 |
| Q016 | 没风时电网靠什么 | p32 讲了风电，并给出峰值 400 / 平均 130 MWe | 无电网调度与备用容量 |
| Q018 | 乏燃料怎么处理 | p26–p28 讲了核燃料与堆内反应 | 无后处理与废物处置 |
| Q019 | 各方案造价多少 | p5 把「是否做过成本效益分析」作为反思抛出 | 全篇无造价数据 |
| Q025 | 中国的规划怎么做 | p6/p9 有「全球视野下的规划史」 | 只讲欧美源流与殖民扩散 |

Q019 是最典型的一条：课件**主动提出了这个角度**却没有回答，检索器很可能命中 p5。

## 4. 建集方法与已知限制

### 4.1 不从切片文本反向生成问题

从切片里挑句子改成问句，检索必然命中——**测出来的是字符串匹配，不是语义检索，
而且分数会很好看。** 本集的做法是：先读懂课件讲了什么，再用学生会用的说法提问，
尽量避免直接复用切片中的关键名词短语。

对照几例：

| 课件的说法 | 本集的问法 |
| --- | --- |
| `heat engine efficiency`, `η=(1−Te/Ti)` | 为什么不能把热全都变成电 |
| `enrichment` | 为什么还要先加工一道 |
| `power density` | 同样一平方米各能出多少电 |
| `energy carrier` | 它本身算是一种能源吗 |
| `nonce`, `POW` | 「挖矿」机器到底在算什么 |
| 规划的 `stakeholder` / 授权 | 到底谁说了算 |
| `DESIGN tradition` / `EMPOWERMENT tradition` | 主要是画图纸的，还是跟各方博弈的 |

`校验.py` 会检查问题中的英文词是否出现在 gold 页原文里（当前 **0/30 有重合**）。
⚠️ **这只是机器化的下限**：它挡得住英文词的字面复用，**挡不住中文的语义复用**。
后者靠人工把关，没有自动手段。

### 4.2 学科覆盖：术语翻译 vs 概念口语化

跨专业的「同义」不是同一件事，两种都测到了：

- **工科**（22.081J）：术语 → 通俗量。`power density` → 「同样一片地发多少电」
- **文科**（11.201）：概念 → 口语。规划的授权与合法性 → 「到底谁说了算」；
  两大传统之争 → 「画图纸的还是搞博弈的」

后者更难：它没有一个可替换的名词，整句话的说法都不一样。

### 4.3 三条排除规则

| 排除 | 范围 | 依据 |
| --- | --- | --- |
| **15.316 整份** | 19 页全部 | 整份扫描件，`verdict = unusable`，解析层已拒绝，检索层根本拿不到。出题只会重复测一件已测过的事。第 3 类的「预期失败」改用 14.129 的图密集页与 `image_only` 页——那是**表面可用、实质读不了**的情形，更隐蔽也更值得测 |
| **14.129 的 8 页** | p10, p11, p25, p26, p31, p38, p40, p42 | 第三方保留权利内容（6 个权利人）。`测试集/SOURCES.md` 的处置要求：「用作评测输入时应跳过这些页」 |
| — | | 与第 3 类**无重叠**：图密集页是 p12/13/14/32/45/46/47，`image_only` 页是 p33–36 |

> **p31 的发现**：按 `© … All rights reserved` 直接搜只能搜到 **7** 页，而 SOURCES.md 记的是 8 页。
> 漏的是 p31——它的 `©` 与 `All rights reserved` 被解析切在**两个不同的文本块**里。
> 这是 PRD v2「课件内第三方版权声明识别与标注」的第一个实测反例，已记入
> `parse-service/TODO.md`。

### 4.4 `source_file` 而不是 `doc_id`

`gold_pages` 用 `{source_file, page_index}`，**不用 `doc_id`**。

原因：parse-service 的口径 P23 已确定**服务不产出文档主键**——按内容哈希做键等于
跨用户共享存储，违反 PRD §12.1。主键归持久化层。本集是离线数据，按文件名引用
`测试集/` 里的文件（与 `SOURCES.md` 的登记表对得上）；真跑评测时由上层把文件名
映射到各自的 `document_id`。

### 4.5 规模：30 条而非 §8.3 的 50–100

**这是一条「先不做」的决定，故记归属与理由。**

**由评审拍板**（2026-08-21），理由：语料只有 4 门课，问题池有限；30 条足以比出
策略差异。§8.3 说的 50–100 是针对**溯源人工标注集**的，那个集要支撑绝对指标，
本集只做相对比较，要求不同。

若日后要用本集支撑绝对指标，规模与标注方式都必须先改（见 §2.2）。

### 4.6 图密集页与 image_only 页的 notes 经人工核图

这两类页的可提取文本只有标题或页码，**光看解析输出写不出标注依据**。
本集的做法是把这些页渲染成图像逐张看过，notes 写的是图里实际有什么
（如 p33 的「Model 1 共同账本，取 A-P 边」、p46 的「六个住户调查、误差 16%–51%」）。

这一步不能省：否则 notes 就成了从上下文推测的猜想，而 notes 是这个集唯一的标注依据。

## 5. 数据格式

```jsonc
{
  "id": "Q003",
  "question": "同样占一片地，风电和太阳能哪个最后发出来的电更多？",
  "gold_pages": [
    { "source_file": "MIT22_081JF10_lec01b.pdf", "page_index": 32 },
    { "source_file": "MIT22_081JF10_lec01b.pdf", "page_index": 35 }
  ],
  "notes": "两页各给一半，且用同一面积基准：p32 风电…，p35 太阳能…",
  "tags": ["synonym", "multipage"]
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | `Q001`–`Q030` |
| `question` | 用户会怎么问 |
| `gold_pages` | 答案所在页，可多页；`no_answer` 为空数组 |
| `notes` | **为什么是这几页**，一句话。这是本集唯一的标注依据 |
| `tags` | 见 §3，可多个 |
