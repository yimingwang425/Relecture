# explain · 讲解对话链路（F3a）

AI 课件讲解助手 · **F3 第一步**。检索 → 讲解生成 → A 类三维审查 → 不合格重生成（上限 2）。
**不含 F3b 的三分类兜底判断**（留了插入点），**不含流式**，**不接 Supabase**。

**v1 的风格遵循度只有三个维度**：详细程度 / 引用长度 / 讲解语言一致性
（PRD §3.2「风格遵循度的 v1 定义」）。术语处理已下线，冗余句式未实现。

```bash
python3 -m venv .venv && ./.venv/bin/pip install -e ".[dev]"
./.venv/bin/python -m pytest        # 59 条，零 API 成本
```

核心链路**零第三方依赖**（与 a_rules 同一约定：PRD §9.2 的方案 C 要求审查能在
流式输出中按句并行执行）。两个可选依赖各自只被一个模块用到：
`retrieval_adapter` → `retrieval`，`llm.AnthropicModel` → `anthropic`（运行时 import）。

## 二、prompt caching：论断的前提在新架构下不成立

PRD §7.3 写「**课件内容会话内不变 → 必须启用 prompt caching**」。
**这句话的前提是课件全文在 system 里**——那是第 0 周的架构。

接检索之后：

| | 第 0 周 | 接检索后 |
| --- | --- | --- |
| 课件全文 | 在 system 里，约 5K token | **不在上下文里** |
| system 段 | 约 5K token，断点当然生效 | **实测约 406 token / 485 字符** |
| 每轮检索片 | 无 | 约 400 token，**每轮不同，天然不可缓存** |
| 还值得缓存的 | system + 对话历史 | **只剩对话历史** |

Sonnet 系的最小可缓存 prefix 是 1024 token。**406 < 1024，system 段的缓存断点
不生效，且不报错。** 这是「会静默改变数字」的形态，故：

- `prompt.system_cache_status()` 给出估算并写进 metadata
- `scan verify` 报「**未生效**」而不是「未命中」
- 实验报告必须单独回答一句：**接检索后 caching 还剩多少收益**

### 实测回来了（2026-08-26，180 轮）

system 段的缓存断点**确实没生效**；但**对话历史的缓存工作良好——第 2 轮起 78/78 命中**，
读取 1,188–27,228 token。成本结构：输出 63% · 缓存写 27% · 缓存读 10% · 未命中 0.0%。

**所以 caching 仍然要开，但理由变了：省的是对话历史，不是课件。**
PRD §7.3 已按此改写，并记为**第 5 次「被数据推翻的判断」**（`F2开发.md` §八）。

它与前四次的差别是**发现代价**：前四次要跑完实验才知道，
**这次一次量纲检查就够了**——406 与 1024 是两个确定量，不是统计结论。
这类假设值得单独归一类：**只需要一次量纲检查、却从没有人做过那次检查的假设**。
它们读起来完全合理，因为写下它的时候确实是对的；错的是它跟着架构一起变了，而句子没变。

## 三、X11 的一次性外部校验（A 验 B）

评审否决了用术语表识别括注（选项 A），但 A 仍然有用：**它没有参与形态规则的设计**，
是一个真正的外部参照（通则七 #3：自洽不是验证，要验证判据必须引入没参与设计的证据）。

在 `实验脚本/测试集/真实样本` 的六份真实讲解上比对（`tests/test_x11_crosscheck.py`）：

| | 处数 |
| --- | --- |
| 两者都认出 | **46** |
| 只有形态规则认出 | **49** |
| **只有术语表认出** | **0** |

**第三行是关键**：形态规则**没有漏掉任何一处术语表认得的括注**，
所以 D15 的立意在无术语表时没有被削弱。

**第二行不是 bug，是一个已经被独立测过的现象。** PRD §8.1 记过：
「实测六轮中模型产出 89 条中英括注，其中 42 条是术语表外的日常词
（电力/供暖/石油/全球变暖）」。46 + 49 = 95 ≈ 89（差额是跨度计数与出现计数的口径差）。
**两次测量互不相干却对上了**——这比任何一次单独的数字都更能说明规则在做对的事。

### ⚠️ 口径选择会不会改变 P4 的答案 —— 旧样本说会，但那份证据不能用

同六份样本上的中文占比：

| 口径 | 均值 | 最低 | 低于 0.95 |
| --- | --- | --- | --- |
| 无排除（v1 若不做 X11） | 0.9533 | 0.9055 | **2/6** |
| 仅术语表（选项 A） | 0.9653 | 0.9287 | **1/6** |
| **形态规则（选项 B，已采用）** | **0.9771** | **0.9606** | **0/6** |

- **P0 的阈值 0.85 上三种口径都不触发**，口径不咬人
- **P4 的阈值 0.95 上三种口径给出三个不同答案**

#### ⚠️ 但这张表**不作为 P4 口径敏感性的依据**（2026-08-22 评审指出）

**这六份样本测自第 0 周**，当时 `term_annotation` 激活、
prompt 里明确写着「专业术语首次出现时用『中文译名（English original）』标注」。
**v1 的 prompt 里 `term_*` 完全不渲染，没有任何一句话让模型写括注。**

所以上表那三个数的分歧**可能是旧 prompt 的伪影**：v1 下模型若几乎不写括注，
三种口径就没有分歧，P4 根本不口径敏感，这个话题自己就关掉了。

拿旧配置下的敏感性分析去解释新配置下的结果，是同一类错误的又一种形态——
**观测范围与应用范围错配**（通则七 #6）。上表留在这里，但它测的是
「D02 期 prompt 下的括注密度」，不是「v1 下的口径敏感性」。

**处置**：新增观察字段 `annotation_count`（与 D48 共用匹配器，零成本），
**三口径对比一律用本轮 transcripts 重算**。三个数都能从同一批数据事后算出，
不需要重跑：`chinese_ratio` 的 `details` 同时输出 `ratio_excluding_annotations`
与 `ratio_including_annotations`，选项 A 可在保存的 transcripts 上离线重算。

#### 用 v1 数据重算的结果（2026-08-26，n=180）

**那个话题没有自己关掉**——括注密度每轮平均 **2.73 处**、180 轮里 **114 轮有括注**，
尽管 v1 的 prompt 里没有任何一句要求它。

| 口径 | 均值 | 最低 | 0.95 下不达标 |
| --- | --- | --- | --- |
| 无排除 | 0.9423 | 0.8193 | **85** |
| 仅术语表（A） | 0.9454 | 0.8193 | **76** |
| **形态规则（B，采用）** | 0.9525 | 0.8193 | **59** |

**三口径给出三个不同的数，P4 确实口径敏感。** 采用的 B 最宽松，
所以 P4 的触发率里有一部分是口径给的——报告三数并列。

旧样本那张表的结论**方向相同**，但依据已换成本批次数据：
被否掉的不是那个结论，是那份证据的适用范围。

## 四、模块

| 模块 | 职责 |
| --- | --- |
| `llm.py` | 模型抽象 + 成本核算。**定价的唯一出处**（从 `漂移实验/drift/models.py` 提升；那边退化为再导出） |
| `context.py` | `ContextPack`：检索片 + `skipped_pages` + 签名。`Retriever` 协议 |

| `style_prompt.py` | `StyleConfig` → prompt 片段。**这是 F1 的接口形状** |
| `prompt.py` | system/messages 组装 + caching 断点 + 可缓存性检查 |

| `gap.py` | F3b 插入点 |
| `observe.py` | 观察项：分段规避探针 + 句级 verbatim 探针 |
| `pipeline.py` | 一轮的编排；`Trajectory` 持有轨迹状态 |
| `log.py` | 每轮一条 JSONL |
| `fake.py` | 段落长度可控的假模型，供 `--fake` 全链路 |

### 为什么 `llm.py` 从漂移实验提升上来

单价表带 **8/31 到期日**。复制一份就等于**两个到期日**——一个按时回落到正价、
另一个继续用 introductory 价，**而且两边都不报错**。§9.1 承诺的是报准单位经济，
那种偏差正是它最怕的形态。

`drift/models.py` 退化为再导出并保留它自己的 `FakeModel`（那个假模型模拟的是
术语标注率衰减，专为 D02/D44 而写，与 v1 无关，不该进生产包）。
`tests/test_llm_pricing.py::TestDriftStillWorks` 断言两边是**同一个对象**而不只是值相等——
值相等允许两份副本存在，而副本正是这次提升要消掉的东西。

## 五、继承自漂移实验的四条口径

逐条列出来源，便于回查：

1. **修正往返不进对话历史**——否则有审查组上下文更长，输入长度成为第二个变量
2. **无审查组照常计算指标，只记录不干预**——不算就没有对照
3. **重生成是反馈驱动，不是重试**——模型已移除 temperature，纯重试大概率复现同样的问题
4. **重复是整条轨迹的重复**——轨迹状态由 `Trajectory` 持有，每个 replicate 一个实例

## 六、已知限制

| 项 | 说明 |
| --- | --- |
| 首字延迟无数据 | 不流式，`latency_ms` 是完整响应时间。PRD §9.2 的「首字 < 3s」本轮**测不了**，日志写 `null` 不塞假数 |
| 分段规避 | `paragraph_length` 量的是**平均**段落字数，可被多敲回车平凡满足。本轮只加观察项（`observe.py`），判定不补——PRD §8.1 的「总输出长度」从来没有代码，按「未实现的维度不参与达标判定」不补判定 |
| `quote_length` 仍按引号猜 | 盲区是不加引号的整段照抄。本轮用 verbatim 探针取证，**先取证再决定要不要升级口径** |
| 无 F3b | `gap_verdict` 恒 `null`。PRD §10.1 的三种情况本轮一种都判不了 |
| 不接 Supabase | 走 retrieval 的本地路径 |
