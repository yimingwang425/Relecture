### 人工验收清单（部署后逐条走）

先按 F17 核对 `x-build-commit` 是不是你以为的那个 commit，再开始。

1. `pairwise` 臂账号访问 `/onboarding` → 应落到 `/onboarding/style`；`text` 臂 → `/onboarding/style-text`。**交叉访问对方的页面应被重定向回自己的臂**。
2. 主臂走完 6 步 → 收尾屏四条轴齐全 → Supabase 里那一行的四列与 `onboarded_at` 都变了。**断言库里那一行变了，不是「页面显示成功了」**。
3. 主臂第 1 步选左 / 选右，第 2 步应分别是 `detail_p0_p2` / `detail_p2_p3`（看展示的两段是否不同）。
4. 对照臂：写一段只提「讲细一点」的描述 → 确认屏上**详细程度**来自描述，**其余三条应显式标着「你没提到」**。
5. 对照臂：`ANTHROPIC_API_KEY` 不配时应报 503 且说明是服务端未配置（不是「请重试」）。
6. 设置页：改一条轴 → 保存 → 刷新后仍是新值。
7. 设置页反馈：`P0` 点「太啰嗦」→ 变 `P2`（**不是 P1**）；再点 → `P3`；再点 → **配置不变且给出一句说明**。
8. 设置页：「例子没懂」→ 配置一个字段都不变，且给出「不改配置」的说明。
9. devtools 全局搜 `sk-ant-` → 0 命中（判据的分辨力已由 `verify:build-guards` 先验过）。
10. **左右随机**：同一个账号连开两次 `/onboarding/style` 第 1 步，读 DOM 上的
    `data-left-variant`——多开几次应当**两个档位都出现过**。始终相同说明随机没生效
    （`verify:logic` 已验过函数本身，这条验的是它真的接在了页面上）。
11. **收回 insert 之后注册仍能建行**：新注册一个账号 → 它的 `style_config` 行应存在，
    `f1_arm` 与 `f1_assign_arm(user_id)` 一致。这是「客户端插不进去」的允许控制，
    **少了它，把注册一起打死也会全绿**。
12. ~~抄回 notice 行数~~ → **已执行，但结论是「未观测」**（口径 F34，见下）。
    有真实用户之后**重查一次** `select detail_level, count(*) from style_config group by 1`，
