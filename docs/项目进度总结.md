## 一、项目是什么

学生上传课件（PDF/PPT），提问，系统按**该学生的讲解风格偏好**生成讲解，并保证不超出课件范围地编造。

四个功能模块：

| 模块 | 做什么 |
| --- | --- |
| **F1** | 风格偏好采集（成对比较 onboarding + 反馈按钮）→ `style_config` |
| **F2** | 解析 / 切片 / 向量检索 |
| **F3a** | 讲解链路 + 三维 A 类审查 + 重生成 |
| **F3b** | 兜底判断（检索片够不够回答）+ 跳过页限定语 |
| **F4** | 跨会话记忆（「这部分没看懂」→ 下次换切入点重讲） |

## 五、工作方法（下一轮必须继承）

这套纪律是项目最值钱的部分，比代码难重建。

### 反向验证

**每条守卫都要当场演示能变红**：把被测逻辑换成平凡实现，断言必须红。不会红的断言是空的。报告里逐条记怎么让它红的。

F4 的八条、内测前的十条，都是这么验的。

### 判据的完整形式

不是「两端是不是自己写的」，是**「两端会不会一起变」**。

F4-P1 抓到的形态：守卫的写入侧和读取侧都不是手写字面量，但**都出自同一个 `slice_key()`**——分隔符一改两端一起改，断言照绿。同源就是空断言。

同形态的历史复发：护栏比自己的源码、人工清单比自己的字面量、嵌入器比自己的声明。

### 常见失败形态

| 形态 | 例 |
| --- | --- |
| **恒不触发** | F3b 原设计「跳过页 ∩ 命中页」恒为空集——跳过页不产生切片 |
| **恒触发** | 一个每轮都注入的限定语，输出看起来完全正常，只是每轮多说一句。**最难发现** |
| **空转通过** | 空表上 CHECK 通过，被读成「存量已确认」 |
| **NULL 通过** | `NULL = '0'` 求值为 NULL，而结果为 NULL 的 CHECK 是通过的（F67） |
| **说谎的字段** | `restricted_pages_excluded` 每次写 0，看似「检查过没有」，实为「从没检查过」（F69） |
| **副本漂移** | 口径表、页号、键拼法出现第二份 → 只改一处就是自己造的不一致 |

### 别的硬规矩

- **三行验证分开报，不合计**（F34）：api pytest / supabase verify / web verify:guards 各是不同性质的证据
- **DDL 执行成功只证明它能执行**，RLS 挡过一次、cascade 删过一行、幂等拦过一次，是另外的证据
- **先记数再操作**：删之前先记数、迁移之前先记数，否则「成功」与「本来就没有」分不开
- **迁移必须先于部署**：反了会静默失败（事件被 23514 全拒而接口照常 200）
- **验收要确认的东西，系统必须能自己答出来**（F53）
- **阈值必须有来源**，不要占位阈值
- **pydantic 一律 `extra="forbid"`**；埋点测试断言**表行数增加**，不是函数被调用
- **禁止 service role key**（F40）
- **不重抄一份实现/页号/拼法**——唯一出处

## 十一、2026-09-19 这一轮补记

### 1. 生成脚本与核对脚本判的不是同一件事（已修）

`verify_pairs.py` 判的是**成对关系**（详细程度那三对的隶属集合要不同，其余五对要相同），
而 `generate_pairs.py` 判的只是「这个样例自己达标就停」。两边判据不同源，于是：
样例次次「达标」，核对次次红在成对关系上，**重掷等于盲掷**——中不中取决于运气。

修法不是继续掷，是让生成侧 `from verify_pairs import measure`，用**同一个**隶属集合
函数判同伴关系（口径 F13）。修完当场就看见了它的必要：`depth_why_derivation.b`
第 1 次自身达标但成对不成立，**旧代码会在这里停下**，新代码接着掷到第 6 次才过。

### 2. P3 够不到区间，是提问的形态问题，不是判据问题

`detail_p0_p3.b` 在 71 次尝试里只有 6 次进过 P3（15–40 字/段）。中间怀疑过是 s3
的「去 AI 味」把短填充段删掉、抬高了段长——**查下来不成立**：同一天同一版 prompt 下
`detail_p2_p3.b` 拿到了 37.4。

- 「下定义」式的问题（「特征值是什么」）→ 成段论述，段落天然长；
- 「有哪几种情况」式的问题 → 模型写成 **bullet 清单**，而段落口径 D09
  **把连续列表项并成一段**（逐条计段会把均值人为拉低）。实测段长分布
  `[46, 28, 53, 23, **121**, 54]`：其余五段本来都在区间内，是那个并起来的 121 拉高的。

### 1. 整份读不出文字的课件不再入库

会被判 `duplicate_in_course`，用户连重试都做不到。

判断落在 `api/`，不落在 parse-service（P08：解析层如实报告，**不替用户拒绝**）。
新增分类 `no_usable_text`，与 `unparsable` 分开——**做了 OCR 之后这一类会消失，
那一类不会**（与 `pptx_not_implemented` 当初分出来同一个理由）。

顺带修掉两条会说谎的判据：`test_upload_events.py` 的 SQL 解析钉死在旧迁移上
（`create or replace` 之后它跟一份不生效的定义比）；`verify_style_logic.mjs` 那条
「SQL 少一类 → 比对变红」用的是 `replace`（只删第一处），两份定义并存后**它自己
空转了**，当场红了一次。

### 2. 顶栏拆掉，课程页变工作区，对话终于能存下来

**在这之前对话只活在浏览器内存里**，刷新就没；`/explain` 无状态，所以
`Trajectory.history` 在生产链路上恒为空——追问没有指代对象，而「平均会话轮次」
（北极星指标）只能按 `session_id`（= 一次页面加载）算。

新表 `conversations` + `messages`，两条写入路径刻意分开（标题是纯 UI 状态归浏览器；
`round_id` / `turn_index` / 答案正文归服务端）。⚠️ 如实登记：数据库**分不出**
我们的服务端与浏览器（服务端带的是用户自己的 JWT，F40），所以那条分工是代码约定，
不是数据库护栏。

前端：顶栏整个删掉（它并排摆着三件使用频率差量级的事），课件与会话进侧栏，
风格与退出进新的 `/settings`；轮次改正序、等待动画改小号贴左上角；
「还没有提问」那张卡去掉。判据跟着搬（十二节读的页面改到 `courses/[id]/page.tsx`），
不是跟着关。

### 3. 样例太长 —— 真正的原因是**产品的回答本来就这么长**

用户：「面对一大段文字只觉得是 2 个不同的东西，分辨不出来。」

先试了两条都**没用**，记下来免得再试：

| 试过什么 | 结果 |
| --- | --- |
| 把非目标轴五对的背景档从 P0 换成 P2 | 长度几乎没变（491/384 → 447/419），`depth_why_derivation` 反而从 450/532 长到 597/592 |
| 把问题收窄成「答案本来就短」的那种 | 仍然 370/469 字 |

原因是：**prompt 里只有「每段多长」，没有「整篇多长」**。段落区间管的是粒度，
模型只是把同样多的内容多分几段。于是「详细程度」这条轴实际上只管段落粒度，
而用户以为它管长度——他选「精简」，拿到的还是一屏。

改法是给风格要求加一行**整篇长度**（`render_total_length_rule`，
= 每段上限 × 3，随档位变、从一个数推出来）。它加在生产侧的包装
`render_all_style_rules` 里，**不动 `render_style_rules`**——配置扫描实验的 180 轮
数据锚在那个函数上。`SYSTEM_TEMPLATE_VERSION` s3 → s4（那一行不在模板里，
但渲染出来的 system 变了，版本号是「样例是否过期」的唯一信号）。

结果：16 个样例平均 **230 字**（此前约 430），127–383 字；
开头去描述片段的从 4/16 降到 **0/16**（那 4 处的共同原因是问的东西那块片段答不上来，
改了两对的提问与喂料）。`verify_pairs.py` 绿 30 · 红 0。

⚠️ **这是一次产品行为的改动，不只是样例的改动**：所有讲解都会变短。
方向与用户此前提的「去 AI 味、不赘述」一致，但影响面比「改样例」大，写在这里。

## 十四、2026-09-21：`Failed to fetch` 其实是冷启动

### 发生了什么

建课报 `TypeError: Failed to fetch`，前端那句话写的是
「可能是它没部署，或 CORS 里没有本站来源」。于是排错去了 Render 控制台
（服务好好的，`4f25a36` 已部署）和白名单（生产域名与 localhost 都在里面）。

**两个猜测都不对。** 真实原因：Render 免费层 15 分钟休眠，休眠后的第一个请求
打在 Render 的**边缘**上，而它在容器起来之前返回的错误页**不带 CORS 头**——
浏览器于是把它报成 `Failed to fetch`，与「CORS 没配」「服务没部署」长得一模一样。

实测佐证（带 Origin 打预检）：

| 来源 | 结果 |
| --- | --- |
| `https://ai-courseware-assistant.vercel.app` | 200，头齐全 |
| `http://localhost:3000` | 200，头齐全 |
| preview / 带斜杠 / www 前缀 | **400，一个 CORS 头都没有** → 浏览器报 Failed to fetch |

### 改了什么

1. **`/health` 报出 `cors_allow_origins`。** 这些来源本来就是公开网址，
   说出来换到的是：「我这个域名在不在白名单里」从猜谜变成事实。
2. **`ApiWarmup`**：打开首页或课程工作区时就去 `/health` 叫醒它，按递增间隔
   重试 6 次。**醒着时页面上不多一行字**；在叫醒时显示「这期间建课与提问会失败」；
   彻底叫不醒时把服务端地址、本站来源、原始错误一起摆出来。
   这是 F74 记的「keep-alive」那一半，**只在有人真的打开页面时做**——
   不需要定时任务，也不花钱。它**不是调大超时**（那是把症状藏起来）。
3. **建课失败的文案不再猜**：先说休眠（最常见的那一种），再给出一句话分清楚的
   办法（对一下 `/health` 里的白名单）。

### 教训

**一句「可能是 A，或者 B」的错误提示，在 A 和 B 都不对的时候，比没有提示更糟**——
它会把排错引向两个死胡同。判据不该猜；猜不出来时，要么把能查的事实摆出来
（白名单、本站来源、原始错误），要么说「不知道」。
`verify:logic` 第十九节钉住了这一条。

## 十六、2026-09-22 第二轮：清废弃代码

### 删了什么

| | |
| --- | --- |
| 路由 | `app/onboarding/style/`（比较臂）· `app/onboarding/style-text/`（文字臂） |
| 库 | `lib/style/pairs.ts` · `lib/style/flow.ts` |
| `taste.ts` | `plan` / `stepAtWithPriors` / `reachablePairIds` / `configFromPicksAndTone` / `LEGACY_REACHABLE` / `Step` / `Picks`（129 行） |
| `events.ts` | `pairShown` / `pairChosen`（42 行） |
| `next.config.ts` | **Turbopack 根目录上提那一行** |

`next.config.ts` 那一行值得单说：它当初只为 `lib/style/pairs.ts` 要 import 仓库根下的
`f1_samples/pairs.json` 而存在。删掉它连带去掉了两项代价——文件监视范围不再是
整个仓库，以及**部署不再依赖 Vercel 的 Include files outside the Root Directory**。
那是一条隐形前提：关掉它构建会 Module not found，而没人会想到去看那个开关。

### ⚠️ 清理时逮到一个我自己造的静默回归

`style_onboarding_completed`（**A5 预登记的 onboarding 完成率**）原来由比较臂与
文字臂的收尾屏发。2026-09-20 把开场改成只剩标签页之后，**没有人再发它了**——
那个指标的分子从此恒为 0，而且不会有任何东西报错。

发现它纯属偶然：正要删的那两个文件上，恰好挂着「这两页发了这个事件」的断言。

**教训**：判据写成「**哪个文件**发了这个事件」时，文件一换它就跟着失效，
而失效的样子是「那条断言随文件一起消失」，**不是红**。

已补上：标签页现在发这条事件，`steps_completed` 记的是**用户真的动过的板块数**
（0–2），不是板块总数——总数是常量，记常量等于没记。

### 判据是搬走的，不是关掉的

删掉的断言全部满足一个条件：**被测对象不存在了**。留着它就是在验一段没人跑的
代码，而一条永远绿的断言比没有断言更危险。凡是纪律还在、只是载体换了的，
一律改指向：

| 原来指着 | 现在指着 |
| --- | --- |
| 三个页面各自抽 `session_id` | 标签页 / 设置页 / 课程页 |
| 「名单含 `makeFlips`」 | 「名单是扫出来的且非空」（写死名字下次改名就空转） |
| 反向控制用 pairwise-client 的修复前版本 | 自造一段同形源码（用**现存**的随机源——用已删函数名的话这条控制自己空转，实测当场空转过一次） |
| 队列断言用 `pairShown` / `left_variant` | `tasteShown` / `payload 原样带过去` |
| 三方一致（Python ↔ flow.ts ↔ pairs.json） | 两方（TS 那一边随比较页没了） |

另外加了一条**显式断缺口**的：「前端不再发的事件类型正好是成对比较那两个」。
不断的话，哪天有人误删一个还在用的构造器，那个循环会安静地少验一个事件。

### `axes_from_default` → `axes_kept`（迁移 20260922100000）

这个字段列的是「描述里没提到的轴」。原来的处置是「没提到 → 回落默认档」，
名字对得上；矫正搬进讲解之后处置变成「**保持当前值**」（F84），
于是这个名字的含义**反了**。

⚠️ **历史行仍是旧键**（F10 不回改），分析时要并起来读：

```sql
coalesce(payload->'axes_kept', payload->'axes_from_default')
```

这是改名的真实代价。不改的代价更大：一个说谎的字段名会让每个读它的人
得出相反的结论，而没有任何东西会提醒他。
