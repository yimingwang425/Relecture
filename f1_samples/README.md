# f1_samples · F1 风格获取的生产资产

**这是生产资产，不是实验产物**——所以不在 `实验脚本/` 下。
`explain` / `retrieval` 在运行时读这里的 `pairs.json`，而不是反过来。

| 文件 | 内容 |
| --- | --- |
| `README.md` | **F1 口径决策表**（下 §一），全项目唯一一份 |
| `synthetic_deck.md` | 自写合成课件片段（英文，Bloom filter，503 词）。文件头写明**为什么这个主题撑得住四条轴**——换素材时照那一节判断新素材够不够格 |
| `style_axes.py` | 四条轴的取值、默认值、prompt 片段。A 类走 `explain.style_prompt`，B 类措辞在这里 |
| `generate_pairs.py` | 样例生成（口径 F18/F19）。`--pairs <id>` 重生成指定的对 |
| `pairs.json` | 8 对 / 16 个预生成样例 + 完整元数据 |
| `verify_pairs.py` | 三维核对 + 反向验证（调用 `a_rules`，零 API 成本） |
| `render_manual_review.py` → `manual_review.md` | B 类人工核对清单（**生成物，会被覆盖**） |
| `manual_review_result.md` | 人工核对结论（**手写，脚本不碰**） |
| `spend_log.jsonl` | 每一次真实调用的花费流水，**含被丢弃的重生成** |
| `_paths.py` | 包路径注入，与 `scan/_paths.py` 同一约定 |

```bash
# 生成（凭据局部注入，不要全局 export——全局会让 Claude Code 从订阅切到 API 计费）
env $(grep -v '^#' ../实验脚本/配置扫描实验/.env | xargs) \
  ../实验脚本/A类规则计算脚本/.venv/bin/python generate_pairs.py

# 核对（零 API 成本）
../实验脚本/A类规则计算脚本/.venv/bin/python verify_pairs.py
```

## 三、阶段 2 的发现与代价（登记，不自行处理）

### 发现 · P0 与 P1 在档位轴上分不开 —— 第 2 次比较可能在问一个没有答案的问题

`detail_p0_p1` 那一对**连续 8 次生成都没过隶属集合判据**。这不是运气：

| 尝试 | P0 字/段 | P1 字/段 | 隶属集合 |
| --- | --- | --- | --- |
| 1 | 85.7 | 57.7 | 都是 `{P0, P1}` |
| 2–3 | *（当时没逐次记数，只记了红/绿）* | | 都是 `{P0, P1}` |
| 4 | 76.0 | **81.1** | 都是 `{P0, P1}` |
| 5 | 66.1 | 65.7 | 都是 `{P0, P1}` |
| 6 | 63.6 | 70.8 | 都是 `{P0, P1}` |
| 7 | 86.4 | 69.8 | 都是 `{P0, P1}` |
| 8 | 72.2 | 65.1 | 都是 `{P0, P1}` |

**结构性原因**：`P1(40–90)` 完全被 `P0(30–120)` 包含，而模型在这两条指令下的
自然段落长度都落在 40–90 里。这与项目自己的先验一致——`scan/points.py` 给 P1 的
定语就是「**自然中枢仍在区间内**，只是余量收窄」。P1 被设计成一个模型不必改变行为
就能满足的轻微偏离，那么 P0 与 P1 的输出长得像，是这个设计的**直接推论**而不是意外。
第 4 次尝试里 P1 甚至比 P0 更长（81.1 vs 76.0），方向都是反的。

**产品侧的后果**（这才是要紧的那一半）：onboarding 的第 2 次比较，
在用户第 1 步选了 P0 之后给他看 P0 vs P1。如果 A 类指标分不开这两个样例，
**很难相信用户分得开**——那次点击拿到的更像噪声而不是偏好。而 F1 的全部产出
就是这个归因（F01）。

**不自行处理**（任务书指定）。三条可能的路，各有代价，需要拍板：

| | 做法 | 代价 |
| --- | --- | --- |
| A | 维持现状，把这一对的红留在 `verify_pairs.py` 里 | 一条长期红的守卫会被习惯性忽略，然后所有红都不再有人看 |
| B | 第 2 次比较改成 `P0 vs P2`（跳过 P1） | 二分粒度变粗；且 P1 是否还该留在轴上就要重答 |
| C | 把 P1 的区间收窄到与 P0 真正可分 | 那是改实测点位——`points.py` 的四组数字有实测依据，改它要重新论证 |

我倾向 **B**：它不动实测点位、不放宽判据，代价（粒度变粗）是可说清的。但这是产品决策。
