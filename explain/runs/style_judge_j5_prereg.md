# 风格审查员 j5（分档打分 + 阈值）· 评测 · 预登记（2026-10-13）

**本文件在跑 j5 的任何一次真模型之前写下并提交。** 结果出来后不改本文件；偏离写在结果文件里。

## 为什么

j3 误报 61%、j4 抽测 6/10。免费重算显示误报里只有约 7/39 只涉及非目标轴，标签混杂解释不了大部分误报——
审查员本身偏严。j5 不再让模型直接说「打回 / 放行」，改为**每个方面打偏离分**（0 符合 / 1 小出入 / 2 明显 / 3 严重），
**由代码按阈值决定打回**：阈值成了一个可以在数据上选、而且选法可以写清楚的旋钮。

## 数据与切分（选阈值的数据不报成绩）

- 条目：与 j2 / j3 完全相同的 168 条（`style_review_eval.build_items()`，讲解不重新生成）。
- **开发集**：问题 m01–m04 的「符合」32 条 + 「偏离」32 条。**只用来选阈值。**
- **留出集**：问题 m05–m08 的「符合」32 条 + 「偏离」32 条，加冲突 20 条、冲突对照 20 条。**只在这里报成绩。**

## 阈值的选法（预先定死）

候选阈值 {2, 3}（「最高分 ≥ 阈值 → 打回」）。在**开发集**上：
1. 取开发集检出率 ≥ 70% 的候选里，开发集误报率最低的那个；
2. 都不满足 70%，取（检出率 − 误报率）最大的那个。

选定的阈值写进 `style_review.REWRITE_THRESHOLD`，上线。另一个候选在留出集上的数也一并报，不藏。

## 报什么

- 留出集：误报率、检出率、冲突放行率、冲突对照打回率（选定阈值，以及另一个候选）；
- 开发集上两个候选的数（说明阈值是怎么选的）；
- 失败条数（按放行计）、单次成本、延迟。
- 预算：这一跑约 $1.4，上限 $1.6。
