## 必须遵守的既有纪律

1. 不开分支，只用 main。commit 前缀 `feat(web)`。
2. **随机与副作用不要写在客户端组件的 `useState` 初始化里**——SSR 和 hydrate 会各跑一次，导致服务端与客户端不一致。本轮如无随机需求则不适用，但改动到已有组件时不要引入。
3. **事件必须走 `createEventQueue`**（退避重试 + sessionStorage 跨页面存活）。不要直接发 POST：浏览器会自动重发幂等 GET，但**不会自动重发 POST**，丢了就没了。
4. 事件的 `user_id` / `arm` / `session_id` / `schema_version` / `created_at` / `deck_id` **是列，不在 payload 里**。写 payload 时不要重复塞。
5. 服务端比客户端旧要响亮失败。新增字段时确认 API 侧已经认得它。

## 做什么

### 1. 第五个反馈按钮

在讲解页每轮下方现有的四个反馈按钮区加第五个：**「这部分没看懂」**。不新建组件。

点击行为：

```
POST /api/v1/marks  { round_id, slice_ids, question }
  成功 → 按钮变为「已记下」并 disabled（本轮内不可再点）
  失败 → 按钮恢复可点，不静默吞掉
```

`round_id` 与 `slice_ids` 来自本轮 `/explain` 的响应（P1 已保证返回）。

**不做取消**（口径 F60）。**不做跨刷新回显**——刷新后按钮回到可点状态，重复提交由后端幂等挡掉。

### 2. 文案必须把它和「讲太深」分开（口径 F56）

这是本轮最容易出错的一处。两个按钮语义接近，用户点错不会有任何指标变红——
配置会被一路改深，而没人知道。

| 按钮 | 作用域 | 持久性 | 改配置 |
| --- | --- | --- | --- |
| 讲太深 | **全局**，深度轴下移一格 | 永久，影响之后所有讲解 | ✅ |
| **这部分没看懂** | **局部**，只影响本轮命中的那几片课件 | 下次讲到这部分时生效 | ❌ |

文案要把「以后都」和「这次这里」说开。具体措辞你定，但两个按钮的说明必须放在一起能看出区别，
不要一个写在 tooltip 一个写在按钮上。

### 3. 埋点事件 `confusion_mark_created`

进现有那张 `event_type` + `payload jsonb` 的表，**不建新表**。

| payload 必需字段 | 来源 |
| --- | --- |
| `round_id` | 本轮响应 |
| `slice_ids` | 本轮响应 |
| `mark_count_after` | `POST /api/v1/marks` 的返回值 |

必需字段清单要登记进既有的必需键出处（和 F1 五个事件同一处，不要另开一份列表）。

**这个事件不改配置**：`config_changed: false`，**不进「配置修改频率」的分子**（F41），
形态与「例子没懂」（F06）一致。

### 4. web 测试

- 按钮点击 → 发出请求 → 成功后 disabled
- 请求失败 → 按钮恢复可点
- 事件带齐三个必需字段
- 事件走的是 `createEventQueue` 而不是裸 POST（**把队列换成空实现，断言必须红**）

### 5. 人工验收清单

写进 `docs/F4/` 下的一份 md。要求：

- **判据跑前定死**，不写「点几次看看」这种。
- **标出执行顺序的依赖**：要有 `round_id` 才能点按钮，所以必须先完成一轮讲解；
  注入效果要在**第二轮**才看得到（同一课再问一次同一片内容）。
- **标出不可逆步骤**。
- 至少覆盖：
  1. 点击后按钮变「已记下」，刷新后回到可点，再点一次数据库里仍是一行
  2. 标记后再问一次会命中同一批切片的问题 → 请求里含限定语
  3. 问一个**完全不同**、命中其他切片的问题 → 请求里**不**含限定语（这一条是防注入恒触发的，不能漏）
  4. 事件表里多了一行 `confusion_mark_created`，三个字段齐全
- 第 2、3 条怎么看到「请求里含不含限定语」：给出具体查法（服务端日志字段 / 调试接口，哪个现成用哪个）。**不要让我去手查数据库拼字符串**。
