## 二、口径的演化

这一节是本文的主体。**同一件事改过几次、为什么改**，比最终值本身更有参考价值。

### 被数据推翻的判断（截至 2026-08-21，四次）

| # | 我判断的 | 数据说的 | 推翻的是什么 |
| --- | --- | --- | --- |
| 1 | 图注术语正文未出现，模型讲解时也不会提，不必收（§2.2） | 图注术语占分母 **42%**，图密集章节 83–87% | 对**课件**的假设 |
| 2 | 风格漂移是「对话变长后衰减」（PRD §2） | 无审查组第 1 轮标注率**全部为 0**，不是衰减是一次没做 | 对**模型**的假设 |
| 3 | 检索是压成本的主要手段（§2.9） | 输出 token 占 **68%**，成本主体是重生成 | 对**成本结构**的假设 |
| **4** | **G1 用「常用词表」近似领域限定性即可**（`glossary/README.md`） | **正文通道召回率仅 17%**，`heat engine` `power density` `energy density` `waste heat` `solar constant` 等成片被砍 | **对自己方法的假设** |

**第 4 次与前三次性质不同。** 前三次推翻的是我对课件、模型、成本的**外部假设**——
那类错误是 0→1 项目的常态，测了就知道。第 4 次推翻的是**我自己设计的判据**：

G1 的实现要求「单词候选不在常用词表内；多词组合仅当**全部**成词都是常用词时才拒绝」。
问题在于，本领域的术语大量是「常见词 + 常见词」的组合——
`heat engine`、`power density`、`waste heat`、`solar constant`、`energy carrier`
的每一个成词都是通用英语高频词，组合起来才是术语。
于是这条判据**在自己的语料上系统性地砍掉了目标对象**。

正确的方向已经清楚：**多词组合本身就提供了领域限定，不该要求每个成词都不常见。**
但这条修法**不在本次做**——见 `glossary/TODO.md`：在同一门课上验证修得对不对，
就是第 6 轮迭代，而第 6 轮的收益是负的（数字更好看、可信度更低）。
该 TODO 的触发条件是**有第二门课的独立金标准**，不是「有空时改」——
**它的前提是新数据，不是新想法。**

这一次也说明：**自己设计的判据同样需要被数据检验**，而且更难发现——
外部假设错了会有反常现象提示你，自己的判据错了只会安静地少收东西，
看起来像「提取得比较保守」。

### 2.1 术语表判据：五条 → G2 拆双侧

**第一版**：五条判据（领域限定 / 匹配无歧义 / 讲解必要 / 翻译有障碍 / 非专有名词），
从 22.081J 能源课提出 27 条正文术语。

**跨学科验证推翻了其中一条。** 用 14.129（区块链金融）跑同一套判据，G2「匹配无歧义」
把 `block`、`token`、`consensus`、`velocity` 全部排除——**这门课的核心概念一个不剩**。
最硬的证据是同一文档内两种词义并存：p4「signed blocks」是技术义，p20「the basic
**building block**」是日常义。

根因是判据混淆了审查对象：**匹配发生在中文讲解文本上，不是英文课件上**。`block` 英文
裸形有歧义，中文「区块」没有。

**修订**：G2 拆为 G2-en / G2-zh，任一侧无歧义即可收录，条目记 `match_anchor`。
10 条触发 G2 的词里 6 条被救回。

**回溯检查**：22.081J 的 44 条 `match_anchor` 全为 `both`，不需重建。这本身是结论
——**判据的脆弱性是学科相关的**：能源术语以复合名词短语为主，天然不与日常词碰撞；
金融/CS 把日常词赋予精确技术义，G2 会在核心概念上密集触发。只用一门课验证判据必然过拟合。

### 2.2 图注术语：不收 → 收（我判断错了）

**我的第一版判断**：16 条术语只出现在示意图标注里，正文一次未提。建议 v1 不收，理由是
「图注术语正文未出现，模型讲解时大概率也不会提，进不了分母」，且收了会让人工表与自动
提取表出现系统性差异。

**这个判断是错的，而且方向反了。** 实测：

| 轮次 | 术语出现总数 | 其中图注词 |
| --- | --- | --- |
| 第三轮（火电厂流程） | 31 | **87%** |
| 第五轮（压水堆结构） | 34 | **83%** |
| 六轮合计 | 166 | **42%** |

原因：那两页课件的**实质内容就在示意图里**，正文只有一句标题。模型讲这部分时，除了
图注里的词没有别的词可用。若当初不收，这两轮会各自丢掉八成以上分母，直接退化为无观测。

同时我把两个数混为一谈了：**「术语表相对课件的覆盖缺口」与「讲解文本相对术语表的分母
缺口」是两回事**。加 `source` 字段（`body_text` / `figure_caption`）后一份数据可算两种口径。

### 2.3 术语表：v1.0（44 条）→ v1.1（+6 变体 + accepted_annotations）

六轮真实文本实测发现 **9 条译名变体漏匹配**，方向是**把合规判成违规**：

| 模型写 | 术语表只有 |
| --- | --- |
| 能源密度 / 裂变 / 富集 / 增殖反应堆 / 光热 / 燃烧室 | 能量密度 / 核裂变 / 铀浓缩 / 增殖堆 / 光热发电 / 炉膛 |

另有 3 次「汽轮机（turbine）」——不是变体缺失，是**术语映射冲突**（汽轮机挂在
`steam turbine` 下，`turbine` 的译名是涡轮机）。加 `accepted_annotations` 字段：
只在括注内生效、永不参与自由文本匹配、逐条显式列举。不做「接受中心词」的通用规则
——那会让 `descent` 通过 `梯度下降` 的检查。

术语表自 v1.1 起冻结，实验期间不改。

### 2.4 中文占比：对称区间 → 单侧下限

**第一版**：`0.85 ± 0.05`，对称区间。

**改为**：`≥ 0.85`，只设下限。两条理由——要检测的是「开始说英文」，不存在「中文太多」
这种失败模式；上界会与术语维度**重复计量**（`translate_with_source` 要求写括注，括注
英文本就压低中文占比，两个维度会给出方向相反的信号）。

`TargetBand` 随之整个替换为 `MinRatio`，旧 schema 显式报错而非静默按默认值跑。

### 2.5 段落长度：60–180（占位）→ 30–120（实测校准）

第一版是我拍脑袋填的。六轮真实讲解实测均值 41–75 字，据此改为 30–120。
这是全项目唯一一个**由实测校准**得来的阈值。

### 2.6 分母护栏：无 → 5 → 实验覆盖为 2

**加护栏**：某轮首现术语数太少时，标注率只能取 0% 或 100%，没有分辨率，却会把一个
极端值贡献进曲线。实测第四轮只有 1 个首现术语。故加 `term_min_occurrences=5`。

**实验侧覆盖为 2**，生产保持 5。理由不是精度而是**有效性**：若为满足护栏去挑术语密集
的提问，20 个问题就不再是真实学习行为的样本，测出来的会是「术语密集提问下会不会漂移」
而非「真实使用中会不会漂移」——适用范围被悄悄收窄。护栏是为单次生产判定设计的；实验
有 3 条轨迹可合并，低分母噪音会被部分平均掉。代价是低分母点可信度低，故逐轮记录首现
术语数，图上标 ▽。

### 2.7 术语首现的作用域：每轮（D02）→ 整段对话（D44）

**这是全过程中最重要的一次修正。**

追查「重生成为什么不收敛」，先发现该说法不准确——28 个触发轮次里 26 轮改善、0 轮持平。
但第 2 次重生成平均只 +0.113，且 **8/19 次完全无变化**：触顶失败的轮次中，第二次产生的
违规集合与第一次**逐字相同**，模型到了不动点。

查那些反复修不掉的术语：**57% 在同一轨迹的更早轮次里已被正确标注过**，8 个卡住的轮次
里 **6 个是 100%**。

模型在做一件合理的事：术语在对话里首次出现时标注，之后不再重复。而指标每轮重置。

**这不只是作用域写窄了。** PRD §2 的 P1 明确把「太啰嗦」列为痛点，产品目标是讲解符合
用户认知习惯。**要求同一术语每轮重复标注，正是在奖励一个让用户体验变差的行为——指标
方向与产品目标冲突。**审查 agent 按这个指标逼模型变啰嗦，而重生成又是成本主体：一个
方向错了的指标，同时制造了质量问题和成本问题。

**修正**：首现按整段对话计。排除依据是「**已被正确标注过**」而非「已出现过」——后者会让
一个始终未标注的术语几轮后永远逃出检查，义务凭空消失。函数仍是纯函数，已标注集合由
调用方跨轮累积后传入。新旧口径并排输出，不覆盖。

配置版本 v1.0 → v1.1，指纹 `b50218965f4c` → `bbef8c831592`，新旧批次不会被误合并。

### 2.8 实验设计：20 轮 → 15 轮；1 次 → 3 条独立轨迹

**轮次**：15 轮取自真实复习序列。凑到 20 需要编造提问，样本会偏离真实学习行为。

**重复**：最初每条件每轮 n=1。当前模型已移除 `temperature`，采样随机性无法消除，n=1
分不清漂移与噪音——六轮探路数据的 53.6 → 75.0 → 23.1 → 0.0 → 56.2 → 20.0 就是预演。

改为 3 次重复时，语义又改了一次：**重复必须是整条轨迹的重复，不是轮内重采样**。同一条
对话里对某轮采 3 次再挑一条继续，轨迹仍是单次实现，只是给单个点加了误差棒。

**误差带取全距（min–max）而非 ±1SD**：n=3 时样本标准差极不稳定，±1SD 会暗示一个并不
存在的分布假设。

### 2.9 成本模型：正价 → introductory 价；检索归因 → 重生成归因

**第一次错**：定价表用了 `claude-sonnet-5` 的正价 $3/$15，理由写的是「宁可高估也不要
在达标判定上乐观」。实测差近两倍。**那个理由是错的**——§9.1 承诺的是报准单位经济，
高估不是安全，是错。改为 introductory 价 $2/$10 并带到期日，8/31 后自动回落。
单轨 $1.0971 → $0.7314，与后台对上。

**第二次错**：把检索列为压成本的主要手段。实测不支持——输出 token 占成本 **68%**，
检索只作用于输入侧，输入压到零也只省 32%。**成本主体是重生成**：62% 的触发率使有审查组
的实际生成次数翻倍（92 次 vs 45 次）。

### 2.10 成本目标：保留 $0.05 → 改归占位待定

发现实测 $0.590 超目标 11.8 倍时，第一反应是「工程没做好」。复查后发现，**这个 $0.05
和「20 轮」「85%」一样，是初版随手填的占位值，从未从定价模型推导过**。

按阈值来源规则应重新推导，而不是保留、也不是放宽：

```
单会话成本上限 = 月付价 × (1 - 目标毛利率) ÷ 月均会话数
```

参考推算（仅标定量级）：月付 ¥19.9、月均 8 次、毛利 50% → 约 $0.17。实测与之差 3.5 倍
属可优化距离，与 $0.05 差 11.8 倍则不是工程问题。

### 2.11 B 类维度：计划做 → 移入 v1.1

v1 的风格遵循度只算 A 类。B 类依赖低成本模型判断，而 judge 的可靠性需人工标注的
ground truth 验证；校准前使用等于把**未经验证的测量工具的输出**当作指标。
**宁可指标覆盖面窄，不可指标来源不可信。**

## 三、抓到的 bug

这些**都不会报错**，只会静默改变指标——这是本项目最该记住的一类风险。

| bug | 后果 |
| --- | --- |
| `^` 与 `Pattern.match(s, pos)` 叠加 | 只有出现在文首的术语能被识别为「已标注」，其余全判违规。**误判方向与真相相反** |
| 空输出被判「全部达标」 | 其余三维在空文本下无法计算，`quote_length` 返回 0/达标使其成为唯一计分项——生成失败会在曲线上变成满分点 |
| 批量输入按文件名排序 | 中文数字按码位排，得到「第一轮、第三轮、第二轮」，漂移曲线 x 轴静默错乱 |
| 浮点边界 | `abs(0.9-0.85)=0.050000000000000044 > 0.05`，恰好落在容差上的样本被判不达标，在曲线上表现为一个无法解释的失败点 |
| `preview()` 切归一化串 | 取证片段带上了未参与计数的代码 |
| 英文句号切句 | `0.01` 被切碎 |
| 定价表用正价 | 成本报高 50% |
| 假模型衰减挂调用次数 | 重生成也算调用，有审查组衰减快 3 倍，假跑呈现「审查让结果更差」的形态——**假模型的缺陷，却长得像结论** |
| 我的分析脚本正则贪婪 | 差点报出「22 条漏匹配」，实际是 9 条 |

## 四、实验结果

### 结论

**在术语标注维度上，审查 agent 有效但不完全。** 无审查组 0–0.36 从未达标；有审查组
0.67–1.00，6 轮达标。其余三维两组曲线基本重合、全程达标。

### 三条限制

1. **结论只适用于术语标注维度**——另外三维既不支持也不反对审查 agent 的价值。这个区分度
   本身有意义：若四维一起动，更可能是测量工具的系统性偏向。
2. **不是漂移，是从未遵守**——无审查组三条轨迹第 1 轮标注率全为 0.0，形态一致（3 个首现
   术语全是只给中文译名）。PRD §2 的 P2 表述据此修正：**审查 agent 的价值不只在阻止衰减，
   更在强制执行一条从未被遵守的约束**。前者可以靠更好的提示词解决，后者意味着提示词根本
   没起作用。
3. **审查有效但不完全**——45 个有审查轮次中 13 轮重生成 2 次后仍不达标。

### 口径缺口（未解决）

现有全部曲线与数值都是 **D02 口径**下所得；代码与 PRD 现行口径是 **D44**。
D44 重跑未执行，原因是资源限制。两个口径下组间差异都成立。

并排数字：有审查 0.764 → 0.813，无审查 0.154 → 0.212，不达标轮次 28/45(62%) → 4/45(≈9%)。

**另一个已识别未解决的问题**：D44 下 45 轮仅 6 轮有观测，新术语集中在第 1/2/3/8 轮。
「遵循度 vs 轮次」这个曲线形式对术语维度不再适用。建议替代形式是「累积标注覆盖率
vs 轮次」，**尚未实现也未验证**。

## 五、形成的几条通则

这些是从具体错误里提炼出来的，比任何单个数值都更值得带进 MVP。

**一 · 不能让测量结果反向定义标准。** 目标值不能由模型现状反推（否则模型多好目标就多高，
指标失去约束力）；达标线也不能由某次实验的样本长度反推（否则实验跑几轮标准就写几轮）。
由此形成 §3.2 的**阈值来源标注规则**：所有阈值必须标明来源——产品目标 / 实测依据 /
占位待定，占位项须写明确定路径。未标来源的阈值，与随手写的数字无法区分。

**二 · 对照实验中，处理组多做的任何动作，都可能在无关维度上引入偏差。** 排查时要问：
偏差是不是挂在了错误的计数上？但**并非所有组间差异都是偏差**——重生成带来的成本差异是
审查 agent 的真实代价，本来就该被测出来；要消除的是与被测属性无关的差异。

**三 · 判据的脆弱性是学科相关的，只用一个样本验证必然过拟合。**

**四 · 发现分类：影响数字的立刻修，只影响文档完整性的记 TODO 继续走。**

**五 · 指标必须与产品目标同向。** D44 那次修正的本质不是技术问题：一个方向错了的指标，
会同时制造质量问题和成本问题，而且它的输出看起来完全正常。

**六 · 会静默改变数字的 bug，比会报错的 bug 危险得多。** 本项目抓到的 9 个 bug 全部属于
前者，其中两个的误判方向与真相相反。

F3a 的配置扫描实验又抓到 4 个，全部同族——**不报错，只让数字偏移**：

| bug | 后果 | 怎么发现的 |
| --- | --- | --- |
| 检索同一性守卫按 `(点, 轮)` 分组 | 两条臂都跑 P0，报出**并不存在的分歧** | 假跑第一次运行 |
| `band_of` 按区间遍历，`6/12` 落进先匹配到的「不可分辨」 | **一个本该有结论的点变成没结论** | 单元测试 |
| `metadata.json` 只在跑完时写 | 中断后 11 轮**已付费数据无法核验** | 真实中断（API 余额耗尽） |
| **`--resume` 不清理不完整轨迹的残留轮次** | 追加模式续写后，同一条轨迹出现两套轮次——**报告按 11 轮而非 6 轮求均值** | 续跑前复查 |

**最后一条最典型**：续跑是为了省钱，而它省钱的方式恰好是**把旧数据留在文件里**；
留下的那几轮属于一条会被整条重跑的轨迹，于是同一条轨迹被算了两遍。
没有任何一步会报错，报告照常出数，只是均值偏了。
修法是续跑前先删掉不完整轨迹的记录，并留一条测试**演示不清理会变成 11 轮**。

**七 · 验证动作本身也需要被验证。** 前六条讲的是「怎么把事情做对」，这一条讲的是
**「怎么知道你以为的验证真的验证了东西」**。一个失效的验证比没有验证更糟：没有验证时
人会保持警惕，失效的验证会让人停止追问。**九个实例**（1–6 来自 F2、7 来自 F3a、8–9 来自 F3b），形态各不相同：

| # | 实例 | 它看起来在做什么 | 它实际在做什么 |
| --- | --- | --- | --- |
| 1 | 写进 `TODO.md` 的「本测试集 123 页 `rotation` 全为 0，**无从验证**」 | 陈述一个已核实的事实 | **从没测过。** 实测 11.201 的 15 页 `rotation=90`，块顺序与 bbox 全错 |
| 2 | 旋转页的回归测试：把横排文字画上去再 `set_rotation(90)` | 测「旋转页的阅读顺序」 | **在测竖排页。** 那样构造出的页面显示为竖排，本就没有横向阅读顺序，断言必然失败——失败还容易被当成实现有问题 |
| 3 | 「切片结果与方案预测完全一致」 | 验证判据成立 | **只验证了实现与方案自洽。** 方案和实现出自同一次思考，一致是应该的；它没有验证判据在真实世界成立 |
| 4 | 检索链路的「假向量跑通」验证 | 验证索引 → 检索 → 打分整条链路可用 | **所有指标恒为 0，把被测逻辑整个删掉也照样通过。** 假向量是词袋哈希，而语料是英文、评测集问题是学生的中文说法，两侧 token 零重合 |
| 5 | 选型规则里的噪声判据「差异小于 1 题视为不可分辨」 | 防止把小差异读成结论 | **永远不会触发。** `full-hit` 是整数计数，差异要么是 0 要么 ≥ 1，该判据只会把完全打平判为噪声——**一个看起来在防过度解读的规则，实际不防任何东西** |
| 6 | 「图注判定用 `image_adjacency` 与 `size_rank` 联合」（**来源：评审指定，非方案提出**） | 依据 2a 的实测观测选定图注通道的主信号 | **在需要它的页上信号根本不存在。** 2a 观测到 `is_adjacent` 命中了真图注，但那是**位图页**上的观测；而贡献全部 17 条金标准图注术语的 p20/p27 **一张位图都没有**（图是矢量绘制），邻接恒为 null，联合判定命中 0 条 |
| 7 | F3a 的 59 条测试「全绿」（2026-08-23） | 验证讲解链路可用，含模型抽象层 | **真实模型从没进过测试。** `AnthropicModel.request_signature` 被一次批量改名弄成了 `requestsignature`，59 条断言**一条都没红**——它们全走假模型，真实模型的方法名从未被任何断言碰过。错误直到第一次真实调用才暴露，那时已经在花钱了 |
| **8** | F3b 兜底的第三类「由 `skipped_pages` 与检索命中页的**交集**判出」（**来源：评审指定**） | 用规则零成本判出「内容在图里读不了」 | **交集恒为空集。** `image_only` 页不产生切片，**不可能出现在检索命中页里**。信息是全的——`retrieval/README.md` §四写着「gold 页不产生切片，`page-recall` 在结构上恒为 0」，`F2开发.md` §11.2 也列为结构性上限——**漏的是一次范围核对** |
| **9** | G03 第一版门槛设在 `insufficient` 上（**来源：实现**） | 只在「片段完全没提」时提示跳过页 | **模型看不到跳过页的内容，没有依据给出那个判断。** 校准实测两道 `unreadable_page` 题只触发一道：Q029 判 `partial`，而那是合理的。**把门槛建在一个模型无法可靠给出的判断上**，2 题漏 1 题，通道形同虚设 |

**第 6 例的形态与前五例都不同**：它不是验证空转，是**观测范围与应用范围的错配**——
把「在一批页上观测到信号」误认成「在需要信号的页上有信号」。
22.081J 全篇有 22 张位图，观测本身没错；错在没有追问
**「贡献金标准的那些页有没有位图」**。

它也说明这类错误与经验无关，只与**有没有问那一句**有关：
2a 的报告如实写了「命中 18/334 块」并举了例子，信息是全的，
漏掉的只是一次范围核对。**指定机制时要问的是「这个信号在目标对象上存在吗」，
而不是「这个信号在我见过的地方存在吗」。**

### 第 8、9 例：同一个坑在同一轮里被踩了两次

两例都是第 5 例（防护措施空转）的变体——**一条看起来在做兜底的规则，实际不会触发**。
但来源不同：**第 8 例来自评审指定，第 9 例来自实现**。

| | 第 8 例 | 第 9 例 |
| --- | --- | --- |
| 谁定的 | 评审 | 实现 |
| 为什么不触发 | 信号**在目标对象上不存在**（跳过页没有切片） | 门槛**建在一个模型无法可靠给出的判断上** |
| 发现时机 | 动手前算了一次交集 | 跑批前的校准数据 |

**「同一个坑在同一轮里被踩了两次」这件事本身比任何一例都值得记。**
第 8 例发生之后，我已经知道要问「这个信号在目标对象上存不存在」，
**却在设计替代机制时没有对自己的门槛问同一句话**——
`insufficient` 这个判断所依赖的信息（跳过页里有什么），模型一个字也看不到。

所以第七条通则要加一句限定：**问过一次不算问过。**
每引入一个新的判据、门槛、触发条件，都要重新问一遍
「**做出这个判断所需的信息，判断者手上有吗**」——
无论判断者是一段规则，还是一个模型。

两次的代价都很低，因为都问在了花钱之前：第 8 例问在动手前，
第 9 例问在跑批前——**这正是先跑校准的价值**。

**第 7 例与第 4 例同族，但失效的位置更靠前**：第 4 例是「被测逻辑被换成平凡实现，
断言照样通过」，第 7 例是**「被测对象根本不在测试范围内」**——
连换掉的机会都没有，因为它从来没被调用过。

两者的检查方式因此不同：第 4 例问「如果被测行为是错的，这个测试会不会红？」；
第 7 例要问的是**「这个对象被哪条断言碰过？」**。
一个替身（假模型 / 假向量）用得越顺手，越容易让人忘记问后一句。
修法是加一条**协议一致性**断言：真实实现与替身必须暴露同一组方法名，
且真实实现里不需要网络的部分（如请求指纹）要被直接调用一次。

**第 4 例是这几例里最清楚的一个**，因为它的失效是可判定的：把 `retrieve()` 换成
「返回空列表」，这个验证的输出**一个字符都不会变**。前三例还要靠论证才能说明白问题
出在哪，这一例可以直接演示。

它也说明这类错误不是「早期不成熟」——它出现在**写下这条通则的同一次工作里**，
就在写完前三个实例之后几小时。知道原则和用上原则是两件事，所以才需要把它固化成
一条会红的测试（`test_fake_embedder_would_be_a_useless_assertion`），而不是记住它。

**第 5、6 例各是一种新形态**：前四例是「验证动作空转」，第 5 例是**防护措施空转**，
第 6 例是**观测范围与应用范围错配**。
写下一条约束时同样要问：**它在什么情况下会触发？如果答案是「几乎不会」，它就不是约束。**
它的修法也说明了方向——**小样本上不要靠阈值，要靠重复**：
差异必须在多个独立条件下同向出现才算证据（见 `retrieval/README.md` R17）。

六者的共同点：**都产出了「已验证 / 已设防 / 有依据」的信号，而对象是错的或根本不存在。**

各自的教训不同，不可互相替代：

- **假断言（#1）比 bug 更危险。** bug 会被测试发现；假断言会让人**不去测**。
  凡是写成「已验证 / 无从验证 / 全部为 X」的句子，必须能指出是哪次测量得出的。
- **测试要先验证它测的是不是目标现象（#2、#4）。** 写完一个测试后要问：
  「如果被测行为是错的，这个测试会不会红？」以及反过来——
  「它现在红/绿，是因为被测行为，还是因为我把输入构造错了？」
  #4 给出了这个问题的可执行形式：**把被测函数替换成平凡实现，看断言会不会红**。
  不会红，这个测试就是空的。
- **自洽不是验证（#3）。** 实现对照方案、代码对照注释、结果对照预期——
  这些都只在检查内部一致性。要验证判据本身，必须引入**没有参与设计的证据**
  （另一个 OCR 工具的扫描件、另一门学科的课件、人工核过的图）。

这条与第三条（判据的脆弱性是学科相关的，只用一个样本验证必然过拟合）互补：
第三条说样本不够，第七条说**即使样本够，验证动作本身也可能是空转的**。

### 成本：这条会影响 MVP 的架构决策

| | 有审查 | 无审查 |
| --- | --- | --- |
| 每轮 | $0.0393 | $0.0154 |
| 15 轮单会话 | **$0.590** | **$0.231** |

上限尚未推导（公式在 §9.1，缺定价模型）。但**归因已经清楚，可以直接指导架构**：

**成本主体是重生成，不是上下文。**

- 输出 token 占成本 **68%**，检索只作用于输入侧——**输入压到零也只省 32%**（$0.59 → $0.40）。
- 62% 的重生成触发率使有审查组的实际生成次数翻倍（92 次 vs 45 次）。
- D44 口径下触发率估算降到约 9%，这是目前最大的单一杠杆（未经重跑验证）。

**对 MVP 的三条直接含义：**

1. **不要指望检索解决成本问题。** 检索该做，但它的收益上界是 32%，而且是在输入侧。
   把它当成压成本的主要手段会导致投入错配。
2. **重生成策略是架构决策，不是调参。** 触发率、重生成上限、反馈如何注入（追加轮
   还是系统提示词层），这三者共同决定成本量级。当前实现是「反馈作为追加轮」，
   实测第 2 次重生成平均只 +0.113 且 8/19 次完全无变化。
3. **成本上界仍在 $0.17 参考值的 3.5 倍处。** 这是可通过工程优化接近的距离，
   但需要重生成率真的降下来——所以 D44 重跑不只是验证指标，也是验证成本假设。

完整清单见 `A类规则计算脚本/TODO.md`（20 条）。
