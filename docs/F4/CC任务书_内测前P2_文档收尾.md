## 做什么

### 1. 新增口径 F73–F76

写进 `f1_samples/README.md` §一，沿用既有列格式。

| 编号 | 口径 | 理由 |
| --- | --- | --- |
| **F73** | **`gap_cost_usd` 的三种取值含义不同，必须靠 `gap_implementation` 区分** | 事件表里同一列有三种语义：数值＝真的花了这么多；`null` + `impl: "error"`＝**花没花钱不知道**（超时后线程杀不掉，后台调用可能跑完并计费）；`null` + `impl: null`＝旧构建，这一跳不存在。**后两种都是 null**，不区分就会被一起当成 0，而其中一种其实是「未知」。这与 `restricted_pages_excluded` 写 0 是同一类错误：一个看起来是测量结果的数，实际是未知 |
| **F74** | **每次容器冷启动后的第一轮判断必然超时**，登记不修 | Render 免费层 15 分钟休眠，首次调用要建连接、初始化 SDK。方向单向（那一轮没有兜底提示，退回 F3b 之前的行为）。**修法是 keep-alive 或升级计划，不是调大超时**——调超时是把症状藏起来，让真正的挂起更晚被发现。触发条件：内测中 `gap_implementation == "error"` 占比超过可接受范围 |
| **F75** | **判断失败时单轮成本被低估，金额未知** | 两件事的同一半：超时后后台调用可能仍计费；`cost_usd` 不计入这笔。方向单向（低估），不修。**不要拆成两条小问题记** |
| **F76** | `explain_turn` 的 `gap_*` 字段**不进必需清单** | 两个理由，都已被生产数据验证：失败时 `gap_cost_usd` 写 null 不写 0（请求可能已计费、金额未知）；迁移上线到新构建上线之间旧构建发的事件没有这些键，进了清单会被 23514 全拒。真库里确实存在一行三个 `gap_*` 全 null 的旧构建事件 |
