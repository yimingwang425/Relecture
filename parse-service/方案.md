## 0. 先说一个必须改的结论：原判据不可判别

任务给的判据是「**内嵌字体数 ≈ 0 且存在铺满版面的全页图**」。
我在 123 页上把这两个信号都量了一遍，**两个都不可判别**。这不是阈值调不好，是两类
样本的取值区间本身重叠。

### 0.1 「铺满版面」不可判别

图像并集覆盖率（所有图片落版矩形的并集面积 ÷ 页面积）的类内分布：

| 类别 | n | min | p50 | max |
| --- | --- | --- | --- | --- |
| 扫描页（15.316 的 17 个有文本页） | 17 | **0.775** | 0.810 | **0.844** |
| 非扫描页（其余三份 + 15.316 的 2 个无文本页） | 106 | 0.000 | 0.141 | **0.865** |

**非扫描侧的最大值 0.865 高于扫描侧的最大值 0.844。区间完全被包住，不存在任何阈值能分开。**

落在 15.316 区间 `[0.775, 0.844]` 里的数字文本页（全部来自 14.129）：

| 页 | 并集覆盖率 | 不可见文本占比 | 可见字符数 | 实际是什么 |
| --- | --- | --- | --- | --- |
| 14.129 p32 | 0.865 | 0.066 | 58 | 一张满版示意图 + 标题 |
| 14.129 p12 | 0.830 | 0.025 | 79 | 满宽配图 + 标题 |
| 14.129 p45 | 0.823 | 0.043 | 45 | 满宽配图 + 标题 |
| 14.129 p46 | 0.788 | 0.032 | 30 | 同上 |

机制上的原因：**扫描图有白边**。15.316 的扫描图落版矩形是
`(53.2, 75.2) – (805.9, 621.0)`，页面是 `805 × 621`——右下溢出页面，但左上留了
53pt / 75pt 的边，所以只覆盖 0.82，够不到「铺满」。而讲义里贴一张满宽配图同样能到 0.8+。
「铺满版面」这个直觉在真实扫描件上并不成立。

### 0.2 「内嵌字体数 ≈ 0」也不可判别

123 页里 **45 页**内嵌字体数为 0，其中只有 19 页属扫描件——**精确率 42%**。

| 文件 | 内嵌字体数为 0 的页数 | 是否扫描件 |
| --- | --- | --- |
| MIT15_316SU05_leader_dev | 19 / 19 | 是 |
| MIT14_129S25_lec02 | 21 / 50 | 否 |
| MIT11_201F07_slides2 | 4 / 15 | 否 |
| MIT22_081JF10_lec01b | 1 / 39 | 否 |

原因：**base-14 标准字体按 PDF 规范本就不内嵌**。11.201 全篇用 `ArialMT` /
`TimesNewRomanPSMT`（均未内嵌），是彻头彻尾的数字课件。而 15.316 的 OCR 文本层用的是
`Helvetica` / `Times-Roman`——**与 11.201 属同一类未内嵌标准字体**，字体这一路根本区分不了它们。

### 0.3 能判别的信号：不可见文本（Tr 3）

| 类别 | n | 不可见文本字符占比 |
| --- | --- | --- |
| 15.316 的 17 个有文本页 | 17 | 全部 = **1.000** |
| 其余 104 个有文本页 | 104 | 中位 0.000，**最大 0.066** |

**间隔 `[0.066, 1.000]`，宽 0.934。** 这是本次测量里唯一干净分开的信号。

它不是这份文件的偶然属性，而是机制性的：OCR 工具把识别出的文字用
**Tr 3（不可见文本渲染模式）** 叠在扫描图上——让人看到的是图、让机器搜到的是字，
这正是「OCR 文本层」的定义性特征。PyMuPDF 通过 `page.get_texttrace()` 的 `type` 字段
直接暴露它（`3` = 不可见，`7` = 仅加入裁剪路径，同样不着墨）。

对照 PRD §6.2 与 `测试集/SOURCES.md` 的结论——判据从「有没有文本」升级到「内嵌字体 + 全页图」
方向是对的，但**落点应当是「这些文本是不是画出来给人看的」**。OCR 层的文字压根不着墨，
这比字体与面积都更贴近「这页的实质内容在图里，不在文字层」这个我们真正想问的问题。

## 1. 输出 JSON schema（Python ↔ TS 契约）

用 pydantic 定义（FastAPI 自带，不新增依赖），随服务导出 JSON Schema 供 TS 侧生成类型。

三条设计原则：

1. **版面信息一律保留**，不为了「统一 PDF 与 PPTX」而丢任一侧的字段——
   格式特有信息全部收进 `origin`，共有信息升到顶层。
2. **判据发出的是测量值，不只是结论。** 每个结论旁边并排放它依据的原始数字
   （`evidence`、`image_adjacency` 的几何量），这样第三步改阈值时可以直接重算，
   不必重新解析文件。
3. **邻接给测量不给定论。** 「与图片相邻」的阈值应当由第三步的图注标注集反推，
   现在定死等于凭空造一个数（违反 PRD §3.2）。故并排给出 `is_adjacent`（按默认阈值导出）
   与 `gap_lines` / `overlap_ratio`（可重算的原始量）。

### 1.1 顶层

```jsonc
{
  "schema_version": "1.0",
  "document": {
    "doc_id": "sha256:9f2c…",           // 文件内容哈希；去重与缓存键
    "source_format": "pdf",             // "pdf" | "pptx"
    "filename": "MIT15_316SU05_leader_dev.pdf",
    "byte_size": 1863221,
    "page_count": 19,
    "producer": "Acrobat Capture 3.0",  // PDF /Producer 或 PPTX docProps/app.xml；扫描件归因用
    "parser": {
      "service_version": "0.1.0",
      "pymupdf": "1.28.2",
      "python_pptx": null,
      "ruleset_version": "scan-1.0"     // 判据版本；口径变了这个数必须跟着变
    },
    "usable_page_count": 0,
    "unusable_page_count": 19,
    // 【调整 2】verdict 收成两值，并给出不可用页清单。
    // 「占比低于某数就拒绝」是把产品决策塞进解析层 —— 放行并告知，不替用户拒绝。
    "unusable_pages": [ { "index": 1, "kind": "scanned_ocr" }, /* … */ ],
    "verdict": "unusable",              // "usable" | "unusable"
    "verdict_reason": "无可用页（共 19 页：2 页 image_only、17 页 scanned_ocr）"
  },
  "pages": [ /* PageOut */ ]
}
```

### 1.2 页 / 幻灯片

```jsonc
{
  "index": 1,                           // 1-based
  "size_pt": [805.0, 621.0],            // PPTX 由 EMU 换算（1 pt = 12700 EMU）
  "rotation": 0,
  "kind": "scanned_ocr",                // digital_text | scanned_ocr | image_only | empty
  "usable": false,                      // 仅 digital_text 为 true
  "evidence": {                         // 判据的全部输入，逐页留存
    "image_coverage_union": 0.822,
    "image_coverage_max": 0.822,
    "invisible_text_ratio": 1.000,
    "text_char_count": 79,
    "embedded_font_count": 0,
    "font_count": 3,
    // 【调整 1】观测项：纯白填充文本字符占比。只记录，不接入规则、不参与判定。
    // 深色底幻灯片的正常白字有噪声（实测 14.129 有页达 0.919）。
    "white_fill_text_ratio": 0.0,
    "rule_fired": "R1_ocr_layer"
  },
  "notes_text": null,                   // 仅 PPTX：演讲者备注（无版面信息，故不进 blocks）
  "blocks": [ /* TextBlock */ ],
  "images": [ /* ImageObj */ ]
}
```

### 1.3 文本块

```jsonc
{
  "block_id": "p3-b7",
  "page_index": 3,
  "order": 7,                           // 解析器给出的顺序，非阅读顺序（见 §3.6）
  "text": "Figure 2. Global primary energy consumption by source",
  "bbox_pt": [112.4, 488.0, 623.9, 501.1],
  "bbox_norm": [0.140, 0.786, 0.775, 0.807],   // 除以页宽高；跨页面尺寸可比
  "font": {                             // 块级汇总：按字符数加权的主导值
    "size_pt": 9.0,
    "size_rank": 0.12,                  // 该字号在本页字符加权字号分布中的分位 —— 图注偏小
    "bold": false,
    "italic": false,
    "name": "NimbusSanL-Regu",
    "color": "#000000",
    "resolved": true                    // PPTX 继承未解析出时为 false（见 §3.2）
  },
  "image_adjacency": {
    "nearest_image_id": "p3-i1",
    "relation": "below",                // above|below|left|right|inside|overlap|null
    "gap_pt": 4.2,
    "gap_lines": 0.32,                  // gap_pt ÷ 本块行高 —— 尺度无关，跨字号可比
    "overlap_ratio": 0.87,              // 与图在正交轴上的投影重叠比
    "is_adjacent": true                 // 由默认阈值导出，可用上面三个量重算
  },
  "origin": { /* §1.5 */ }
}
```

### 1.4 图片

v1 **不导出图片二进制**，只给位置与标识；图注通道要的是位置关系，不是像素。
需要像素时（多模态 / 图内 OCR）按 `image_id` 回取，接口另开。

```jsonc
{
  "image_id": "p3-i1",
  "bbox_pt": [98.0, 190.5, 640.2, 483.8],
  "bbox_norm": [0.122, 0.307, 0.795, 0.779],
  "coverage": 0.452,                    // 本图落版面积 ÷ 页面积
  "pixel_size": [1204, 652],
  "origin": { "kind": "pdf_image", "pdf": { "xref": 265, "colorspace": "DeviceRGB", "bpc": 8, "placement_index": 0 } }
}
```

### 1.5 `origin`：两种来源各自的原始信号

**PDF**

```jsonc
{
  "kind": "pdf_textblock",
  "pdf": {
    "block_number": 7,
    "line_count": 1,
    "spans": [
      { "text": "Figure 2. ", "size_pt": 9.0, "font": "NimbusSanL-Regu",
        "flags": 4, "bold": false, "italic": false, "serif": true, "mono": false,
        "color": "#000000", "render_mode": 0, "bbox_pt": [112.4, 488.0, 158.2, 501.1] }
    ]
  }
}
```

保留 span 级是必要的：块是 PyMuPDF 按几何聚类出来的，一个块里混着不同字号很常见
（22.081J p3 的同一块里 13.06pt 与 31.33pt 并存），只留块级汇总会把「标题 + 副标题」
压成一个平均字号，字号信号就废了。

**PPTX**

```jsonc
{
  "kind": "pptx_shape",
  "pptx": {
    "shape_id": 5,
    "shape_name": "Content Placeholder 2",
    "shape_type": "PLACEHOLDER",        // MSO_SHAPE_TYPE 名
    "is_placeholder": true,
    "placeholder_type": "BODY",         // PP_PLACEHOLDER 名
    "placeholder_idx": 1,
    "from_layout": false,               // true = 来自 layout/master 的背景装饰，非本页内容
    "z_order": 2,
    "rotation": 0.0,
    "paragraph_index": 0,
    "list_level": 1,                    // 项目符号层级 —— PDF 侧没有的结构信号
    "runs": [
      { "text": "Heat engine", "size_pt": 24.0, "bold": true, "name": "Calibri",
        "resolved_from": "layout" }     // run | placeholder | layout | master | theme | null
    ]
  }
}
```

`resolved_from` 是 PPTX 侧特有的：字号/加粗常常不写在 run 上而是继承来的，
**记下它是从哪一级解析到的**，比只给一个数字诚实——`null` 表示没解析出来，
下游要知道这个块的字体信号不可用，而不是把它当成「没有加粗」。

## 2. 扫描件判据

### 2.1 三个测量量

对每一页计算：

| 量 | 算法 | 备注 |
| --- | --- | --- |
| `invisible_text_ratio` | `page.get_texttrace()`，`type ∈ {3, 7}` 的字符数 ÷ 总字符数 | 3 = 不可见，7 = 仅加入裁剪路径 |
| `image_coverage_union` | 所有 `page.get_image_rects(xref)` 落版矩形的**并集**面积 ÷ 页面积 | 用矩形扫描线求精确并集（探针里用的 80×80 网格近似，实现时换精确算法） |
| `text_char_count` | `page.get_text("text")` 去空白后的字符数 | |

用**并集**不用最大单图：扫描件可能被切成多条带（15.316 p8 就是 2 张图）。
用**落版矩形**不用图像像素尺寸：一张图可以被缩放到任意大小，像素数说明不了它占多大版面。

### 2.2 规则（逐页，按序命中即停）

| 编号 | 条件 | 判定 | `usable` |
| --- | --- | --- | --- |
| R1 | `text_char_count > 0` 且 `invisible_text_ratio ≥ 0.80` 且 `image_coverage_union ≥ 0.50` | `scanned_ocr` | false |
| R2 | `text_char_count < 10` 且 `image_coverage_union ≥ 0.25` | `image_only` | false |
| R3 | `text_char_count < 10` | `empty` | false |
| R4 | 其余 | `digital_text` | **true** |

**【调整 2】** 文档级 `verdict` 只有两值：`usable_page_count == 0` → `unusable`，其余一律 `usable`，
并给出 `unusable_pages`（页号 + kind）与 `unusable_page_count`。
「可用页占比低于某数就拒绝上传」是把**产品决策**塞进解析层——
服务如实报告哪些页不可用，**放行并告知，不替用户拒绝**；UI 文案由调用方按计数决定。

### 2.3 阈值来源

| 阈值 | 值 | 来源 | 依据 / 确定路径 |
| --- | --- | --- | --- |
| `invisible_text_ratio` | ≥ 0.80 | **实测依据** | 2026-08-20，123 页。非扫描侧最大 0.066，扫描侧最小 1.000，间隔宽 0.934。取 0.80 落在间隔内偏扫描侧，为「扫描页夹带少量数字文本（页码、水印）」留余量 |
| `image_coverage_union`（R1） | ≥ 0.50 | **实测依据（弱，非判别项）** | 同上。扫描页实测 `[0.775, 0.844]`，0.50 远在下界之下。**它不是判别器**——判别全靠不可见文本比；它只挡「整页不可见文本但根本没有图」的畸形 PDF。刻意不取 0.775 贴边，因为 §0.1 已证明该维度类间重叠，贴边等于把一个不可判别的量当判别器用 |
| `text_char_count`（R2/R3） | < 10 | **占位待定** | 现值只保证 15.316 p8/p14（0 字符）与 14.129 p33–p36（2 字符，内容是页码「33」）被判不可用，这 6 页确实没有可用文本。确定路径：第三步的图注标注集建成后，按「跳过该页是否丢失术语」反推 |
| `image_coverage_union`（R2） | ≥ 0.25 | **占位待定** | 同上。它决定「一张图配一行标题的幻灯片」算不算可用。同一确定路径 |
| ~~`usable_page_ratio` 的 0.5 / 0.9~~ | — | **【调整 2】已删除** | verdict 收成两值：`usable_page_count == 0` → `unusable`，其余 → `usable`。另给 `unusable_pages`（页号 + kind）与计数，UI 文案由调用方决定 |

### 2.4 本判据的已知漏判方向

**漏判（扫描件被放行）是危险方向**——OCR 噪声会一路进切片、术语表、讲解，正是
`SOURCES.md` 要防的那件事。已知两种漏法：

1. **没有文本层的纯扫描件**：`invisible_text_ratio` 无定义（无文本），R1 不触发。
   → 由 R2/R3 接住（判 `image_only` / `empty`，同样 `usable=false`），结果等价，安全。
2. **用白色字或裁剪路径实现的 OCR 层**（部分老工具）：R1 漏判。
   → **当前无缓解手段，也不打算现在造一个**。测试集里没有这种样本，凭空调阈值等于
   编一个数。
   **【调整 1】本条已提到 [`README.md`](README.md) 口径表首位**，并连同
   「判据实测基础只有 1 份文件、1 个 OCR 工具（Acrobat Capture 3.0）」一并写明；
   同时增加观测字段 `evidence.white_fill_text_ratio`（纯白填充文本字符占比），
   **只记录，不接入规则**。

误判方向（正常页被判扫描）在本测试集上为 **0 页**——非扫描侧不可见文本比最大 0.066，
离 0.80 有 12 倍余量。

### 2.5 预期验证结果

按上述规则，4 份课件的预期逐页判定（实现后跑脚本核对，作为 golden file 回归）：

| 文件 | `digital_text` | `scanned_ocr` | `image_only` | `empty` | 文档 verdict |
| --- | --- | --- | --- | --- | --- |
| MIT11_201F07_slides2 | 15 | 0 | 0 | 0 | usable |
| MIT22_081JF10_lec01b | 39 | 0 | 0 | 0 | usable |
| MIT14_129S25_lec02 | 46 | 0 | 4 | 0 | usable (0.92) |
| MIT15_316SU05_leader_dev | 0 | 17 | 2 | 0 | **unusable (0.00)** |

## 3. PDF 与 PPTX 两条路径的差异点

> **【调整 3】本次只实现 PDF 路径。** 下表是 schema 形状的设计依据——
> `origin` 的分装方式据此确定，并已通过往返测试（`tests/test_schema.py::TestOriginUnion`）。
> PPTX 解析器为下次交付。

| # | 维度 | PDF（PyMuPDF） | PPTX（python-pptx） | 处理 |
| --- | --- | --- | --- | --- |
| 3.1 | 单位与页面尺寸 | pt，**逐页可变**（本测试集就有 805×621 / 792×611 / 720×540 三种） | EMU，整份固定（`presentation.slide_width/height`） | 统一换算到 pt；同时给 `bbox_norm`，邻接判定一律用归一化量 |
| 3.2 | 字体信息 | span 必带 `size` / `font` / `flags`，完整 | run 的 `size` / `bold` / `name` **常为 `None`**，继承自 placeholder → layout → master → theme | 按继承链回溯，并记 `resolved_from`；回溯不到就 `resolved=false`，**不猜默认值** |
| 3.3 | 「块」从哪来 | PyMuPDF 按几何聚类，**不稳定**（多栏版面可能跨栏误合） | 天然由 shape → paragraph 给出，结构可靠 | PDF 侧保留 span 级原始数据以便下游重切；PPTX 侧一段一块 |
| 3.4 | 图片位置 | 需 `get_image_rects(xref)`；**一个 xref 可多处落版** | picture shape 直接有 `left/top/width/height` | PDF 侧对每个落版矩形各发一条 `ImageObj`（`placement_index` 区分） |
| 3.5 | 背景装饰图 | 无法与内容图区分 | 可判断来自 slide 还是 layout/master | PPTX 侧记 `from_layout`；来自母版的图**不参与邻接计算**（每页都有的 logo 会把每个文本块都判成"图注"） |
| 3.6 | 阅读顺序 | 无可靠顺序，只能几何排序 | z-order ≠ 阅读顺序，但 `placeholder_idx` 较可靠 | 两侧都只给 `order`（解析器顺序），**schema 明确声明它不是阅读顺序** |
| 3.7 | 结构信号 | 只有字号/加粗，标题层级靠推 | 有 `placeholder_type`（TITLE/BODY）与 `list_level`，**直接给出层级** | 各自进 `origin`，不强行折叠成一个统一的 "heading_level" |
| 3.8 | 扫描件判据 | 不可见文本层（§2） | **不存在 OCR 文本层这一形态**；对应形态是「整页贴一张 PDF 截图」的幻灯片 | PPTX 侧 R1 不适用，改用：无文本 shape 且 picture 覆盖率高 → `image_only`。**判据不共用，各写各的** |
| 3.9 | 表格 / 图表 | 是散落文本 + 线条，无结构 | 有原生 table / chart shape | v1 表格按文本块导出；chart 只记存在与 bbox（`origin.kind = "pptx_chart"`），不解数据 |
| 3.10 | 备注 | 无 | 有演讲者备注（`notes_slide`），对讲解价值高 | **【调整 4】** 进 `page.notes_text`；**不进 `blocks`**——它没有 bbox，混进去会污染邻接计算。**备注同样受 PRD §12.1 的单段引用 100 字上限约束**（已写入 schema 注释）。术语提取是否使用备注由第三步决定，本服务**只存不用** |
