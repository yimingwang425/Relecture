## 二、三件预查的结论

### 1. `ModelGapChecker` 搬到哪里 —— **类本来就在共享包里，搬的是 Haiku 那份配置**

查到的实际情况与任务书的描述有一处出入，如实写：

- `ModelGapChecker` / `NullGapChecker` / G03a 规则通道 `skipped_pages_hint` / 限定语渲染 `render_gap_note`
  **本来就住在 `explain/explain/gap.py` 与 `prompt.py`**，生产 `/explain` 早就 import `explain`。
- 住在 `实验脚本/配置扫描实验/scan/live.py` 的只是 **`build_gap_checker()` 里那份构造**：
  模型 id `claude-haiku-4-5-20251001`、`effort=None`、`thinking="disabled"`、`max_tokens=300`、两个缓存关。
  生产拿不到它，所以一直回落 `NullGapChecker`。

**方案**：把那份构造搬进 `explain/explain/gap.py::build_model_gap_checker()`（**唯一构造处**），
`live.py::build_gap_checker(True)` 与 `api/main.py::_default_gap_checker()` 都只调它。
方向同 F46「生产拥有，实验再导出」。**参数逐项未改**，F3b 那组数仍对应现在的代码。
`TestOneImplementation` 三条钉住：模型 id 字面量不许出现在 `api/api` 与 `scan/` 下；
`ModelGapChecker(` 不许在 `gap.py` 之外被构造；两侧都调共享函数。

⚠️ 模型 id 用的是带日期后缀的 `claude-haiku-4-5-20251001`，不是任务书写的 `claude-haiku-4-5`：
那是 F3b 校准与跑批实际用的 id，换写法就是换了被测对象的名字（价目表按前缀匹配，两者同价）。

### 2. `skipped_pages` 在生产上拿不拿得到 —— **拿得到，来源是 `documents.unusable_pages`**

不是现编的来源：`api/api/retriever.py::SupabaseRetriever._skipped_and_unusable` 在 F3 接线时就把
`documents.unusable_pages`（摄入时落库，`ingest.py:154`）还原成 `SkippedPageRef` 放进 `ContextPack.skipped_pages`，
`supabase.py` 的 `DOCUMENT_COLUMNS` 也读这一列。所以 G03a 在生产上**做得了**，本轮直接接通。

`TestHintIsNotAlwaysOn::test_skipped_pages_reach_the_hint_from_the_database` 走真检索后端那条路
（给 `course_id`），跳过页只写在假库的 documents 行里，限定语必须出现在讲解模型收到的 user turn 里。

**已有的、本轮不修的缺口**（`retriever.py` docstring 早就登记）：slicer 的第二个跳过分支
「可用页但无文本块」不在 `unusable_pages` 里，到不了这里。触发条件沿用原登记。

### 3. `explain_turn` 里有没有 `gap_*` —— **一个都没有，全补了**

`RoundResult.cost_usd` / `latency_ms` 本来就含判断那一跳（`pipeline.py`），但事件里没有单列。
补的键：`gap_verdict` / `gap_reason` / `gap_cost_usd` / `gap_latency_ms` / `gap_implementation` /
`gap_model` / `gap_error` / `gap_skipped_hint_pages`。`/explain` 响应另加 `gap` 字段（口径 F53）。

**全部不进必需清单**，理由写在 `events.py::_gap_fields` 与迁移头：null 有含义（F50）；
判断失败时 `gap_cost_usd` 是 null 不是 0（请求可能已计费、金额未知）；
**迁移先于构建的那段窗口里，旧构建的 `explain_turn` 没有这些键**，进了清单会被静默全拒。
代价：这几列没有数据库护栏，护栏在 `test_gap_wiring.py`。

## 五、如实登记

1. **不传 `course_id` 的替身路径从来不发讲解事件。** `InMemoryRetriever` 的 `meta` 没有
   `embed_model` / `embed_dimensions`，`retrieval_executed` 构造时抛，整批事件被 `build_error` 吞掉
   （响应里看得见，不静默）。**不是本轮引入的**，是 `test_gap_wiring.py` 第一版借这条路时 12 条全红抓出来的；
   测试里给替身补了那两个 meta。生产讲解页恒传 `course_id`，不受影响。本轮不修，触发条件：有人要在替身路径上做事件断言时。
2. **判断失败时 `explain_turn.cost_usd` 少算了一笔未知成本。** `GuardedGapChecker` 的 `GapResult.cost_usd` 是 0.0，
   `RoundResult.cost_usd` 把它加进总数；请求若已计费，总数偏低。事件单列那一格写 null 标明「未知」。
   触发条件：内测里 `gap_implementation="error"` 的轮次不是个位数时。
3. ~~判断调用没有单独的超时~~ → **已修（本轮追加，见守卫 8）。** 这一条第一版被我写成「遗留问题」，**写错了**：
   它是本轮引入的——之前是 `NullGapChecker`，零延迟，没有东西可以挂住；接进生产后它成了主链路上的一次外部 API 调用，
   而 `GuardedGapChecker` 接的是异常不是超时，挂住时兜底不会触发。
   处置：`GAP_TIMEOUT_S = 5.0`（≈ 3× F3b 实测 P90 1,595 ms，锚在实测上），超时按判断失败走同一条 error 路径。
   **剩下的代价**：Python 杀不掉正在跑的线程，超时后那次调用仍在后台（守护线程）跑完、可能照样计费、占着连接直到 SDK 自己的超时。
4. **G01 写的是「严格两选一」，prompt 输出的是三个取值**（`covered` / `insufficient` / `partial`）。
   F3b 的「两分类」指「够 / 不够」，不够再分两种。本轮沿用校准过的 prompt 原文，一字未改。
5. **`/explain` 响应里的 `gap.gap_cost_usd` 与事件那一格在失败时不同**：响应是 `to_dict()` 原样（0.0），
   事件是 null。**读响应时先看 `gap_implementation`**；只有它是 `"model"` 时成本那一格才有意义。
