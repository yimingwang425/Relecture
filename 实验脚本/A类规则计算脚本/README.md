# A 类规则计算脚本

AI 课件讲解助手 · 风格遵循度 **A 类维度**（规则可计算、零模型成本）的度量模块。
对应 PRD §8.1 的 A 类表格，服务于 §8.2 的漂移衰减曲线实验与 §13.1 的每轮埋点。

**输入**：讲解文本（str）+ 风格配置（JSON）+ 术语表（list）
**输出**：各维度得分的 dict，按维度分别报告，**不做混合分**（见 D17）

| 维度 | 模块 | 状态 |
| --- | --- | --- |
| 共享预处理层 | `a_rules/text.py` | ✅ 已完成 |
| 中文字符占比 | `a_rules/metrics/chinese_ratio.py` | ⬜ 待实现 |
| 术语英文标注率 | `a_rules/metrics/term_annotation.py` | ⬜ 待实现 |
| 平均段落字数 | `a_rules/metrics/paragraph_length.py` | ⬜ 待实现 |
| 单段最长引用字数 | `a_rules/metrics/quote_length.py` | ⬜ 待实现 |
| 风格配置 | `a_rules/config.py` | ✅ 已完成 |
| 术语表 / 聚合入口 / CLI | `glossary.py` `evaluator.py` `__main__.py` | ⬜ 待实现 |

## 口径决策表

> **这张表是本模块最重要的部分。**
> 口径变了，指标绝对值就变了，§8.2 的漂移曲线前后不可比、§8.4 的上线达标线失去意义。
> 因此规则：**任何口径调整都必须先改这张表并记录新的决策日期，再改代码。**
> 未记录在此表的口径变更视为 bug。

### 一、指标口径

| 编号 | 口径 | 决策 | 理由 | 决策日期 |
| --- | --- | --- | --- | --- |
| D01 | 中文字符占比的分母 | 汉字数 + 英文**单词**数（非字母数） | 按字母计会让 `gradient descent` 顶 16 个汉字的量，占比随中英混合比例剧烈抖动，与 §8.2 要观察的漂移信号混淆 | 2026-08-19 |
| D02 | 术语计数单位 | 主口径按术语 type 的**首次出现**计；`details` 同时输出全量出现（`all`）口径 | 标注只需首现一次，全量计数会惩罚正常写作；但两种口径的差值本身是有用信号（反映模型是否反复堆砌括注），故并行输出 | 2026-08-19 |
| D03 | 空文本 / 无可计量内容 | 返回 `raw=None` + `reason`，由上层标记为无效样本；**不返回 0.0** | 返回 0.0 会被下游读成「纯英文，严重不达标」——误差方向危险。PRD §8.1 已明确未激活维度不计入分母 | 2026-08-19 |
| D04 | 统一字数口径 | 汉字按字符计，连续英文串按 1 词计，连续数字串按 1 计，标点与空白不计 | 与 D01 同源；「平均段落字数」「单段最长引用字数」共用同一函数，避免两个指标各算各的 | 2026-08-19 |
| D15 | 中文占比是否排除术语英文括注 | 排除（`exclude_annotated_terms=True`，默认开），`details` 保留未排除口径 | `term_policy=translate_with_source` 时用户**要求**模型写「梯度下降（gradient descent）」，若把括注英文计入分母，满足术语维度就必然拉低语言一致性维度——两个维度直接打架 | 2026-08-19 |
| D16 | 引用长度达标线 | 单段 ≤ 100 字（可配） | 直接来自 PRD §12.1 的版权约束，非风格偏好 | 2026-08-19 |
| D17 | 是否输出混合总分 | 不输出。只按维度分别报告 + 一个 `all_activated_passed` 布尔量 | PRD §8.1 设计要点：混合分会掩盖结构性问题（「长度控制良好但从不给类比」仍能得 88%） | 2026-08-19 |

### 二、配置口径（`config.py`）

| 编号 | 口径 | 决策 | 理由 | 决策日期 |
| --- | --- | --- | --- | --- |
| D19 | 配置里的未知字段 | 严格报错，不静默忽略 | 静默忽略意味着把 `tolerance` 拼成 `tolerence` 也能跑，实验跑完才发现用的是默认值。§8.2 的曲线经不起这种错 | 2026-08-19 |
| D20 | 语言标签 | 归一到主子标签：`zh-CN` `zh_Hans` `ZH` → `zh` | 激活判定只关心「讲解语言是否等于课件语言」，地区差异在这个判断上没有意义。不归一会让 `zh-CN` ≠ `zh` 这种伪不等把跨语言维度错误地激活 | 2026-08-19 |
| D21 | 达标区间的边界 | 闭区间，且浮点比较加 `1e-9` 补偿 | 达标线是「不低于」不是「严格高于」；`abs(0.9-0.85)==0.050000000000000044 > 0.05`，不补偿的话恰好落在边界的样本被判不达标，在 20 轮曲线上表现为一个无法解释的失败点 | 2026-08-19 |
| D22 | 维度激活判定的归属 | 集中在 `config.py`，维度模块不各判各的 | PRD §8.1 的激活机制直接决定遵循度的分母；分散判定必然出现两个维度对「是否单语」的理解不一致 | 2026-08-19 |
| D23 | 配置指纹 | `to_dict()` 的规范 JSON 取 sha256 前 12 位 | §8.2 要求 20 轮固定同一份配置。每轮日志带指纹，事后 `len(set(...))==1` 即可验证，不必依赖「我记得没改过」 | 2026-08-19 |

### 三、术语表收录口径

判据全文见 [`examples/glossary_criteria.md`](examples/glossary_criteria.md)，此处只记结论性决策。

| 编号 | 口径 | 决策 | 理由 | 决策日期 |
| --- | --- | --- | --- | --- |
| D18 | 单位、化学式、专有名词 | 不进术语表 | `term_policy` 的三个取值对它们都不适用——单位与化学式默认保留原文，不存在「译文+原文括注」与「仅用译文」的选择空间。强行纳入会让分母膨胀且分子恒等于分母，虚高整个指标 | 2026-08-19 |
| D24 | 有日常义的术语 | 取复合形式收录，单形进 `unsafe_aliases` 不参与匹配 | `enrichment` 单独匹配会误伤「丰富/充实」，`uranium enrichment` 不会 | 2026-08-19 |
| D25 | 课件写法 vs 标准写法 | 必须收标准写法为主形，课件写法进 `aliases` | 术语表匹配的对象是**模型输出**而非课件。22.081J 写非标准的 `solar voltaic`，模型几乎必然输出 `photovoltaic`——只收课件写法会导致该条永不命中，指标静默失效 | 2026-08-19 |
| D26 | 边界模糊的术语 | 默认不收，登记备查，走用户手动增删入口 | PRD §8.1「宁漏勿错」：漏收只降低灵敏度，误收造成误判 | 2026-08-19 |

### 四、预处理口径（`text.py`）

| 编号 | 口径 | 决策 | 理由 | 决策日期 |
| --- | --- | --- | --- | --- |
| D05 | 归一化的位置 | Unicode 归一化（NFKC、全角半角、中文标点变体）**统一在 `text.py` 完成**，维度模块不得重复实现 | 四个维度共用同一份地基；分散实现必然出现某个维度漏了某类变体，造成指标间不一致且极难排查 | 2026-08-19 |
| D05a | 归一化顺序 | 换行统一 → 零宽字符剔除 → NFKC → 中文标点表 | 顺序不可换：NFKC 不处理 `\r`；零宽字符若留到 NFKC 之后仍会打断术语字符串匹配 | 2026-08-19 |
| D05b | NFKC 的已知副作用 | 接受：全角 `（）→()`、`，→,`、`！→!`、`Ａ→A`、`１→1`、`…→...` | 这些字符全部是标点或不参与计数的形式差异；换来的收益是术语括注匹配只需处理半角括号一种形态。`。「」『』` 无兼容分解，NFKC 不动，引用检测依赖它们 | 2026-08-19 |
| D08 | 汉字的范围 | CJK 主区 + 扩展 A + 兼容表意文字 + 星平面扩展区；**排除**日文假名与韩文谚文 | 假名谚文同属 CJK 却不是中文，计入会虚高「中文字符占比」——这是个会静默发生的误判 | 2026-08-19 |
| D06 | 哪些内容不参与任何统计 | 围栏代码块、缩进代码块、行内代码、数学公式（`$…$` / `$$…$$`）、URL 与 markdown 链接目标 | 一段 Python 示例能把中文占比直接打到 60% 以下，造成系统性误判；URL 里的英文同理。markdown 链接的**显示文字保留**，只掩 URL——显示文字是给用户看的正文 | 2026-08-19 |
| D07 | 排除的实现方式 | 掩码：替换为 `\x00` 且**保持长度与换行位置不变**，而非删除 | 掩码串与归一化串逐字符对齐，维度模块可以直接在掩码串上跑正则，再用同一组偏移量回原文取证（§12.1 的引用超限需要留证据，光有数字不够） | 2026-08-19 |
| D09 | 段落的定义 | 空行分割；**连续列表项合并为一个段落**；标题、表格、代码块不计入段落统计 | 逐条 bullet 计段会把段落均值人为拉低；标题是结构不是散文，表格是数据不是散文 | 2026-08-19 |
| D10 | 未闭合的代码围栏 | 延伸到文末，整体按代码处理 | 流式输出被截断时的常见形态。若不当作代码，半截代码会被计进中文占比 | 2026-08-19 |
| D11 | 缩进代码块的识别 | 仅当前一行为空行（或位于文首）时才识别 4 空格缩进为代码 | 段落续行常被缩进；误判为代码会把正文从所有统计里整段抹掉 | 2026-08-19 |
| D12 | 引用块是否计入正文 | 计入「中文占比」与「术语标注率」，不计入「平均段落字数」 | 引用是讲解的一部分，语言与术语约束对它同样成立；但它的长度由被引原文决定，混进段落均值会污染「详细程度」维度 | 2026-08-19 |
| D13 | 取证片段（`preview`）的来源 | 切掩码串，而非归一化串 | 取证要展示的是「被计入统计的那部分内容」；代码、公式、URL 既然没参与计数，就不该出现在证据里 | 2026-08-19 |
| D14 | 英文句号是否算句末 | 仅当后接空白或文末、且前一字符不是数字时算 | 否则 `0.01`、`3.14` 会被切碎。（`split_sentences` 当前四个维度未使用，为 PRD §8.1「冗余句式」维度与 §9.2 方案 C 的句子级并行审查预留） | 2026-08-19 |

## 设计约束

**零第三方依赖**（仅 `pytest` 为开发依赖）。
理由：PRD §9.2 倾向方案 C——A 类检查要在流式输出过程中按句并行执行，必须是毫秒级、
可直接嵌入服务端的纯函数。引入 `pydantic` / 分词库会同时抬高延迟与部署成本，
而 D01/D04 的字数口径本身就绕开了对分词的依赖。

**函数无状态**。四个维度函数签名一致、可独立调用、接受任意文本片段，
天然支持流式分句增量调用。

## 用法

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest        # 全部测试
```

```python
from a_rules.text import Document

doc = Document.parse(explanation_text)
doc.count()               # CharCount(han=…, latin_words=…, digit_groups=…)
doc.is_blank              # 无可计量内容 → 上层标记为无效样本（D03）
doc.paragraph_blocks()    # 供「平均段落字数」
doc.countable_masked()    # 供「中文占比」「术语标注率」
```

CLI（`python -m a_rules --text f.md --config c.json --glossary g.json`）随
`evaluator.py` 一并交付，用于 §8.2 的批量实验。
