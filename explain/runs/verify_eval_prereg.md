# 出处核对 agent · 注入错误评测 · 预登记（2026-10-10）

**本文件在跑任何一次核对之前写下并提交。** 结果出来后不改本文件；任何偏离写在结果文件的「偏离预登记」一节。

## 要回答的问题

1. 讲解里被人为改错的说法，核对员能抓出多少（**检出率**，按错误类型分开报）？
2. 没改过的讲解，核对员会误报多少（**误报率**）？
3. Haiku 与 Sonnet 哪个更合适：检出、误报、单轮成本放在一起比。
4. 每轮多花多少：核对成本占单轮讲解成本的百分比。

- **基础讲解**：

  - 合计 30 段。生成后**不挑**：除非讲解里一个页码都没标（那样「标错页」无从注入），全部进集。
- **未改样例**：30 段原样。

## 三类注入（确定性规则，代码在 `explain/scripts/verify_eval.py`）

每段讲解对每一类至多注入一处，只改一处，其余不动：

| 类型 | 规则 |
| --- | --- |
| `number` 改数字 | 讲解里第一个不在「第 N 页」里的数字（含负号）：`0→1`、`1→3`、`-1→-2`、`2→3`，其余 `+1`；「两倍」→「三倍」 |
| `concept` 换概念 | 按固定的替换表，替换讲解里第一个命中的术语：垂直↔平行、最大↔最小、实数↔复数、对称矩阵→反对称矩阵、行列式↔迹、拉伸↔旋转、协方差矩阵→相关矩阵 |
| `page` 标错页 | 讲解里第一个「第 N 页」改成另一页：`N → N+3`，超出 10 就 `N−3`（离得远，内容不同） |

**人工检查（在跑核对之前做）**：逐条读注入后的那一句，**改了之后仍然为真**（例如把「最大」换成「最小」恰好也对）的剔除，
剔除清单与理由写进 `verify_eval_items.json`。剔除后每类不足 15 条，就加生成讲解补足，不降标准。

## 判据（预先定死）

- **命中**：那一处改动所在的说法被核对员提取为 `fact`，且判定不是 `supported`（`wrong_page` 或 `not_found` 都算抓到）。
  匹配方式：说法与改动所在的句子互为子串（归一化后），且包含改动后的那个词；`page` 类按 `cited_page == 改后的页码` 匹配。
- **漏检**：那一处被判 `supported`、被归为 `supplement`、或根本没被提取（三种分开计数）。
- **核对失败**（`status = failed`）：算漏检，单列。
- **误报**（只在未改样例上算）：
  - 逐段：至少有一条 `fact` 被判成非 `supported` 的段数 / 30；
  - 逐条：被判成非 `supported` 的 `fact` 条数 / 全部 `fact` 条数。
  - 误报的每一条都人工复核：讲解本身真的有错（基础讲解也可能错）的，**单列为「真问题」**，不算误报，并写出是哪一句。
- **达标线**（决定能不能上线默认开启）：三类检出率**都** ≥ 70%，且逐条误报率 ≤ 10%。
  不达标照样报数，照样可以上线，但界面文案要降级（只显示「已核对」，不显示「课件里没找到」）。

## 模型

- Haiku 4.5：全部 30 + 3×n 条。
- Sonnet 5：同一批；若预算不够（核对总花费上限 $3），只跑同一批里按段号取的前一半，并在结果里写明。

## 成本口径

- 核对单次成本 = 核对 agent 各步之和（按 `llm.PRICING`）。
- 「单轮成本增加百分之几」= 核对均值 / 讲解单轮均值。讲解单轮均值取两个数分别报：
  固定流水线 $0.0151（180 轮实测）与 agent 链路课件题 $0.027（2026-10-08 真模型验收，n = 5）。
