## 任务 A · 合成课件片段

产出 `f1_samples/synthetic_deck.md`。

### 硬约束

- **英文**。`source_language='en'` / `explain_language='zh'`，否则 `chinese_ratio` 维度不激活，
  核对脚本里那一维会是空转的（通则七 #5，这是你自己在阶段 1 抓到的形态）
- **不得与 22.081J（能源/核工程）或 14.129（博弈论/机制设计）撞主题**——
  否则 F1 样例与 F2/F3 测试集是同一份材料，以后讲解质量出问题分不清是样例设计还是课件特性
- 400–600 词
- 文件头注明「自写合成内容，非第三方课件，用于 F1 样例」

### 内容要求：必须同时支撑四条轴

| 轴 | 课件里要有 |
| --- | --- |
| 详细程度 | 内容够厚，短讲和长讲都成立 |
| 深度（what / why / derivation） | 一个有**机制**的概念，不能只是定义 |
| 结构（先结论 / 先铺垫） | 有一个可以先说也可以后说的结论 |
| 举例（more / fewer） | 有可举例、可类比的地方 |

主题你挑。在文件头写清**为什么这个主题满足上面四条**——这段以后要用来判断换素材时新素材够不够格。

## 任务 B · 8 对 16 个样例

产出 `f1_samples/pairs.json`。

### 口径 F18（新增，本阶段最重要的一条）

> **样例必须由模型在对应 `StyleConfig` 下真实生成，不得手写、不得人工润色。**
>
> 手写会得到「理想中的 P3」，而用户真正拿到的是「模型在 P3 下实际产出的」。
> 两者不同，用户按样例选完拿到的东西就不是他选的那个——**F1 的整个前提垮掉**。
> 已有实测支持这条：E10 显示 P3 达标 72% 来自分段，手写样例不会有这个问题，
> 而真实输出会有。**用真实生成的样例，用户至少选到的是他真的会得到的东西。**

生成不过核对（任务 C）时**重新生成，不修改样例文本、不放宽判据**（F01 的使用纪律）。
16 个样例的生成成本一次性，不构成理由。

### 八对

| # | 目标轴 | 对 |
| --- | --- | --- |
| 1 | 详细程度 | P0 vs P3 |
| 2 | 详细程度 | P0 vs P1 |
| 3 | 详细程度 | P2 vs P3 |
| 4 | 举例 | more vs fewer |
| 5 | 结构 | conclusion_first vs buildup_first |
| 6 | 深度 | what vs derivation |
| 7 | 深度 | what vs why |
| 8 | 深度 | why vs derivation |

**F01**：每对只在目标维度上不同，非目标维度一律取默认值
（`P0` / `more` / `conclusion_first` / `why`）。

### 生成方式

- 输入 = 合成课件**全文**，不走检索。理由：样例要展示的是风格差异不是检索质量，
  400–600 词一次塞得下。**代价登记**：样例不经过检索，不代表带检索时的真实行为
- A 类维度的 prompt 片段：调 `explain/style_prompt.py` 的 `render`（只读调用，不改它）
- B 类维度的 prompt 片段：本阶段在 `f1_samples/` 下自己拼，写清每条的措辞

### pairs.json 必须记的元数据

否则以后重新生成会得到不同的东西而没人知道为什么：

模型标识与版本 · 生成时间 · 每个样例的完整 `StyleConfig` · 完整 prompt（或其 hash + 模板）·
`a_rules.config.CONFIG_VERSION` · temperature 等采样参数 · 实际花费。

## 任务 C · 三维核对脚本

产出 `f1_samples/verify_pairs.py`。调用**现有的** `a_rules`。

### 三条断言

| 维度 | 判据 |
| --- | --- |
| `paragraph_length` | **隶属集合判据**（下） |
| `chinese_ratio` | 全部 16 个样例 ≥ **0.85**（生产默认阈值，不引入新数字） |
| `quote_length` | 全部 16 个样例 ≤ **100 字**（§12.1 合规线） |

### 隶属集合判据

对每个样例，计算其平均段落字数落进 `AXIS_POINTS` 四个区间中的哪些，得到一个隶属集合。

- **非详细程度的 5 对**（#4–#8）：两个样例的隶属集合**必须完全相同**
  ——含义是「在 F1 自己的档位轴上不可分辨」，零自由参数
- **详细程度的 3 对**（#1–#3）：两个样例的隶属集合**必须不同**

> ⚠️ 第二条要特别当心第 2 对：**P1（40–90）完全被 P0（30–120）包含**。
> 若 P0 样例恰好落在 40–90，两者隶属集合相同，判据会红。**这是判据在正确工作**，
> 重新生成，不要改判据。

### 反向验证

- 造一对在两个 A 类维度上都不同的样例 → 非目标维度那条必须红
- 造一对详细程度上无差异的样例 → 目标维度那条必须红
- 断言 `samplesChecked == 16`——**扫了 0 个样例也会得到 0 条失败**（F16 那一类）

### 观察项：打印，不判定

按 F1方案 §3.4 选项 B，对每个样例打印 `total_chars` 与 `paragraph_count`，
详细程度那 3 对额外打印两个样例的实际平均字数与差值。

**这是 P3 分段问题在真实用户之前的第一手证据。** 不作判定，不据此调整档位。
若差值小到你认为用户分辨不出（尤其第 2 对 P0 vs P1），**如实登记为发现**，不自行处理。
