## 0. ⚠️ 阻塞项：11.201 的 15 页是旋转页，切片文本顺序全乱

**这条必须在建任何索引之前修掉**，否则 2b 测出来的数字有一门课是废的。

### 0.1 现象

`MIT11_201F07_slides2.pdf` 全部 15 页 `/Rotate = 90`，文字方向 `(0, -1)`。
`parse-service` 用 `page.get_text("dict", sort=True)` 取块，而该排序在**未旋转的
坐标空间**里按 y→x 进行，对旋转页给出的是错误的阅读顺序。

实测 p2（拼接后的 `slice.text` 开头）：

```
again.
cycle" interpretation of same, place
historical developments in global
perspective.
case) with preview of traditions.
Today's learning objectives          ← 标题排在第 6 块
1. Synthesize lessons of the RLA case: ...
```

正确顺序（按显示坐标重排后）：

```
Today's learning objectives          ← 标题回到第 1 块
1. Synthesize lessons of the RLA case: Move from theory to practice and
again.
2. Understand major chapters of modern planning history and risks of the "life-
cycle" interpretation of same, place
historical developments in global
perspective.
...
```

`title_block_id` 落在第 4 块及以后的比例：**11.201 有 13/15 页**，
而 22.081J 是 3/39、14.129 是 0/46。异常集中在这一门。

### 0.2 不只是顺序，bbox 也是错的

| 量 | 值 |
| --- | --- |
| `page.rect`（显示尺寸） | 718 × 538 |
| `page.mediabox`（未旋转） | 612 × 792 |
| `get_text("dict")` 的坐标空间 | **538 × 718** |

`pdf.py` 拿 `page.rect`（718×538）去裁剪 dict 空间（538×718）里的 bbox，
于是 **11.201 每个块的 `y1` 都被裁到 538**，`bbox_norm` 也是按错误的轴算的。
实测该文件所有块的 `bbox_pt[3]` 恒为 538.0，就是这个裁剪造成的。

### 0.3 影响面

| 受影响 | 是否受影响 | 说明 |
| --- | --- | --- |
| `slice.text` 顺序 | **是** | 直接影响 embedding 质量——这是 2b 的核心测量对象 |
| `bbox_pt` / `bbox_norm` | **是** | 11.201 全部块 |
| `image_adjacency` | 否（侥幸） | 11.201 有 0 张图，无邻接可算 |
| `size_rank` | 否 | 基于字号，与坐标无关 |
| 扫描件判据 / `kind` / golden file | 否 | 判据用不着墨占比与图覆盖，均不依赖块顺序 |
| 22.081J / 14.129 / 15.316 | 否 | `rotation` 全为 0 |

**为什么这条阻塞 2b**：11.201 承担评测集 8 个 gold 页引用，且**全部文科
`synonym` 题（Q020–Q025）都在它上面**。用乱序文本建索引，测出来的
「-small vs -large 在文科题上的差异」会混进排序噪声，无法归因。
而索引一旦建好再修，两个模型的所有变体都要重建。

### 0.4 修法（已验证）

对每页取 `page.rotation_matrix`，把 dict 的 bbox 变换到显示坐标空间，
再按显示坐标 (y, x) 重排块，页面矩形仍用 `page.rect`。
实测在 11.201 p2 上：标题回到第 1 块、阅读顺序正确、bbox 变回横向
（最大 678 × 512，落在 718 × 538 内，不再溢出被裁）。

改动范围限于 `parse_service/pdf.py`，需递增 `SCHEMA_VERSION` 或至少在
README 口径表记一条（块顺序口径变更）。`kind` 的 golden file 不受影响。

## 1. 型号与维度：用评测集实测，方案里不给推荐

按要求不凭参数表推荐。本节给的是**实验矩阵与判定规则**，结论等跑完再写。

### 1.1 候选

| 编号 | 模型 | 维度 | 备注 |
| --- | --- | --- | --- |
| M1 | `text-embedding-3-small` | 1536（默认） | |
| M2 | `text-embedding-3-large` | 3072（默认） | ⚠️ 超过 pgvector 近似索引 2000 维上限，见 §1.3 |
| M3 | `text-embedding-3-large` | 1024（降维） | 该系列支持 `dimensions` 截断 |
| M4 | `text-embedding-3-small` | 512（降维） | 测降维的召回损失 |

### 1.2 判定规则（先写死，避免看到数字再挑标准）

按 §2 的三个指标分 tag 报告，**不合并总分**。选型规则按序：

1. 若某模型在 `synonym` 与 `multipage` 两组上的 `full-hit@5` 均不低于对手，选它。
2. 若互有胜负，看 `page-recall@5` 的 tag 分组表，**以 `synonym` 为准**——
   它是选 embedding 的核心理由（评测集 README §3）。
3. 若差异落在噪声内（见下），**选 M1**（`-small` @ 1536，默认维度）。
   理由：**未降维、未放弃 ANN、假设最少的默认值**。
   刻意**不用「存储与索引更省」作理由**——§1.4 已判定成本不是决策依据，
   存储同理（100 条 × 4KB ≈ 400KB）。**用一个已经判定为不相关的量去打破平局，
   是在给随意选择套一个看起来有依据的理由**，比直说「平局时取默认」更糟。

**噪声判定**：n 只有 25 条有 gold 的题，单组最少 2 条。
差异小于 **1 题**（即 `full-hit@5` 差 < 1/组样本数）一律视为不可分辨，
不作为选型依据。这条现在写下，是为了防止事后把 18 题里差 1 题读成「更好」。

### 1.3 pgvector 的维度上限（工程约束，非选型依据）

pgvector 的 `hnsw` / `ivfflat` 索引最大支持 **2000 维**，`vector` 列本身可到 16000。
故 M2（3072 维）**无法建近似索引**，只能精确扫描。

对 v1 不构成问题：PRD §7.5 已判定「课件规模可控（单门课数十页）」，
本语料单门课 15–46 个切片，精确扫描的代价可忽略。
但若 M2 胜出，**须在 README 记明「该选择放弃了 ANN 索引能力」**，
将来单用户课件量上去要重新评估。

### 1.4 成本（确认不是决策依据）

| 项 | token |
| --- | --- |
| 全语料切片文本 | 约 8,900（估算，实跑以 API 返回的 usage 为准） |
| 30 条问题 | 约 900 |
| 全矩阵（4 型号 × 4 文本变体） | 约 **14 万** |

`-small` $0.02/1M、`-large` $0.13/1M → 全矩阵**合计 < $0.02**。确认可忽略。

## 2. 召回指标

### 2.1 有 gold 的 25 题：三个指标并列，不合并

| 指标 | 定义 | 回答什么问题 |
| --- | --- | --- |
| **full-hit@k** | top-k 覆盖了**全部** gold 页 → 1，否则 0 | 「这题能不能答全」 |
| **page-recall@k** | \|命中 ∩ gold\| / \|gold\|，逐题算再平均 | 「答到几成」 |
| **first-hit-rank** | 第一个 gold 页出现的名次（未命中记为 ∞，单独报未命中数） | 「排序好不好」 |

**必须三个都报**，理由就是你指出的那条：9 条 `multipage` 题上，
「2 页中命中 1 页」和「全中」在 `page-recall` 上是 0.5 与 1.0，
在 `full-hit` 上是 0 与 1——**只看任何一个都会漏掉另一半信息**。
这与 a_rules 的 D17（不输出混合总分）是同一条纪律。

k 取 **1 / 3 / 5 / 10**。

⚠️ **小语料警告**：全库仅 100 个切片，k=10 就是 10% 的库。
这里的 recall 数字**不可与任何公开 benchmark 比较**，也不可写进 PRD §3.2 的
溯源率指标（评测集 README §2.2 已写明不能作绝对召回率依据）。它只用于本矩阵内的横向比较。

### 2.2 `unreadable_page` 的上限恒为 0，必须标注

Q029 / Q030 的 gold 页是 `image_only`，**根本不产生切片**，
不在索引里，`page-recall` **在结构上恒为 0**。

报告里要显式标成 `上限 0（gold 页不产生切片）`。
否则这两条会被误读成「模型不行」，进而有人去换模型试图提升它——
**它测的不是检索质量，是「兜底文案必须存在」这件事**。

`figure_heavy`（3 条）不同：gold 页有切片，只是切片里只有标题。
**那是真正的测量**，可能中也可能不中，结果有信息量。

### 2.3 `no_answer` 的 5 题：先测可分性，不拟合阈值

判据候选：`max_similarity < τ` 判为「课件里没有」。

**τ 现在标占位待定，且本次不定值。** 理由不是没时间，是 **n=5 拟合不出阈值**——
在 5 个点上选出来的 τ 必然过拟合，还会显得有依据。

**确定路径**：本次只做一件事——把两组的 top-1 相似度**分布画出来**：

- 25 条有 gold 的题的 top-1 相似度
- 5 条 `no_answer` 的 top-1 相似度

然后报告**两组之间有没有间隔**：

| 结果 | 结论 |
| --- | --- |
| 有明显间隔 | 记录间隔区间，τ 待更多样本后在区间内取值；**本次仍不定值** |
| 无间隔（重叠） | **这本身就是结论**：纯向量相似度无法支撑 PRD §10 的「课件里没提到」兜底，需要引入别的信号（如检索后让模型判断）。这个负面结果比一个拟合出来的 τ 有用得多 |

## 3. 送去 embedding 的文本：与 `slice.text` **解耦**

### 3.1 提议：不改 `slice.text`，另设 `embedding_text`

你的问法预设了「改 embedding 输入 = 改 `slice.text` = 递增 `SLICE_RULESET_VERSION`」。
**建议把两者拆开**：

| | `slice.text` | `embedding_text` |
| --- | --- | --- |
| 给谁用 | 人看、溯源、引用比对（S08） | 只给向量模型 |
| 谁产出 | slicer | index 层从 `SliceSet` 派生 |
| 版本号 | `SLICE_RULESET_VERSION` | **新增 `EMBED_TEXT_RULESET_VERSION`** |
| 改动代价 | 切片契约变更 | 只重建索引 |

理由：本节要跑 4 个文本变体，每个变体都递增 `SLICE_RULESET_VERSION` 并重切一遍，
是没必要的耦合；且 `slice.text` 承担溯源与 §12.1 的引用比对职责，
**不该为了向量效果被改写**。代价是「检索到的切片文本」与「被嵌入的文本」不完全相同，
这在 RAG 里是常态，但要在 README 写明。

### 3.2 两类改动要分开：缺陷直接修，口径才做 A/B

| 类别 | 项 | 处理 |
| --- | --- | --- |
| **缺陷** | 旋转页顺序（§0） | **直接修**，不做 A/B。乱序不是一种「口径」 |
| **缺陷** | 私用区字符 | **直接修**。14.129 有 **103 个 U+F076**（Wingdings 项目符号字形），在文本里是纯噪声。只在 `embedding_text` 里剥除，`slice.text` 保持忠实 |
| 口径 | 重复页眉页脚 | A/B，见 §3.3 |
| 口径 | title 前置 | A/B |
| 口径 | 文档级上下文前缀 | A/B |

### 3.3 文本变体矩阵

| 编号 | 组成 | 依据 |
| --- | --- | --- |
| **T0** | 当前口径：块按 order 用 `\n` 拼接（已修旋转 + 剥私用区字符） | 基线 |
| **T1** | T0 − 重复样板块 | 实测样板占全语料字符 **4.4%**，但**分布极不均**：11.201 达 12.5%、22.081J 7.1%、14.129 仅 0.4%。**在过短切片上更严重**——22.081J p38 的 60 字符里 18 个是样板（**30%**）、p33 是 20%。过短切片正是 S04 关心的那批 |
| **T2** | T1 + title 单独前置并重复一次 | 22.081J 的 title 在第 2 块的有 35/39（第 1 块是章节面包屑如 `Technologies / Other`）；14.129 的 title 100% 在第 1 块。前置的收益可能因文档而异 |
| **T3** | T2 + 文档级前缀（课程号 + 讲次标题） | 跨文档检索时提供领域信号。风险：所有切片共享同一前缀，可能压低区分度 |

该 50% 阈值标 **占位待定**，确定路径：T0/T1 的对比结果——若 T1 明显更好，
再按阈值敏感性扫一遍（30%/50%/70%）确定。

## 4. 邻接扩展

### 4.1 三种模式

| 模式 | 行为 |
| --- | --- |
| `none` | 只取 top-k |
| `always` | 每个命中切片各取 `prev` / `next` 各一片 |
| `short_only` | **仅当命中切片 `char_count < τ_short` 时**才扩展 |

`short_only` 就是 S04「过短页要不要合并」的替代验证——
它不改切片，只在检索时扩展，因此**不需要重建索引也不需要改切片契约**。

### 4.2 必须在同等预算下比较（否则扩展必然赢）

扩展本身就是「多取几片」，直接比 `recall@5` 对 `none` 不公平。
定义**预算 B = 最终交给下游的切片数**，在同一 B 下比：

| B | `none` | `always` |
| --- | --- | --- |
| 3 | top-3 | top-1 + 邻居 |
| 5 | top-5 | top-2 + 邻居（约 6，按 §4.3 的顺序取前 5） |
| 10 | top-10 | top-4 + 邻居 |

### 4.3 超预算时的取舍顺序（先写死，这个细节会决定结论）

邻居切片**没有相似度分数**，无法与命中片混排，故顺序必须显式规定：

1. **命中片在前**，按相似度降序。
2. **邻居紧随其宿主片**：宿主排名越靠前，其邻居越靠前。
3. **同一宿主内，`prev` 先于 `next`。**
4. 去重：一个切片既是命中片又是别人的邻居时，只保留其命中片位置（更靠前）。

例：top-2 命中 `s010`(0.82)、`s027`(0.79)，顺序为
`s010, s009, s011, s027, s026, s028`，取前 5 得
`s010, s009, s011, s027, s026`。

**这条写进 README 口径表**，改动须递增扩展口径版本——
它决定同预算下哪些片被挤掉，直接影响对照结论。

### 4.4 `τ_short`

`τ_short` 取值 **占位待定**。本次不拍，改为**扫描**
`char_count` 的实测分位（p25=149 / p50=266）附近若干点，报告曲线形状。
确定路径：若曲线平坦，说明 `short_only` 与 `always` 无差别，S04 的问题
「不需要合并」即得到答案；若有峰，峰位即 τ 的候选，但仍需更大样本确认。
